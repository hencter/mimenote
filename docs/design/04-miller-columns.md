# 设计 04：文件树的双栏（Miller columns）模式

- 状态：**已定稿，进入实现**（`task-4`；对应 ADR-0058）
- 日期：2026-10-12
- 前置：ADR-0027（界面偏好）、ADR-0030（显示名口径）、ADR-0035（容器切割树）、
  ADR-0051（文件树工具栏的取舍）、ADR-0054（每格一个文档）、`docs/design/01-keymap-and-config.md`
  （`tree.toggleColumns` = `Mod+Alt+C`）

## 0. 一句话

文件树除了现在的"一棵会展开的树"，多一种**苹果 Finder 的分栏（Miller columns）**看文件的姿势：
左边一列是上一级目录的内容，右边一列是当前目录的内容；点目录往右推进一列，`←/→` 在两列之间走。
**默认仍是单栏**，两种模式共用同一份状态、同一套排序、同一套过滤判据。

## 1. 不变量（先写死，后面每条决定都受它约束）

1. **排序只有一套判据**：`domain/tree.ts` 的 `makeEntryComparator`（由 `vault-store` 建树时使用）。
   分栏视图**不排序**，只按 `TreeNode.children` 的现成顺序取行 —— 树的顺序与分栏的顺序因此
   不可能漂移（"单栏是拼音序、分栏是字典序"这种 bug 在结构上不成立）。
2. **可见性只有一套判据**：文本过滤仍走 `domain/tree.ts` 的 `matchesFilter`；
   标签过滤仍走 `tag-filter-store` 算出的可见路径集合。分栏**不新增**第二套"命中"规则。
3. **虚拟化只有一套实现**：`domain/virtual-list.ts` 的 `computeWindow` + `scrollTopToReveal`，
   行高常量 `ROW_HEIGHT = 30` 与 overscan `10` 与单栏共用。**每一列各自虚拟化**。
4. **"选中项"仍然只有一份**（`vault-store.selected`）：分栏不引入第二份高亮/光标，
   行上的选中样式是它的直接投影（理由见 §2.2 与 §4）。
5. **切换模式不写任何状态**：`treeLayout` 是纯偏好，切过去再切回来，`expanded`/`selected`/`filter`
   一个都不变（`focusedDir` 也照旧留着，下次切回分栏仍是那一层）。

## 2. 列的定义

### 2.1 第一列 = Vault 根的子项

第一列**永远是 Vault 根**（`relPath = ''`）。它不显示"Vault 名"那一行 ——
那一行的信息在左下角的「最近打开的 Vault」与状态栏里已经有了，多一行只会让每一列都少 30px。
（列头只写"根目录"，当前目录的完整路径统一放在整块底部的路径条里，见 §3.5。）

**被否决的替代方案**：第一列放"收藏 / 最近 / 收件箱"之类的虚拟入口（Finder 的侧栏 + 分栏两段式）。
否决理由：那要把"虚拟节点"引入 `TreeNode` 体系（排序、拖拽落点、F2/F6、reveal 全都要知道
它不是一个真实目录），代价远超收益；而且这个 Vault 的文件树本来就没有侧栏语义。

### 2.2 列链 = **焦点目录**的祖先链

分栏只有**一个**额外状态：**焦点目录 `focus`**（末列显示它的内容）。列链是：

```
['', 祖先1, 祖先2, … , focus]        ← 最后一列显示 focus 的内容
```

- **点 / `→` / `Enter` 一个目录**：`focus` = 那个目录（列链变长一列），
  **`selected` 不动** —— 那一行在左边那一列里保持高亮，右边已经是它的内容。
  这就是 Finder 的样子，也是"点一下往下钻"的全部实现；
- **`↑/↓`**：`selected` 在**焦点列内**移动，`focus` 不变；
- **`←`**：`focus` = 父目录，同时 `selected` = 父目录；
- **打开一篇笔记（别处定位过来 / 首次打开 Vault）**：`focus` 为"跟随"状态，
  末列 = 选中项所在的目录，那篇笔记在其中高亮；
- `selected === null` 且没有焦点：只有根一列。

**为什么 `focus` 不能由 `selected` 推导**（这一条是设计里唯一被真机走查推翻过的）：
最初写成 `focus = parentOf(selected)`，不新增任何状态。结果**点一个目录右边不会多出一列**
（`focus` 还是它的父目录，列链没变），并且**键盘完全无法向下钻**。
想让它成立就得让"末列"跟着选中项走，而那正是分栏要解决的问题。所以 `focus` 独立存在，
三件事的语义各自分明（`selected` 管"接下来所有动作作用于谁"，`focus` 管"末列是谁的内容"）。

**被否决的替代方案 1：列里显示整棵子树**（在"日记"这一列里直接铺开 `日记/2025/01.md`，靠缩进区分）。
否决理由：与单栏模式没有形态差异（用户要的就是"不要缩进、一列一层"），而且列内行数会退化到
O(子树规模)，虚拟窗口的收益被削弱。

**被否决的替代方案 2：把列链整个存进 store（`columnsOpen: string[]`）**。
否决理由：徒增一份要与条目表（删目录/改名）对账的状态。只存**一个** `focus` 时，
对账退化成"这个目录还在不在"一句话（见 `domain/columns.ts` 的回退规则），
而派生出来的东西（列链、每列的行、哪一列是焦点）全都是纯函数。

### 2.3 "当前选中目录"如何持久化

`focus` **按 Vault 根分桶**持久化在 localStorage
（`mimenote.tree.focus.v1`，见 `features/vault/tree-focus.ts`）—— 与
`mimenote.vault.expanded.v1` 同一姿态：换一个 Vault 就是另一套"我在看哪儿"。

三条边界：

1. **重启后回到上次的焦点目录**，`selected` 照旧是"每次打开 Vault 都清空"
   （`vault-store.openVault`）—— 所以重启后看到的是"上次那一层的内容，且最后一列没有高亮"，
   而不是"一条看不见原由的高亮"；
2. **记的那个目录已经不在了**（被删/改名/换 Vault）→ 退回"跟随选中项"
   （`focus = null`），`columnsFor` 的 `focusAccepted` 会把这条回退如实告诉界面；
3. **它不影响单栏**：切回单栏时 `expanded` 原样生效，两者互不覆盖。

**被否决**：把 `focus` 塞进 `vault-store`（那是数据层，住的是 `expanded` 这种与数据同源的偏好）
或 `settings-store` 的 `treeLayout`（那管的是"用哪种画法"，不是"看到哪一层"）。
两条都不合适，于是留在视图层自己的键里 —— 也与 Lead 的落地**零耦合**。

### 2.4 列的排序、图标、徽标与单栏**逐字节一致**

行渲染复用同一个组件（`features/vault/TreeRow.tsx`）：同样的 `folder`/`folderOpen`/`file`/`dot`
图标、同样的 `.md` 去扩展名（`displayName`）、同样的附件扩展名徽标、同样的 `title`（相对路径 ·
大小）、同样的选中/打开样式。**分栏不给行加缩进**（列的位置本身就表达了层级），
因此 `padding-left` 是固定值，不像单栏那样按 `depth` 递增。

## 3. 列宽与滚动

| 问题 | 决定 | 理由（与被否决项） |
| --- | --- | --- |
| 列宽 | **默认 240px，右缘可拖**（140–560）；按目录路径、按 Vault 持久化 | 见下 |
| 每列滚动 | **每列独立纵向滚动**，各列有自己的 `scrollTop` | 见下 |
| 总宽溢出 | **横向滚动**（容器 `overflow-x: auto`），列不收缩 | 见下 |

- **可拖列宽**：每列右缘有一条命中区手柄；偏好按**该列显示的目录相对路径**存
  （`mimenote.tree.column-widths.v1`，与焦点目录同一分桶姿态），推进/回退后同一目录再出现
  时宽度还在。默认 240、下限 140、上限 560（与侧栏 `SIDEBAR_MAX` 对齐）；双击手柄或
  `Home` 恢复默认。末列 `flex-grow` 吃掉侧栏余量（偏好宽度作下限），避免两列时右侧大块留白。
  **被否决**：`minmax` 无下限均分（列多时会被压到 80px 以下）；按"第几列"存（换深度后错位）。
- **每列独立滚动**：Finder 就是这样；而且"外层整体滚动"会让右侧列跟着左侧列上下跑，
  一列滚到底就再也看不到别的列的表头意义。**代价**：一列里滚到第 500 行时，切走再切回来
  会回到顶部（列组件在目录变化时重建）；这是刻意的 —— 让"换列"永远从第一行开始读，
  也避免滚动位置错位到另一批内容上。
- **横向滚动而不是自动收缩**：3～6 层深的目录在 288px 宽的侧栏里必然超出；
  自动收缩（`flex-shrink`）会把每一列压成一条，等于功能消失。**被否决**："只显示最后两列"
  （用户点回上一级时要重新找位置，Miller 的价值恰恰是**路径一直可见**）。

**窄面板的兜底**：侧栏宽度最小 180px（`ui-store.SIDEBAR_MIN`），此时一列也可能装不满，
横向滚动条就在下面 —— 能滚、能读，只是要滚。这与"单栏在 180px 下也一样要横向滚"是同一档体验，
不为它做特殊分支。

### 3.5 当前目录的路径条（底部一行）

整块的最底部有一行「当前在哪一层」（`focus === ''` 时写"Vault 根目录"）：
列头在窄列里只能用省略号，而"我在哪一层"是分栏里最需要一眼看到的信息
—— 浏览器的地址栏做的也是这件事。

它放在**横向滚动区之外**（滚动区是列那一层，路径条是整块的第二行），因此
`flex: 0 0 auto` 且不参与列的纵向空间分配：列的可见高度恒定，虚拟窗口不会随它出现/消失而抖。

## 4. 键盘模型

焦点（DOM 焦点）仍在树根容器 `.mn-tree` 上（`tabIndex=0`，与单栏相同），
按键由容器（`FileTree`）统一处理、由视图挂在根元素上。**`↑/↓/←/→/Enter/F2/Delete` 都不冒泡出去**。

| 键 | 分栏下的语义 | 备注 |
| --- | --- | --- |
| `↑` / `↓` | **焦点列内**上/下移动一行 | 到边界即停（与单栏一致，不跨列）；刚推进一列时从第一行/最后一行起步 |
| `→` | 选中的是目录 → **推进一列**（`focus` = 它，`selected` 不动）；是文件 → 无操作 | 与单栏"展开目录"是**同一个动作的两种画法**（单栏的目录展开 = 在这里把它的内容摆到右边） |
| `←` | `focus` = 父目录，同时选中父目录（= 回退一列）；已在根 → 无操作 | 见下 |
| `Enter` | 目录 → 推进一列；Markdown → 打开到标签页；可查看附件 → 查看器 | 文件那一支与单栏 `activateRow` **同一个函数** |
| `F2` | 重命名选中项 | 与单栏同一条命令（`handleSharedKey`，两种画法共用） |
| `Delete` | 删除选中项到回收站 | 同上 |
| `Escape` | 标签过滤生效时回到全量（与单栏同一条路径） | 分栏下**不**兼做"回退一列" |
| 过滤框 / `F6` / `Mod+Shift+E` / `Mod+Alt+E,W` / `Mod+Alt+C` | 不变 | 见下 |

三条必须写清楚的理由：

1. **`Escape` 不做"回退一列"**。`Escape` 在单栏里已经有一个语义（清除标签过滤），
   而"回退一列"与"清除过滤"同时命中一个键时，用户没法预期会发生哪一个。回退有专属的 `←`。
   （Finder 自己也是 `←` 回退、`Esc` 关浮层。）
2. **`←` 同时改 `focus` 与 `selected`**（都指向父目录）：`focus` 决定末列显示谁的内容，
   `selected` 决定"接下来所有动作作用于谁"。只改其中一个会得到两种都别扭的状态
   —— 只改 `focus` 则高亮留在看不见的那一列里，只改 `selected` 则末列还是子目录的内容。
   已在根那一列时无操作：根没有上一级，按住 `←` 不该有任何动静。
3. **现有快捷键一个都不能回归**。分栏视图不注册任何全局快捷键、不改 `commands` 表；
   过滤框仍是同一个 `<input>`（`TreeToolbar` 不随模式变化），`Mod+Shift+E` 聚焦它、
   `Mod+Alt+E/W` 展开折叠（分栏下**展开状态不参与渲染**，但状态照旧被维护、切回单栏时原样生效），
   `F2/F6/Delete` 作用在 `selected` 上，与模式无关。因此**唯一的模式差异是画法**。
   `F2`/`Delete`/`Escape` 在两种画法下走的是**同一个** `handleSharedKey`（分栏只把 `←→↑↓/Enter`
   之外原样交回）—— 两份实现的第一天就会分叉。

**被否决**：`→` 在文件上跨到"下一个目录"（Finder 的"右箭头跳下一列"是另一种约定，
在只有一个可见目录层的实现里语义不明）；`Tab` 在列间切换（`Tab` 必须留给"离开文件树去别的面板"，
这是无障碍与键盘用户的第一条路径）。

## 5. 与既有状态的映射

| 来源 | 分栏怎么用 |
| --- | --- |
| `vault-store.tree` | 列链每一步 `children` 的来源（唯一数据源，不另建索引） |
| `vault-store.selected` | "哪一行高亮"、`↑/↓` 在焦点列内移动的作用对象；**没有**焦点目录时也用它推导末列 |
| **本地 state `focusedDir`**（`FileTree`） | 末列是谁的内容；`null` = 跟随选中项，`''` = 根，其他 = 用户钻进去的那一层。持久化在 `mimenote.tree.focus.v1`（按 Vault 根分桶，见 §2.3） |
| `vault-store.filter` | 复用 `matchesFilter`（经 `deferredFilter` 去抖）过滤每列的行 |
| `vault-store.expanded` | **不参与分栏渲染**（分栏的行集与展开无关）；切回单栏时原样生效 |
| `tag-filter-store`（经 `useTagFilterView`） | 可见路径集合按 `Set` 成员判定，逐列过滤；空态文案与单栏共用同一套推导 |
| `ui-store.treeSort` | 不直接读 —— 排序早已发生在 `vault-store` 建树时（§1 第 1 条） |
| `ui-store.sidebarVisible` / 窄面板 | 无感知（分栏只在自己的宽度里横向滚动） |
| `settings-store.treeLayout` | 模式开关（Lead 落地，默认 `'single'`）；读取口是 `features/vault/tree-layout-pref.ts` |
| `note-store.doc` | 行上的"当前打开的笔记"标记（`.mn-tree-row--open`），与单栏同一个订阅 |
| `REVEAL_ROW_EVENT` | 分栏也监听（容器只订阅一次，由当前视图回答"滚哪儿"）：定位到某一行的**列**，滚动那一列 |

**标签过滤在分栏下的语义**（与单栏的差别必须说清）：单栏的 `flattenTree` 会把祖先目录保留
在行里，所以"命中笔记藏在深层目录里"时仍然看得见路径。分栏的列链本来就是**祖先链**，
所以祖先路径仍然一直可见；差别只在**每一列只列直接子项** —— 一个目录里的深孙子命中时，
单栏是"命中行 + 它的祖先"，分栏是"祖先列里那个目录 + 右边一列里的命中行"。
两者表达的是同一件事，用户看到的路径也一致。这是分栏可以只做逐列 `Set` 判定、
不必把整棵树展平的根据。

**收件箱置顶（留给下一轮，本轮不实现）的接口**：`domain/columns.ts` 的 `rowsFor`/
`columnViewOf` 只读 `TreeNode.children`，**不排序、不重排**。收件箱置顶要的
"某个目录永远排第一"应当落在**建树的那一侧**（`vault-store` 的 `treeComparator`，
那是排序判据的唯一出处），分栏零改动就会跟上。若将来需要在某一列里强制插一行"收件箱"
（虚拟入口，与 §2.1 被否决的方案不同：这只是**一列之内**的排序偏置），
落点也只在 `rowsFor` 一处，列与列之间的顺序不会因此分叉。

## 6. 性能预算（可测）

| 预算 | 数字 | 怎么测 |
| --- | --- | --- |
| 每列的 DOM 行数 | 可视行数 + overscan 10 × 2，一列 ≤ 60 行 | jsdom/浏览器里数 `[data-column-path] .mn-tree-row` |
| 整个分栏视图的 DOM 行数 | 列数 × 上述值（5 层 ≈ 200 行以内），**与 Vault 条目数无关** | 同上 |
| 换一列（点目录 / `→` / `←`） | ≤ 1 帧：不重建树、不重算展开、不重扫 | 换列后 `vault-store.tree` 引用不变（`toBe`），且 `focusedDir` 一次 `setState` |
| 换列的行计算量 | O(可见列数 × 该列行数)，不是 O(条目数) | `columnsFor` 的单测：10 200 条目的树只算出 2 列 / 200 + 50 行 |
| 滚动 | 每列自己的 rAF 合并（与单栏同一条 `handleScroll` 写法） | 目测 60fps + 行数恒定 |

**结构保证**（比数字更重要）：
- 行组件（`TreeRow`）用 `memo` 包，且只订阅自己的布尔状态（`selected === relPath`、
  `expanded.has(relPath)`、`doc?.relPath === relPath`）—— 选中某一项不会重渲染整列；
- 每一列的滚动状态是一个**扁平 map**（`dirPath → {scrollTop, height}`）：
  滚动一列只换那条记录，`TreeColumn` 按 `metrics[column.path]` 拿自己的那份，
  其余列不会因为 `metrics` 换了引用而重渲染内容；
- 列的 `key` 用目录路径，位置变化（列链变长变短）不会让 React 复用错行。

## 7. 单栏 ⇄ 分栏 ⇄ 堆叠的切换点

`settings-store.treeLayout` 三态：`'single' | 'columns' | 'stack'`（默认 `'single'`）。

- **`columns`**：经典 Miller 横排列（本文件主体）。
- **`stack`（堆叠卡片）**：同一套列模型与键盘；列用 `position: sticky` + 递增 `left`
  （露边 ≈ 28px）叠在左侧，焦点列在前。横向滚动把叠在上面的卡片往右摊开，逐渐接近
  横排列。点非焦点列的列头 = 把 `focus` 收到那一层。

1. **命令行**：`tree.toggleColumns`（`Mod+Alt+C`）做**三态循环**
   `single → columns → stack → single`（`docs/design/01-keymap-and-config.md` §3.2）。
2. **界面上**：文件树工具栏「视图整理」里的分栏按钮；`aria-pressed` = 非单栏；
   文案在堆叠态显示「堆叠」。**不放进设置页**（ADR-0027 分工）。

两个入口都走 `features/vault/tree-layout-pref.ts` 的 `toggleTreeLayout()` /
`useTreeLayout()` —— 不新增第二个来源。

## 8. 空态与异常

- **空 Vault**（`tree` 为空）：与单栏共用同一份空态（"这个 Vault 还没有 Markdown 文件" +
  新建按钮），不画任何列。
- **过滤命中为空**：列照常画（列链是稳定的），列里只有一行灰字"没有匹配的项"
  —— 与单栏的"没有匹配的笔记"同一句话术。
- **焦点目录被删掉 / 改名**（外部改动 / 回收站 / 重命名）：`columnsFor` 在
  `ancestorsOf` 走到第一个存在的目录处停下（宁可少一列，也不画空列）；整条链都不合法时
  退回"跟随选中项"（选中项的父目录），并置
  `focusAccepted = false`，由容器把回退值写回持久化。这也是"只存一个 `focus`"最值钱的地方
  —— 没有"列栈里躺着一个不存在的目录"这种态。
- **选中项指向一个不存在的目录**（手工改过的 localStorage / 刚重扫）：同上，退回根那一列。
- **焦点目录存在但为空**：照常画出一列空列（写"（没有匹配的项）"），位置保持不变 ——
  整列消失会让右边的列整体左移，用户按 `←` 时看到的位置与刚才不是同一个。
