# ADR-0058：文件树的分栏（Miller columns）模式

- 状态：已采纳（已交付）
- 日期：2026-10-12（用户需求："像 Finder 那样一列一列地看文件"，可切换回单栏）
- 相关：ADR-0027（界面偏好）、ADR-0030（显示名口径）、ADR-0035（容器切割树）、
  ADR-0051（文件树工具栏的取舍）、ADR-0054（每格一个文档）、`docs/design/04-miller-columns.md`、
  `docs/design/01-keymap-and-config.md`（`tree.toggleColumns` = `Mod+Alt+C`）

## 背景

文件树一直是"一棵会展开的树"：缩进表达层级，`→` 展开目录，`←` 折叠或回到父目录。
它在"我知道那篇笔记叫什么"时很快，在两件事上慢：

1. **路径不可见**：三层深的一篇笔记打开后，左边的树只显示它所在的展开链，兄弟目录与
   上一层还有什么是看不出来的（要么滚、要么折叠再找）；
2. **横向空间被浪费**：侧栏是竖长的，而"一层一层往下看"这个动作天然是横向的。

Finder 的分栏（Miller columns）就是为这两件事设计的：每一层目录占一列，路径永远可见，
点目录只往右推进一列。本 ADR 记的是"把这套画法加进来、并且不破坏既有的一切"这件事的取舍。

## 决策

### 1. 列链 = **焦点目录**的祖先链；焦点目录是分栏唯一的新状态

设焦点目录为 `focus`，列链就是 `['', …祖先, focus]`，末列显示 `focus` 的内容；
`focus` 由容器持有（`FileTree` 的 `focusedDir`）、按 Vault 根分桶持久化
（`mimenote.tree.focus.v1`，见 `features/vault/tree-focus.ts`）。
判据在 `domain/columns.ts`（纯函数：`directoryChainFor` / `columnsFor` / `drillTarget` /
`siblingRowTarget` / `arrowLeftTarget`）。

三个动作的语义因此分明（**`selected` 与 `focus` 是两件事**）：

| 动作 | `focus` | `selected` |
| --- | --- | --- |
| 点 / `→` / `Enter` 一个目录 | 推进到那个目录 | 不动（那一行保持高亮） |
| `↑` / `↓` | 不变 | 在**焦点列内**移动 |
| `←` | 回退到父目录 | 设成父目录 |

⚠️ **这一条是被真机走查推翻重做过的**，写在这里免得后来者又"优化"回去：最初的实现是
`focus = parentOf(selected)`（不新增任何状态），结果**点一个目录右边不会多出一列**
（列链没变），并且**键盘完全无法向下钻**。想让它成立就得让"末列"跟着选中项走，
而那正是分栏要解决的问题。所以 `focus` 是独立状态；`selected` 仍然是**唯一的选中项**
（行上的高亮是它的直接投影，没有第二种"光标"）。

**被否决**：把整条列链存进 store。只存**一个** `focus` 时，对账退化成"这个目录还在不在"
一句话（`columnsFor` 的 `focusAccepted` 会把它回退到选中项所在目录或根，界面据此写回持久化），
列链与每列的行都是纯函数派生出来的。

### 2. 分栏不排序、不判可见性、不自己虚拟化

三个复用（这是本 ADR 里最重要的纪律）：

- **排序**复用 `vault-store` 建树时的 `makeEntryComparator` —— 分栏只按 `TreeNode.children`
  的现成顺序取行。视图层再排一次序，"单栏是拼音序、分栏是字典序"只是时间问题；
- **过滤**复用 `domain/tree.ts` 的 `matchesFilter`（文本）与 `tag-filter-store` 的可见路径
  集合（标签）；
- **虚拟化**复用 `domain/virtual-list.ts` + 同一个行高常量 `ROW_HEIGHT = 30`。

### 3. 列宽固定 240px、每列独立滚动、溢出走横向滚动

见设计文档 §3 的对照表。要点：可拖列宽要为"第几列"引入一份按 Vault 存的偏好，
而收益只是几个像素；自动收缩在 288px 的侧栏里会把每一列压成废条。

### 4. 每列独立虚拟化；行组件与单栏共用

`features/vault/TreeRow.tsx` 从 `FileTree.tsx` 里抽出来，单栏与分栏共用同一段行渲染
（图标、显示名、附件徽标、选中/打开样式、拖拽落点状态），`FileTree.tsx` 变成"容器"：
读偏好、算可见行、按模式分派给 `SingleColumnTree` 或 `ColumnsTree`。
**`FileTree.tsx` 不继续膨胀**：它只负责"两种画法共用的那部分"（过滤推导、标签过滤视图、
右键菜单的数据、对话框挂载）。

### 5. 键盘：`←/→` 跨列、`↑/↓` 列内、`Enter` 打开；`Escape` 不做回退

`→` 在目录上 = 推进一列（`focus` 换成它、`selected` 不动），在文件上 = 无操作；
`Enter` 在目录上同上、在文件上与单栏共用 `activateRow`（打开到标签页 / 可查看附件开查看器）；
`↑/↓` 只在**焦点列内**移动，刚推进一列时从第一行/最后一行起步；
`←` 同时把 `focus` 与 `selected` 设成父目录（已在根时无操作）。

`Escape` **不**兼做"回退一列"：它在单栏里已经是"清除标签过滤"，一键两义时用户无法预期。
Finder 也是 `←` 回退。

`F2` / `Delete` / `Escape` 两种画法走**同一个** `handleSharedKey`（分栏只把
`←→↑↓`/`Enter` 处理掉，其余原样交回）—— 分栏里 F2 静默失效是最容易被当成随机 bug 的一类回归。

### 6. 现有快捷键与动作零回归

分栏视图不注册任何全局快捷键、不改 `commands` 表。过滤框（`Mod+Shift+E`）、展开折叠
（`Mod+Alt+E/W`）、`F2`/`F6`/`Delete`、`REVEAL_ROW_EVENT`、右键菜单、拖拽整理全部照旧；
`expanded` 在分栏下不参与渲染但**照旧被维护**，切回单栏立即生效。
唯一的模式差异是画法。

### 7. 拖拽：落在某一列的空白 = 那一列显示的目录

`domain/drag.ts` 的 `dropTargetFor` 一个字没改：一行仍然是"文件夹 → 那个文件夹 /
笔记 → 它的父目录"，**新增的是列本身也是一个落点**（列 = 它显示的目录）。
这符合"拖到哪儿就是哪儿"的直觉，也顺带解决了"目标目录里暂时没有可见行"时无处可放的问题。
第一列就是 Vault 根的内容，所以"移到根目录"这个落点天然存在 —— 容器因此**不**再代表根目录
（单栏那条规矩不变：整块空白 = Vault 根）。

标签过滤生效时，空白区域照旧**不**接收落点（在收窄视图里"空白代表的目录"恰恰最看不见），
提示语在中栏说明原因 —— 与单栏同一条纪律。

### 8. 持久化"焦点目录"（按 Vault 根分桶），但不碰单栏

`mimenote.tree.focus.v1`：`{ [vaultRoot]: 相对目录路径 }`，重启后回到上次那一层。
`selected` 照旧"每次打开 Vault 清空"，所以重启看到的是"上次那一层的内容、末列没有高亮"，
而不是"一条看不见原由的高亮"。

记的那个目录已经不在了（被删/改名/换 Vault）→ 退回"跟随选中项"
（`focus = null`），`columnsFor` 的 `focusAccepted` 会把这条回退如实告诉界面，界面写回持久化。

**为什么不像单栏那样干脆不持久化**：单栏的"回到哪"由持久化的 `expanded` 与清空的 `selected`
共同决定，而分栏只有一个 `focus`，不记它就等于每次都从头钻。两者互不覆盖
（切回单栏时 `expanded` 原样生效）。

### 9. 模式开关

`settings-store.treeLayout: 'single' | 'columns'`，默认 `'single'`（Lead 落地）。
两个入口：命令 `tree.toggleColumns`（`Mod+Alt+C`）与文件树工具栏第一组里的
`切换分栏视图` 按钮（`aria-pressed` 表达当前态）。两者都走
`features/vault/tree-layout-pref.ts` 的 `useTreeLayout()` / `toggleTreeLayout()`——
不新增第二个偏好来源。设置页**不**放这一项：
它是"我现在想怎么看这一屏"的动线偏好，与"以后一直怎样"的设置分开（ADR-0027 的分工）。

**升级上来的用户看到的树必须和原来一模一样**：默认单栏 + 单栏那条渲染路径一行未改。

## 代价与已知边界

1. **列宽固定 240px**：超长目录名靠省略号 + `title` 悬停，不能拖宽（理由见设计文档 §3）。
   侧栏最小宽度 180px 时一列装不满，要横向滚 —— 不为此做特殊分支；
2. **每列滚动位置在换列后归零**：列组件随目录变化重建是刻意的（换列永远从第一行开始读），
   代价是一列里滚到深处、切走再切回会回到顶部；
3. **分栏下 `expanded` 不参与渲染**：视觉上"没有展开态"是模式的定义，不是缺陷；
4. **过滤时每列只列直接子项**（不像单栏 `flattenTree` 那样把命中的深孙子拉平显示）。
   祖先路径仍然可见（那正是列链），所以"笔记藏在哪一层"始终看得出来；
5. **同一篇笔记仍然不能在两列里对照**（ADR-0035 不变式 1 不变）；
6. **收件箱置顶（下一轮）不在本轮实现**：置顶应当落在建树那一侧（排序判据的唯一出处），
   分栏零改动就会跟上；若要在某一列内插一行虚拟入口，落点只在 `domain/columns.ts`
   的 `rowsFor` 一处 —— 见设计文档 §5 末段；
7. **`role="tree"` 的容器在分栏下同时管着多棵"列"**：没有为分栏另建 ARIA 树结构。
   jsdom 与 E2E 都按 `[data-rel-path]` 找行，这条边界不影响任何判据；
8. **列头是按钮（点它回退一列）**，但**没有实现**点击回退 —— 当前它只是"这一列显示哪个目录"
   的标题（`title` 给完整路径）。回退的唯一入口是 `←` 与（未实现的）点列头；
   留一个能点的按钮而不给它行为是刻意待办，不是漏写；
9. **深路径在 240px 的列头里必然被省略号截断**：完整路径在整块底部的路径条
   （`.mn-tree__columns-path`）与 `title` 里，列头只写末段名字。
