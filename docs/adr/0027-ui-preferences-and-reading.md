# ADR-0027：界面偏好与阅读体验（文件树排序、最近 Vault、阅读主题、任务删除线）

- 状态：已采纳
- 日期：M3 之后（ADR-0026 的同一轮）

## 背景

这一轮剩下的四条诉求，共同点是"**小而独立，但都要求判据只有一份**"：

> 10. 文件树目录的排序规则可以配置
> 11. vault 打开过之后留下固定的索引，便于快速切换，放置于左下角
> 12. 增加一套更适用于阅读的主题色
> 13. 已完成的任务需要删除线样式

## 决策

### 1. 文件树排序可配置（`domain/tree.ts` 一份判据）

`TreeSort = { by: 'name' | 'mtime' | 'size' | 'type', direction, foldersFirst }`，
`makeEntryComparator(sort)` 是唯一判据，`compareEntries` 变成"默认配置"的别名 ——
**默认行为逐字节不变**（升级上来的用户看到的树与从前一模一样）。

三条确定性规则（任何配置下都成立）：

1. `mtimeMs: null`（目录、附件）**恒排最后**，且不随方向翻转 —— 降序时把它翻到最前，
   等于把"没有这个时间"显示成"最新"；
2. 主键相同再按名称（自然序，中文按拼音），仍相同按 `relPath` 兜底 ⇒ 结果与输入顺序无关；
3. 兜底键永远是升序：只有**主键**跟随方向（否则"名称相同的两条"在降序下会颠倒，读起来像不稳定排序）。

重排发生在**数据层**：`vault-store` 用当前偏好建树（`resortTree` 重建而不是就地 `sortTree`，
后者会改动共享对象而 React 察觉不到），由 `ui-store.subscribe` 在 `treeSort` 变化时触发。
订阅方向是"消费数据的 store 订阅偏好"，而不是让最底层的 `ui-store` 反过来依赖业务 store。

### 2. 最近打开的 Vault（左下角）

- 记录在 `localStorage` 的 `mimenote.vault.recent.v1`：最多 8 条、按 `rootPath` 去重、最新在前；
  去重键是**完整根路径**（同名目录 `D:\笔记` 与 `E:\笔记` 是两个 Vault）；
- 组件 `RecentVaults` 挂在**文件树那一块模块的底部**（跟着文件树走：切 Vault 是文件树这个
  上下文的动作，视线本来就在这一栏；它跟着侧栏一起被 `Ctrl+B` 藏掉，不需要第二个落点）；
- 切换走 `openRecentVault`（先 `flushAutosave()` 再 `openVault`），失败时 `openVault` 自己弹 toast；
- 每一条可以 `×` 移除（只影响这张列表，不碰磁盘、不影响"上次打开"的恢复键）；
- `closeVault` **不清**这张列表 —— 它就是为"切走再切回来"准备的。

### 3. 阅读向主题「纸墨」（`themes/mimenote-paper.json`）

暖白纸张风、`appearance: 'light'`，令牌集合与内置浅色主题逐键对齐（`validateTheme` 兜底），
只改色值：底色米白、前景深棕灰、强调色是低饱和的赭石、链接与标题偏暖。

为什么值得内置一条而不只靠 CSS 片段：主题是"看一眼就知道对不对"的东西，
而它的判据（令牌清单）已经在 `theme/tokens.ts` 里 —— 多一个 JSON 文件即可被设置页、
`Ctrl+Alt+T` 循环切换与导出件同时认到，不需要任何代码改动。

### 4. 已完成任务加删除线（改的是**观感**，不是判据）

`- [x] 完成` 的渲染类名（`mn-task-item--done`）早就有了（ADR-0024），这里只改样式：

- 阅读视图与导出件 / 静态站点：`.mn-task-item--done` 加 `text-decoration: line-through`，
  删除线画在 `li` 上只会划到文字 —— 复选框是原生 `<input>`（替换元素，没有文字可被划）；
- 所见即所得编辑器：删除线必须是**只圈文字**的 mark 装饰（`md-task-done-text`），
  挂在行装饰上会连复选框里的 `✓` 一起划掉（`text-decoration` 会传播给所有行内后代且无法豁免）。

**推翻的是 ADR-0024 里的一条观感取舍**（"已完成只变暗、不用删除线，免得与 `~~删除线~~` 撞含义"）：
用户明确要求划线。两者并存时并不冲突 —— 任务项还有复选框这个额外信号，
"我做完了"与"我删掉了这句话"分得开。

## 代价与已知边界

1. 排序按**条目属性**（名称 / mtime / 大小 / 扩展名），不做"按 frontmatter 字段"这类自定义排序；
2. 最近列表不做存活性检查（每个条目一次 IPC 的代价与收益不成比例），失效条目在点击时如实报错；
3. 新主题不改任何代码路径，但它**不**覆盖 callout 的 13 种强调色（那些色由 app.css 的
   `var()` 兜底链给出，ADR-0022 已记录）；
4. 删除线是纯观感，判据（什么算"已完成"）仍然只有 `domain/task-list.ts` 一份。
