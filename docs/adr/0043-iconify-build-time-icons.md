# ADR-0043：图标换 Iconify 构建期打包（推翻 ADR-0042 的自研图标结论）

- 状态：已采纳（已交付）
- 日期：UI 走查轮（v0.2.0 之后）
- 相关：ADR-0033（图标刻度）、ADR-0042（只引行为层；其中"图标继续用自研"一条被本 ADR 推翻）

## 背景

ADR-0042 写下"图标继续用自研"时，理由是"刻度 + 单测纪律已证明够用"。
用户连续三次反馈证明这个判断错了：**够用 ≠ 优雅** —— 35 个手绘路径笔画粗细、
圆角、光学留白全凭手感，与专业画过的同一套字形放在一起一眼可辨。
"为什么那么小"问的是尺寸观感，实质是字形质量。

## 决策

### 1. 字形换 lucide，打包走构建期（`unplugin-icons` + `@iconify-json/lucide`）

- 两个都是 **devDependencies**：图标在 `vite build` 时编进包，运行时零网络 ——
  离线、CSP 都不受影响；**不用 Iconify 运行时 CDN**（那需要出站请求，
  与"默认离线"直接冲突，这也是"Iconify 能不能调用"的答案：运行时不能，构建期能）；
- `IconName` 联合类型与调用点**一个字不改**（名字是稳定的契约，右边映射到 lucide
  具体画法；以后看哪个不顺眼只换映射）；
- 刻度（ADR-0033）、`stroke: currentColor` 跟随主题、`mn-icon` 类名、
  `stroke-width 1.6` 的纤细观感全部保留 —— lucide 默认 2px 偏粗，细笔画才有"气"；
- callout 的字形（`‼` / `✎`）与编辑器行内 `✓` 是**文字**，继续按字号走，不进这套。

### 2. 构建期依赖的代价如实记

- `unplugin-icons` 拉来 `@svgr/core` + `@svgr/plugin-jsx`（JSX 编译用，同样 devOnly）；
  打包增量只有用到的 29 个图标（每个约 1KB）；
- `~icons/*` 需要 `src/icons.d.ts` 的类型引用；vitest 与构建共用同一套 vite 管线，
  测试里直接可用。

## 代价与后续

1. lucide 大版本重命名图标时（如 `columns` → `columns-2`），构建会直接报错
   （找不到模块）而不是静默渲染空图标 —— 这是好事：坏得明显；
2. 若将来需要 lucide 之外的图标（如品牌 logo），按"名字稳定、右边换映射"加，
   不要开第二个图标库。
