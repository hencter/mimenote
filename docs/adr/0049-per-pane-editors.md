# ADR-0049：一格一个编辑器（ADR-0035 的修订）+ 文件树拖入分栏

- 状态：已采纳（已交付）
- 日期：v0.3.0 之后（用户需求："分栏各自保留编辑器"）
- 相关：ADR-0035（容器切割树）、ADR-0037（打开笔记顶掉当前标签）、ADR-0034（标签条）、
  ADR-0032（附件只读查看器）、ADR-0004（唯一写路径）

## 背景

ADR-0035 定下的纪律是"**一格可写、其余可读**"：编辑器全局只有一份，非当前文档在
别的格子里渲染成只读预览（`StaticNotePreview`）。代价是**换一篇笔记时那一格整块换形态** ——
预览组件卸载、编辑器挂载，滚动位置与光标都重置；把当前标签停在哪一格，那一格的
DOM 就变一次。分栏对照阅读时这个抖动尤其明显。

## 决策

### 1. 每个显示笔记的格子各有一个编辑器实例

`MarkdownEditor` 接受可选的 `notePath`：有它时这个实例**只服务这一篇**，
容器的 `data-note-path` 就是它的身份。

- **不变的是纪律**：非当前文档那一格的编辑器是**只读**的（`EditorState.readOnly`
  写在 `Compartment` 里，随"这篇是不是当前文档"重配置）。"一格可写、其余可读"
  一字未改，改的只是"只读"由**预览**变成**只读的编辑器**。
- 非当前文档的正文由 `ipc.noteRead` 单独取（`note-store` 里只有当前那篇）：
  取回来就走 `replaceEditorText` 那条既有路径（与切换笔记同一套整篇替换）。
- 光标记忆（`features/tabs/caret-memory.ts`）与行跳转（`features/editor/line-jump.ts`）
  现在**按路径找编辑器**（`.mn-editor[data-note-path=…]`），找不到才退回旧选择器 ——
  多个编辑器同时在 DOM 里时，"页面里唯一那个 CodeMirror"这个假设不再成立。

### 2. 「把这一格变成当前」由**点正文**触发，不由 focus 触发

这是本轮踩到并修掉的回归：最初写在编辑器的 `onFocusChanged` 上，而**焦点不是可靠信号** ——
搜索面板/浮层关闭会把焦点还给上一篇笔记的编辑器，而那一刻 React 还没把 `notePath`
换成新文档，于是旧路径把自己重新激活，**刚跳过去的笔记 100ms 后被打回原处**
（`line-jump.test.tsx` 的接线用例现在钉着它：命中 → 打开 → 光标落在第 3 行）。

现在由格子内容的 `onPointerDownCapture` 触发：`note !== currentDoc` 时才
`tabs-store.activate(note)`（走既有的完整打开流程：先落盘、再揭示文件树、再换文档）。
`caret-memory` 的恢复也加了一条"这一格已有焦点就别用旧快照覆盖"。

### 3. 文件树里的笔记可以拖进分栏

拖起来时 `layout-drag` 记一个 `fromTree` 旗子：

- 拖到某格的内容区 = **在该格打开新标签**（`openNoteInNewTab`，于是它不顶掉
  那一格正在看的那篇 —— ADR-0037 的"默认顶掉"在跨格拖放里并不适用）；
- 附件（`.txt`/图片等 `isMarkdown === false`）不打开编辑器：直接进该格标签列表，
  由 `FileViewer` 只读渲染（ADR-0032）；
- 落点判定改用**捕获阶段**（`onDragOverCapture` / `onDropCapture`）并对来自文件树的
  拖动 `stopPropagation`：否则编辑器自己的 drop 处理会先把事件吃掉，
  "拖文件树里的笔记进分栏"就永远落不到布局层。拖动源是文件树时，落点落在文件树
  自己身上一律忽略（那是移动文件，不是布局操作）。

### 4. 顺带修掉：独占格子的自我切割判据读错了叶

拖动时的 `soloHere`（"拖到自己独占的格子的边缘 = 无操作"，ADR-0035 定的）原来读的是
**渲染时传进来的 `leaf` prop**，而它可能已经不是当前布局里的那个叶子
（`source` 才是刚从 store 里取出来的那一份）。改成读 `source.items.length`。

## 代价与已知边界

1. **同一篇笔记的编辑器实例数 = 打开它的格子数**：DOM 与 CodeMirror 实例都变多
   （每个实例自己有一套插件与测量）。格子数是手指头量级，这是可接受的；真要做
   大文档的"左右对照编辑"（两边都能写）仍然需要一个多文档模型，本轮**没有**做 ——
   全局仍然只有一份 `note-store.doc`；
2. 非当前文档那一格要打一次 `note_read` 读全文（只读预览那条路径本来也要读盘，
   量级相同）；
3. 非当前文档的编辑器不参与"大纲/标签面板"这些跟随当前文档的面板（它们按
   `note-store.doc` 算）—— 这是"面板只有一个当前文档"的直接后果，不是遗漏；
4. **附件破了一条例外**：ADR-0032 的"附件不进标签页"在**拖入分栏**这条路上不成立 ——
   为了让那一格的标签条真的显示这一项（布局对账以 `tabs-store.tabs` 为"已知项"），
   附件路径会进该格的标签列表。于是 `tabs-store.tabs` **可以**含非 Markdown 路径、
   `active` 也可能暂时指向它（`note-store.doc` 仍然是上一篇笔记）。"查看器不接管主区域"
   这条没有变；但读 `tabs` 的代码不能再假设每一项都是笔记。
