# ADR-0026：视图模块的三个停靠区、标签栏移出主区域、模块的右键菜单

- 状态：已采纳
- 日期：M3 之后（ADR-0025 的下一轮）

## 背景

用户的要求是三条与"界面怎么组织"有关的：

> 7. 每个视图模块要做到在整个编辑器中可以拖拽到任意区域占位
> 8. 标签页移动到顶部
> 9. 任意模块的右键菜单

改之前的外壳是"写死的一行"：左侧固定侧栏（`TreeToolbar` + `FileTree` + `RecentVaults`）、
中间主区域（`TabBar` 是它的第一个子节点）、右侧按顺序摆着链接 / 标签 / 大纲三块面板，
每块的宽度由各自的偏好决定。也就是说：**哪块面板在哪儿，是 App.tsx 里写死的**。

## 决策

### 1. 三个停靠区 + 每区一列模块（`features/dock/`）

```
┌──────────┬────────────────────────────┬──────────┐
│ 左停靠区 │        主区域（编辑器）     │ 右停靠区 │
│          ├────────────────────────────┤          │
│          │        底部停靠区           │          │
└──────────┴────────────────────────────┴──────────┘
```

- 模型是纯函数（`dock-layout.ts`）：`DockLayout = { left, right, bottom }`，每项是一个模块 id；
  校验带一条**不变式** —— 每个模块恰好出现一次（重复会让它被渲染两遍，而两遍的 DOM 带着
  同一个 id，之后任何按 id 查询的代码都会拿到第一个）；
- **只存"位置"，不存"可见性"**：可见性仍在各自的既有开关上（文件树 = `sidebarVisible`、
  链接 = `linksPanelVisible`、大纲 = `outlinePanelVisible`、标签 = tags-store 的 `open`）。
  `Ctrl+B` / `Ctrl+Shift+L` / `Ctrl+Shift+T` / `Ctrl+Shift+O` 四条快捷键因此一字不改，
  而且"哪块面板开着"只有一个真相；
- 尺寸沿用既有字段（左 = `sidebarWidth`、右 = `linksPanelWidth`、底 = `bottomDockHeight`）：
  同一块面板搬到另一侧时，用的就是那一侧的宽度 —— 不因为搬家而多出一套尺寸记忆；
- 缺省布局与改之前**逐像素一致**：文件树在左（可见），链接 / 标签 / 大纲在右且都收起着。
  左停靠区保留 `mn-sidebar` 这个类名（侧栏宽度、`Ctrl+B` 后的存在与否都有 E2E 断言）。

**两条操作路径**（可访问性要求）：

| 操作 | 鼠标 | 键盘 |
| --- | --- | --- |
| 换区 | 拖标题头到目标区（空区在拖动期间会先出现一条"可放"的轨道） | `Alt+1/2/3` = 搬到左/右/底部 |
| 同区内换位置 | 拖到某个模块的前半段（落点由**中线**判定，指示线画在插入位置） | 左/右区 `Alt+↑/↓`，底部区 `Alt+←/→` |
| 打开模块菜单 | 右键标题头 | 标题头上 `Enter` / `空格` |
| 隐藏模块 | 标题头上的 `×` | 菜单里的「隐藏这一块」 |

**为什么是"三个区 + 区内顺序"，而不是任意坐标的浮窗**：这一层要解决的是"位置"，
而自由窗格布局（任意分格、嵌套分栏、尺寸记忆、相机复位）是一个几十倍大的系统。
三个区已经覆盖"放左边、右边还是下边"这个真实诉求，区内顺序再用拖拽/键盘微调。

### 2. 标签栏搬到窗口顶部（`.mn-app` 的直接子节点）

标签是"这个窗口开着哪几篇笔记"的**全局**信息，挂在 `.mn-main` 里时它会跟着主区域被侧栏挤窄。
搬到 `.mn-body` 之上后它横跨整个窗口宽度。

**后续修订（修补轮）**：用户要求「标签栏要到标题栏上方」，于是 `.mn-app` 里的顺序变成
**标签栏 → 标题栏 → 主体**（标题栏现在是第二行，窗口按钮也在第二行）。
两个配套决定：① 顶行的空白段挂一个拖动区（`TabBar` 里的 `.mn-tabs__filler`）——
    标签栏到了最顶上，那一行必须还能拖窗口；只给空白段而不是整条，是因为 Tauri 的拖动区
    会跳过 `button/input/a`，而标签是 `role="tab"` 的 `div`，整条挂上会把"点标签"和
    "以后拖标签重排"一起吃成拖窗口；② 布局不变式不受影响（它是
    `主体 = 窗口 − 标签栏 − 标题栏 − 状态栏` 的**求和**，与顺序无关），UI E2E 另加一条
    "标签栏在窗口最顶行、标题栏在它下面"的位置断言。

- 随之删掉 `.mn-main:has(> .mn-tabs)` 那条条件规则（它原本用来把主区域改成列方向）；
  主区域重新是纯行方向的 pane 容器；
- 没有标签时组件返回 null ⇒ 窗口顶部只有标题栏，与从前逐像素一致；
- 布局契约的断言口径同步更新：主体高度 = 窗口 − 标题栏 − **标签栏（可能不存在，按 0 算）** − 状态栏。

### 3. 一个通用的右键菜单 + 三处接入

`components/ContextMenu.tsx`：调用方只给"项目清单 + 屏幕坐标"，共有的周边行为全在里面 ——
点击外部关闭、`Esc` 关闭、`↑↓/Home/End` 走位（**跳过置灰项**）、`Enter` 执行、
超出视口时**夹回可视区**、关闭后把焦点还给打开它的元素。

接入的三处（都指向既有入口，不复制业务逻辑）：

| 位置 | 菜单项 |
| --- | --- |
| 文件树行 | 打开/展开 · 在这里新建笔记 · 重命名… · 移动到文件夹… · 在文件树中定位 · 复制相对路径 · 展开/折叠全部（目录） · 删除到回收站… |
| 标签页 | 关闭 · 关闭其他 · 关闭全部 · 在文件树中定位 |
| 停靠模块标题头 | 移到左/右/底部 · 同区上移/下移 · 隐藏这一块 |
| 图谱卡片（画布上右键） | 在编辑器中打开 · 浮窗打开 · 居中显示 · 松开这张卡片 · 恢复自动尺寸 |

文件树与标签页的菜单项**直接执行既有命令**（`note.new` / `note.rename` / `note.move` /
`note.delete` / `tree.expandAll`…）：命令表是"这些动作到底做什么"的唯一事实来源，
右键只是它的又一个入口 —— 与 `F2` / `F6` / `Delete` / 工具栏按钮完全同一条链路。
"关闭其他 / 关闭全部"是这一轮新加的 store 动作，实现上**逐个走 `closeTab`**：
未保存确认、光标位置记忆、关掉当前标签之后接续哪一个，全都在那一条路径里。

图谱卡片的右键必须由组件自己接（卡片在 canvas 上，没有 DOM 可右键）：`onContextMenu` 里
按世界坐标命中，再顺手把那张卡片选中 —— 菜单里大多数动作作用于"当前选中的那一张"。

## 代价与已知边界

1. 同侧多块模块**平分**高度/宽度（`flex: 1 1 0` + `min-height: 96px`），没有"每块各自的尺寸记忆"；
   要精确控制请把不常看的那块隐藏（标题头上的 `×`），或用该区的分隔条调整整区的尺寸；
2. 停靠模型不做"同一块面板开两份"（模型的不变式是每个模块恰好一次）；
3. 底部停靠区的高度是全局一份（不按模块记），因为它表达的是"下面这条留多高"；
4. 右键菜单不感知"菜单打开时下面那块面板被隐藏了"这类竞态：菜单项执行的是命令，
   命令自己会判 `when`（不可用时置灰说明原因），菜单不重复一遍。
