# ADR-0025：图谱卡片读正文的那几条决定（完整正文、纯标题档、宽高可调、悬停引线）

- 状态：已采纳
- 日期：M3 之后（ADR-0024 的下一轮）

## 背景

用户在这一轮里提了六条与图谱卡片直接相关的诉求：

> 1. 可以增加一个配置是只有标题（文件名）的卡片
> 2. 鼠标悬浮 wikilink 的时候对应的关系连线高亮
> 3. wikilink 这里出发的关系连线太淡了，不够明显（仍然保持虚线）
> 4. 每个卡片聚焦后的失去焦点继续松开卡片，保持浮动
> 5. 每个卡片可以完整的展示全文（非侧边栏预览），移除侧边栏预览卡片的功能
> 6. 卡片现在只能调整宽度，不能够调整高度

六条各自独立，但它们的**同一个背景**是：卡片从 DOM 搬进 canvas（ADR-0021）之后，
"卡片正面画什么、多大、怎么与连线对上"这三件事都成了我们自己实现的几何 —— 于是每一条
诉求都要在几何层给出答案，而不是加一条 CSS。

## 决策

### 1. 移除停靠预览面板（`GraphPreview.tsx` 删除）

卡片正面本来就是那篇笔记的**完整 Markdown 预览**（与阅读视图同一套块清单，ADR-0021），
右侧再开一块预览面板等于同一份内容有第二个真相：改一处必须记得改另一处，
而两者迟早长得不一样（一个走 `renderMarkdown` 的 DOM，另一个走 canvas 的排版）。

- 单击卡片的语义收成**选中**：`data-graph-selected`、相关连线高亮、HUD 出现它的高度档；
- "读全文"这件事交给**浮窗**（`FloatingNote`，ADR-0023）：它是 DOM，可以选中文字、点链接；
- `Esc`（`graph.closePreview` 命令）的两层语义改成"先关最上面的浮窗，没有浮窗才取消选中"。
  命令 id 与快捷键**不变**：它是外部契约（快捷键表、测试、用户肌肉记忆），改名字的收益为零。

### 2. 「仅标题」档：一个开关，卡片压成一行高

正文卡片动辄几百像素高，跳数一多整幅图就剩几张卡片。`titleOnly` 打开后：

- 焦点视图**不排正文**（`egoLayout` 里直接返回壳高度，markdown 解析与折行的开销全省掉）；
- 高度由 `titleOnlyCardHeight(metrics)` 推出来 —— 与"正文为空的卡片"是同一个算式，
  不手写数字（否则标题行高/分隔线一改，留白就对不上）；
- 没有正文就没有可指的 `[[链接]]`：引线**如实降级**成"从卡片边界出发"（`fromLink: false`），
  而不是画一条指向某处文字的假线；
- 高度档那一行随之收起（纯标题卡片没有"正文高度上限"这回事）。

它是"我怎么看图"的偏好，与 `mode`/`depth` 同一份存储（`mimenote.graph.prefs.v1`），不按 Vault 分。

### 3. 宽高都能拖，另加「全文」档

- 手柄拖动从"只改宽度"改成**同时改宽与高**（`setCardSize`）：手柄的语义是"圈定这张卡片的框"，
  两个方向都是用户的显式意图。历史行为（只拉宽、并把高度上限重置成"自动"）保留在
  `setCardWidth` 上，它是另一条路（"改宽度"与"看全文"是两个正交意图，互不抹掉）。
- 高度档新增**「全文」**：`CardSize.full = true` ⇒ `layoutCard` 的 `maxHeight` 取 `Infinity`。
  它与数值档**互斥**：显式选一个数值上限就退出全文，反之亦然 —— 两者是同一问题的两种答案。
  为什么不用"一个很大的高度"表达全文：那还是一次截断，只是截得远；`full` 与内容长度无关。

### 4. 引线加粗加深，仍然保持虚线

引线（卡片内那段）原本是 1px / `opacity .55`，理由是"它是指示、不是边本身"。用户的实测反馈是
**看不见**。现在改成与卡外那段同粗（1.6）、`--mn-fg-muted` 色、`opacity .85`：

- 区分"指示"与"边本身"靠**线型**（虚线）而不是靠"更淡" —— 淡到看不见时，那条信息就不存在了；
- 虚线图案与相位仍由 `leadDash()` 按引线长度算（ADR-0023 的分界纪律不变：最后一段实线收在卡边）。

### 5. 悬停正文里的 `[[链接]]` → 提亮对应的那条边

新窗口 `linkZones()`（`link-edge.ts`）枚举卡片里**每一段** wikilink 的矩形（卡片内坐标），
与 `findLinkAnchor()` 共用同一套遍历与量宽 —— 于是"悬停高亮的那段字"与"引线出发的那段字"
必然是同一段（几何只有一份，两个功能不会各自漂移）。

- 命中在组件里做：指针 → 世界坐标 → 卡片矩形 → 卡片内坐标 → 热区；
- 热区按**卡片内坐标**存：漂浮每帧都在动，世界坐标的热区立刻就过期；
- 热区 → 边的映射复用 `matchRun` 的候选写法口径（`edgeTargets` + `normalizeLinkText`），
  匹配不上（悬空边、目标不在当前深度里）就**不亮** —— 不拿猜出来的边去高亮；
- 三处一起亮：连线（SVG，`--highlight`）、引线（`--lead--active`）、卡片里那段文字
  （canvas 画一个强调色圆角框），以及 `nwse`/`pointer` 光标。

### 6. 失去焦点即松开

"按住"（`pins`）曾经是近乎永久的状态，只有 HUD 的「松开卡片」能解除。现在判据是
**焦点走了就松开**，两条路都覆盖：

- 点画布空白处：`endPointer` 里显式 `releasePinsExcept(null)`（那一次选中可能根本没变 ——
  比如拖完卡片后本来就没选中任何东西）；
- 选中换到另一张：一条订阅 `selected` 变化的 effect（它也覆盖方向键、「定位笔记」、命令那几条路）。

松开时必须**加热**力场（`RELEASE_HEAT`）：`settle()` 之后强度是 0，只 `unpin` 的话卡片会
"松开了但一动不动"，用户只会以为按钮没生效。

## 代价与已知边界

1. 引线与"从文字出发"的定位只在**焦点视图**里有（全库视图的卡片是紧凑卡片，没有正文位置）；
2. 「全文」档在长笔记上会把卡片撑得极高，环半径随之外扩（同一环的其它卡片被推远）——
   这是用户明确要的效果，不是缺陷；真嫌大就用数值档或「仅标题」；
3. 悬停高亮只对"有对应边"的链接生效；指向图外的链接不伪装成可悬停；
4. 引线现在与卡外那段同粗，密集的卡片上会比从前显眼一些 —— 取舍是"看不见"比"略吵"更糟。
