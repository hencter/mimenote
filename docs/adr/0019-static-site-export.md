# ADR-0019：整库导出静态站点（每篇一个 HTML + 把双链变成可点的链接）

- 状态：已采纳
- 日期：M3 之后

## 背景

ADR-0011 交付了"导出**当前这一篇**"：自包含 HTML（图片内嵌 `data:`、样式内联）与打印/另存为 PDF。
那份 ADR 明确写下了它**没做**的两件事：只支持当前笔记、导出件里的 `[[双链]]` 不可点
（"链接到别处"在一个单文件里没有意义）。这一轮补上它：**把整个 Vault 导出成一个静态站点**。

需求侧的理由很具体：作者的 Vault 在一个同步盘里（4267 篇 Markdown），他时不时需要
"把整库拿给一个没有这个应用的人看"—— 可能是发一份出去、可能是丢到内网静态托管、
也可能是自己归档一份能长期打开的快照。为此要做出的产品承诺是：

* **打开就能看**：目录里有一个 `index.html`，双击（`file://`）就能读，不需要 web 服务器；
* **链接能点**：`[[双链]]` 变成指向另一份 HTML 的相对链接，反向链接也列在每页底部；
* **图片在**：图片随站点一起走，不是一堆占位元素；
* **零依赖**：不引 CDN、不引字体、不引任何外部地址（与 ADR-0011 同一条纪律）。

真正需要决策的不是"生成 HTML"，而是**这条流水线怎么分层**，以及一串只有落到实现上
才会显形的语义（输出目录放哪、同名怎么办、链接怎么改写、能不能增量、确定性怎么保证）。

## 决策

### 1. 三段式：宿主出计划 → 前端渲染 → 宿主批量落盘

这是被两条"唯一一份"逼出来的形状，不是审美选择：

* **Markdown→HTML 的唯一渲染管线在前端**（`domain/markdown.ts` 的 `renderMarkdown`：
  markdown-it + DOMPurify）。ADR-0011 已把"不另写一份渲染"定为硬约束，理由在这里同样成立：
  另写一份就是同时维护两套语法口径与两条 XSS 防线。Rust 侧（`mn-core`/`mn-index`）没有渲染器，
  也不该引一个 —— 那还会牵扯 `docs/dependencies.md` 的依赖与许可证纪律。
* **链接解析的唯一规则在链接索引里**（`mn_index::LinkIndex::resolve_target`：相对本目录 →
  Vault 根 → 后缀表 → 主干兜底，外加歧义消解）。前端复制这套规则是这一块最容易犯的错 ——
  "站点里的链接指向谁"与"反向链接面板里的链接指向谁"一旦漂移，用户看到的就是两套事实。

于是分成三条命令（外加一条通用的批量读）：

| 命令 | 角色 |
| --- | --- |
| `export_site_plan(outputDir?)` | 只读、一次往返：页面表（含每页的出链 href、反链、标题、标签）、统计；给目录时做目标目录预检并回带上次的标记 |
| `notes_read_batch(relPaths[])` | 批量读原文（4267 篇从 4267 次往返压到 ~178 次）；单篇失败进 `skipped`，不整批失败 |
| `export_site_write_pages(outputDir, files[])` | 批量落盘（白名单 `.html`/`.css`/`.json`、逐段路径校验、逐文件原子写、**批内按数组顺序写**） |
| `export_site_copy_assets(outputDir, assets[])` | 把图片复制进 `assets/`（字节只在宿主里搬，不走 IPC 的 base64 通道） |

**被否掉的替代**：① 宿主一条命令跑完全程（要引渲染器并复刻净化规则，两条管线必然分叉）；
② 前端逐篇 `note_read` + 逐篇 `export_write_html`（8500+ 次往返，而且会把"唯一允许写
Vault 之外"的那条命令的能力面放大成"往任意目录写任意多个 HTML"）。

### 2. 输出目录**必须在 Vault 之外**

在 Vault 内、等于 Vault 根、或在 `<Vault>/.mimenote` 之下 → `PATH_INVALID`，附一句人话理由。

三条具体的代价（都在这个仓库里能观察到）：① 应用自己的**扫描器与文件监听**会把几千个
新出现的 `.html` 当新文件处理，导出完立刻触发一轮重扫风暴，文件树被灌满；② 用户的 Vault
**很可能在同步盘里**（作者的就是），整站会被同步客户端上传一份，几百 MB 起步；
③ Vault 内的派生产物早有指定位置（`.mimenote/`），而那里我们**拒绝**写（与 `dir_move` 同一条规则）。

**被否掉的替代**：在 Vault 内建一个 `站点/` 并让扫描器忽略它。那要给扫描器与监听器加一条
**会话级**忽略规则（不是配置项），而"忽略规则"本身就是一类容易漏的地方（用户手工在那里放一篇
笔记就再也扫不到）；相比之下"请选一个 Vault 之外的目录"是一次性的、可解释的成本。

### 3. 非空目录必须先证明"这是我们上次导出的"（标记文件），且**从不删除**

* 目录不存在 → 建（`createdDirs` 如实报出，与 `note_restore` 同一口径）；
* 存在且为空 → 直接用；
* 存在且非空 → **必须有我们上次写的 `mimenote-export.json`**（`tool == "mimenote"`、JSON 能解析），
  否则 `ALREADY_EXISTS`。理由：输出目录是用户选的，很可能是一个装满东西的目录（`D:\Documents`），
  没有这条规则就等于"把几千个文件散进用户的文档目录"。
* 有标记 → 只覆盖我们自己的文件，**从不删除任何文件**：上次标记里有、这次没有写的文件留在原处，
  由前端按 `previous.files` 与新清单对比后在结果与索引页里点名。

**这一条严格版只落在"计划"命令上**（`export_site_plan` 是唯一会拒绝的入口，用户在那里看到原因）。
两条写命令（`export_site_write_pages` / `export_site_copy_assets`）的判定放宽成
"**绝不覆盖一个无法证明属于我们的已存在文件**"（目标文件已存在且目录里没有有效标记 → `ALREADY_EXISTS`）。
原因很实在：标记文件按契约**最后**写，而前端每 200 个文件落一批 —— 让写命令也要求标记，
就等于"第二批开始全部失败"，导出永远走不完。

最后这一条与 ADR-0018（回收站没有"永久删除/清空"）是同一条底线：**应用不替用户删东西**。
代价是重导出一个变小了的 Vault 会留下旧页面（点名即可，用户想彻底重来就先删掉那个目录）。

### 4. 页面命名：镜像目录树 + `.md` → `.html`；URL 逐段百分号编码

`项目/设计 草案.md` → 磁盘上的 `项目/设计 草案.html`，页面里的链接写成
`%E9%A1%B9%E7%9B%AE/%E8%AE%BE%E8%AE%A1%20%E8%8D%89%E6%A1%88.html`。

**磁盘保留原名**：用户就是按目录找东西的，`file://` 直接双击也最好读。
**href 必须编码**：文件名里的空格、`#`、`%`、CJK 不编码会生成语法上错误的 URL
（`#` 之后会被当成片段、`%` 之后会被当成转义），`!`/`'`/`(`/`)`/`*` 也不放行 ——
它们在 Markdown/wiki 语法里是有含义的字符。编码规则只保留 RFC 3986 的 unreserved 集合，
十六进制**大写**（大小写会影响"两次导出是否逐字节相同"）。

**被否掉的替代**：把标题 slug 化。中文标题 slug 之后地址栏变成 `design-a1b2.html` 这类
看不懂的名字，而且 URL 不再是源路径的**纯函数**（要另维护一张标题 → 文件名表，重名还要再消歧）。

同名笔记（`设计.md` 与 `设计.markdown`）映射到同一个 `.html` 时，按顺序第一份保留原名、
其余追加 `-2`/`-3`，并在计划与索引页里**如实报出改名清单**。

### 5. 链接：解析在索引里，前端只查表；悬空链接渲染成不可点的文字

计划里的每一条链接已经带好了 `href`（相对**本页**、含编码后的片段）。
前端的渲染管线为此多了一个 env 钩子 `resolveWikilink(target, anchor)`：拿到 href 就写进 `<a>`，
返回 `null`（悬空）就渲染成 `<span class="mn-wikilink--dangling">` ——
站点里没有"点击创建"这条路，让它看起来可点就是骗人。

**没有**对渲染出来的 HTML 做字符串改写：那要把"我们自己生成的属性顺序"变成一份隐含契约。
钩子让"链接指向哪"只有一处判断，而"谁能解析到谁"依然只有索引那一份。

`![[另一篇笔记]]`（嵌入非图片）与 `[[另一篇笔记]]` 完全同形（既有渲染管线的分流不变）；
`[[甲#小节]]` 的片段指向标题 id —— 因此渲染时为标题生成 `id`（取标题纯文本，同名按顺序加
`-1`/`-2`），**否则带锚点的链接点下去只会停在页首，看起来像链接坏了**。这个能力由
`renderMarkdown` 的 `headingIds` 选项控制，**默认关**：应用内的阅读视图不需要它
（标题跳转走 `outline-scroll.ts`），只有导出站点时才打开。

### 6. 图片：复制到 `assets/<原 Vault 相对路径>`，**不内嵌 `data:`**

单个自包含 HTML 必须内嵌（ADR-0011）；站点是一个**目录**，内嵌会让同一张图在几千个页面里
各存一份 base64（体积 ×4/3，而且浏览器完全没法缓存）。`assets/` 下是 O(1) 映射、
永不碰撞，我们自己在里面唯一的产物是 `assets/site.css`（`.css` 不在图片白名单里，
结构上不可能撞）。

**图片清单来自前端渲染时收集**（`resolveImage` 钩子顺手记一笔）：那才是"正文里到底引用了哪些图"
的权威答案 —— 它用的是与阅读视图完全相同的 `createAssetResolver`（相对路径、裸文件名兜底、
越界拒绝），不像"在 Markdown 源码上跑正则"那样要复刻围栏代码块与转义规则。

宿主侧的 `SitePlan.assets` **刻意留空**：链接索引根本不收录附件（只收 `.md`/`.markdown`），
要在 Rust 里复刻 `createAssetResolver` 要么加文件 IO（破坏"计划零 IO"），要么凭正文文本猜，
而两份规则漂移的后果是**不对称的**（页面里写了 `<img src>`、图却没被复制 ⇒ 死图）。
契约仍然保留这个字段（将来可以由宿主补上），前端按**并集**处理，安全判定不依赖它。
图片分批发给宿主（每批 200 张，见 §3 的命令上限），因此单张/整批上限永远不会碰到。

单张上限 64 MiB；读失败/越界/非图片 → 跳过并如实汇报，页面里退化成既有的占位元素。

### 7. 样式：整站**一份** `assets/site.css`（对 ADR-0011 的有意偏离）

ADR-0011 的规则是"样式内联、零外部引用"，它服务的是"**单个文件**拿到任何地方都能看"。
站点是目录形态，允许一份共享样式表 —— 4000 个页面各内联 6 KB 就是 24 MB 的重复字节，
而且改一次主题要重写 4000 个文件。

内容复用 `buildExportCss(tokens, appearance)`（**与单篇导出同一个函数**），
再加站点外壳（导航、索引页、反链、悬空链接样式）；主题令牌仍由 `readExportTokens()`
从 DOM 取成**字面值**；Vault CSS 片段（用户自定义样式）默认拼在后面并逐段标注来源。

**代价写进下面的表**：单个页面文件离开站点目录后样式会丢。

### 8. 零 JavaScript，因此**没有站内搜索**

* 用户那套 4267 篇 / 50 万行的 FTS5 库实测 **207 MB**（`docs/architecture.md` §8），
  塞进静态站不可接受；
* 浏览器在 `file://` 下**禁止 `fetch()`** —— 任何"打开页面时加载一个 json"的设计，
  恰好会在"从磁盘打开"这个我们承诺的场景里静默失灵；
* 需要搜索时的替代路径已经够用：索引页 + 双链跳转 + 浏览器自带的 `Ctrl+F`。

折叠用 `<details>`、明暗用 `prefers-color-scheme`，都是零 JS 的。
标记文件里的文件清单是将来生成 `search-index.json` 的天然落点（v2 的事）。

### 9. 确定性：同一个 Vault 导出两次**逐字节相同**（页面里没有时间戳）

三条理由：① 用户的 Vault 在同步盘里，几千个文件每次重导出都变会让同步客户端整站重传；
② "这次导出到底改了什么"要靠文件对比才看得出来；③ 确定性是可以**测**的性质（有一条测试）。

做法：页面与索引页**不含时间戳**（导出时间只写在标记文件里，它是元数据不是页面）；
一切顺序显式排序（页面按计划顺序 = 路径字节序、链接按文档顺序、图片按码元序）；
标记文件用固定字段顺序的结构体；编码固定大写十六进制。

### 10. 落盘：逐文件原子写，**不做整目录 staging**；单篇失败不中断

* 每个文件走 `mn_core::atomic::write_atomic`（同目录临时文件 → fsync → rename，ADR-0004）；
* 不做"先写临时目录再整体替换"：Windows 上无法把 staging 目录原子覆盖到已存在的目录，
  而"先删后换"等于对我们不该删的东西动手；
* 单篇读/渲染失败（非 UTF-8、超过读取上限、渲染异常）→ 跳过、继续跑完、如实汇报：
  绝不因为一篇坏笔记让另外 4000 篇白跑；
* **`index.html` 与标记文件最后写**：中途取消或断电留下的是"部分但自洽"的站点
  （每个文件都是完整的），而且没有任何东西自称导出完成。

### 11. 进度与取消都在前端（宿主没有可取消的后台任务）

循环在前端（渲染只能在前端），于是进度天然是 `i/N`、取消就是"不再发下一批"
（每批 24 篇之间检查一次标志位）。宿主侧只有短命令，不需要 `indexer.rs` 那套
`AtomicBool` + `mn://index-status`（那套存在的理由是宿主拥有循环）。

取消后**不写索引页与标记文件**，并明确告诉用户"已经写出 N 个文件、那个目录不会被认成一份
完整的导出、想接着来就换个空目录或先删掉它"。这里刻意**不**做"续传"：目标目录在没有标记文件时
会被计划命令判成"不是我们的目录"（`ALREADY_EXISTS`），而宿主无法区分"我们上次没写完的部分导出"
与"用户自己装满东西的目录" —— 要支持续传就得引入 `complete: false` 的进度标记，
那会动摇"标记文件 = 完成凭据"这条不变量，不值得。

### 12. 新增一个错误码 `INDEX_NOT_READY`

`export_site_plan` 在链接索引未就绪时返回它。为什么不借既有的 `IO`：
`describeError()` 会把 `IO` 翻成"磁盘读写失败：…"，而真实情况是"索引还在构建，等一下就好" ——
那句话比不说还糟（用户会去查磁盘）。同构的先例是附件那轮的 `UNSUPPORTED_MEDIA`。
顺带把 `tag_rename` 里那处借 `IO` 的"索引正在构建"也换成新码（当年借 `IO` 是权宜）。

### 13. 业务性拒绝要显示**宿主原话**，不按错误码翻译

`describeError` 是按错误码翻译的，`PATH_INVALID` 一律翻成"路径不合法或被拒绝（已阻止越界访问）"。
那句话对"拖拽越界"是对的，但对有**具体业务理由**的拒绝就是错的：整库导出把输出目录选在
Vault 里时，宿主写的是"输出目录不能放在 Vault 里面：…（讲清三条代价）"，一翻译就只剩
"路径不合法"，用户完全不知道该怎么办。因此新增 `describeHostReason(error, context)`：
宿主的 message 非空就用它（那是写给用户看的中文），空 message 才退回按码翻译。
`moveTag`（ADR-0006 后续修订）也改用同一个函数。

### 14. 相对路径算术在两端各有一份（**有意的重复**，边界写清楚）

宿主算"笔记之间的链接"（计划里每条的 `href`），前端算"目录树自己的链接"
（索引页 → 每一页、每页 → 反向链接、每页 → 共享样式表）。

为什么接受这一次重复：这两类链接的**数据来源**不同 —— 前者需要链接解析结果（只有索引有），
后者只需要页面路径表（前端拿到的计划里就有）。让宿主为后者再算一遍，要么多一列数据、
要么多一次往返，而"从 A 到 B 的相对路径怎么写"是一段十行的纯算术。

边界因此写死在架构里：**"谁指向谁"只有链接索引那一份**（语义规则，漂移了就是两套事实），
**"路径怎么写"两端各有一份**（纯算术，两边都有测试）。前端这一份在 `domain/site-paths.ts`，
Mock 适配器直接复用它（因此"Mock 里的 href"与"真机里的 href"不可能不一致）。

## 代价与已知限制

| 项 | 说明 |
| --- | --- |
| 输出目录不能在 Vault 内 | 想放在 Vault 里就得先给扫描器与监听器加会话级忽略规则（见决策 2 的被否替代） |
| 单个页面文件不能单独拿走 | 样式在共享的 `assets/site.css` 里（见决策 7）；要"单文件到处能看"就用单篇导出的自包含 HTML |
| 站内没有搜索 | 零 JS 的直接代价（见决策 8）；`Ctrl+F` + 索引页是替代路径 |
| 不做增量重导出 | 每次整库重渲染。计划本身是 O(索引) 且不读文件，成本全在渲染；跨会话的导出台账是一类新的持久化状态，而 ADR-0002 对派生数据的态度是"可重建" |
| 重导出不删旧文件 | 变小了的 Vault 会留下旧页面（结果与索引页都点名）；想彻底重来就先删掉那个目录 |
| 图片先写页面、后复制 | 中断会留下短暂死图（页面引用的 `assets/…` 还没到）。消掉它要把"两遍渲染先发现图片"的成本乘上几千篇，不值得 |
| 标题口径与单篇导出可能差一级 | 站点用"frontmatter `title` ?? 文件名主干"（与图谱卡片同口径，**能在不读文件的前提下算出来**），单篇导出还多一条"正文首个 H1"回落 |
| 锚点只认标题纯文本 | 同名标题的链接落到第一处（与 Obsidian 同口径）；正文里的自定义锚点不支持（既有抽取器没有这个概念） |
| 大 Vault 仍是主线程分片渲染 | 每批 24 篇后让出一次主线程，进度可见、可取消；真正的"离屏渲染"是 M5 的 Web Worker 计划（见 `docs/milestones.md`） |
| 图片超过 64 MiB 不复制 | 也不降采样/转码（与 ADR-0013 的"原样落盘"一致），页面里退化成占位元素并如实汇报 |
