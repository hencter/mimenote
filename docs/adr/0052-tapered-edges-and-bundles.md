# ADR-0052：渐细笔触取代箭头 + 同一对笔记的多条链接画成平行束

- 状态：已采纳（已交付）
- 日期：v0.3.0 之后（ADR-0036 结尾列的"三件更优雅的线"里的前两件）
- 相关：ADR-0021（图谱改成 canvas 卡片）、ADR-0023（引线与卡片边界的分界纪律）、
  ADR-0028（连线的语义分层与环向走线）、ADR-0036（连线搬进 canvas，60fps）

## 背景

ADR-0036 把连线搬进 canvas 之后留了三件事："渐细笔触取代箭头、同一对笔记的多条链接画成
平行束、真正的避障布线"。前两件的**数据早就有了**（`GraphEdge.count` 记着同一对之间有几条链接，
只是从前只出现在 tooltip 里），缺的只是几何与画笔。

当时的箭头是 SVG `<marker>` 的等价物：一个填充三角形，大小是**线宽的倍数**
（`markerUnits = strokeWidth`）。跳数权重生效之后（线宽 1–3 倍变化），近处的箭头又粗又抢眼、
远端的箭头小到看不见 —— 同一个"方向"读出两种重量；而且它有一半压在卡片下面
（卡片画在连线之上），看起来像被裁掉。

## 决策

### 1. 方向由**线自己的形状**表达：起点满宽、末段收尖

- 纯几何在 `features/graph/canvas/taper.ts`（可单测、不碰画布）：
  `taperFactor(t)` 给"线宽系数"，`taperPolygon(points, halfWidth, profile)` 把采样折线
  展开成多边形；画笔只负责 `fill()`。
- 收窄曲线：**前半段满宽**（`TAPER_START = 0.5`），之后按 `TAPER_CURVE = 1.6` 收到
  `TAPER_TIP_RATIO = 0.12`。留 12% 而不是收成零宽：收成 0 会在终点留下一道随驱动而异的锯齿。
- **终点逐坐标仍是几何层给的 `end`**（多边形最后一个点就落在它上面）：卡内引线与卡外这段的
  分界纪律（ADR-0023）不能因为换了形状就破。
- **为什么不"让线宽递减地描边"**：`stroke` 的线宽对一整条路径是常量，想渐细就得把路径切成
  几十段、每段单独 `stroke` —— 漂浮是 60fps，每帧几十次额外绘制调用是实打实的代价；
  多边形填充一次就够，代价与一条线同量级。

### 2. 虚线边 = 虚线（语义）+ 实心笔尖（方向）

虚线在本产品里表达"被动/缺席"（入链、悬空目标），这条语义不能丢；但虚线的末段原本会
**随机地**停在卡片边界附近的某处（取决于图案相位），看着像"没画完"。所以：
整条仍按 `5 4` 描虚线，**末端 18 世界像素**再补一个实心的渐细笔尖。

### 3. 平行束：`count > 1` 时画 2–3 条

- `bundleMembers(count)` 上限 `BUNDLE_MAX = 3`（再多就糊成一团，剩余量与理由交给 tooltip，
  tooltip 里本来就写着"共 N 条链接"）。
- 偏移是**单侧**的（`0, 3.2, 6.4`…，`BUNDLE_GAP = 3.2` 世界像素）：主笔触偏移恒为 0，
  于是它**逐坐标**落在几何层给的锚点上，卡内引线接得上；对称分布（`−(n−1)/2 …`）在
  `count` 为偶数时没有任何一条落在 0 上，交界处必然错开半个间距。
- 偏移方向取"行进方向的右手侧"（局部法向），因此与扫过顺序、视口、缩放都无关 ——
  同一份数据反复画、平移缩放之后，哪一条在左边不会变（连线里没有随机量的那条纪律）。
- 实现上是**沿局部法向平移采样折线**：所以曲线两端位移的**方向可以不同**（不是整体平移），
  但两端距离都恒等于 `BUNDLE_GAP` —— 这正是"始终保持这个间距"该有的样子。

### 4. 自动化抓手

- `PaintedEdge.bundle`：这条边画了几条笔触（引线恒为 1）；
- 宿主上新增 `data-graph-edge-bundled`（画成束的**边数**）与 `data-graph-edge-lines`
  （Σ 笔触数）。既有那批 `data-graph-edge-*` 的语义**不变**：仍按**边**数算，不是按笔触数
  （否则"入链画虚线、出链实线"那几条断言会因为束而变味）。

## 代价与已知边界

1. **实线边不再 `stroke`**（只有一个 `fill`）：任何"数描边"的自动化都要改成"数填充的多边形"。
   本轮把 `tests/graph.test.tsx` 的记录型画布扩了 `fill` 记录，并加了 `centerlineOfRibbon()`
   （从带子的多边形还原中心线）—— 悬停落点、张力对照那几条用例因此仍然精确落在中心线上。
   `tests/graph-paint.test.ts` 里"连线先画"那条也从"数 stroke"改成"描边或填充，且颜色是连线色"。
2. 带子是**采样折线**的近似（每条曲线段 16 个点）：与 SVG 版的贝塞尔描边有亚像素差异。
   **命中判据不受影响** —— `edgeAt` 读的仍是几何层给的精确 `commands`。
3. 束内**主笔触之外**的那几条不在命中判据里（`commands` 只回主笔触）：它们离主笔触
   3.2/6.4 世界像素，5 屏幕像素的容差在 1× 缩放下仍然够；缩到 0.25× 时外侧那条会超出容差
   （如实记在这里：极端缩放下"指到最外侧那条"会命中不到）。
4. 笔尖长度 `TIP_LENGTH = 18` 是常数：比整条线还长的短线（悬空边那种）整条都在收尖，
   于是它看起来像一个小箭头 —— 这是"以形状表达方向"的必然结果，不是例外。
5. **避障布线仍未做**：ADR-0028 的"跨环朝外鼓"还是近似（不与卡片做真正的相交回避）。
