# ADR-0029：标题栏定型为左/中/右三区，当前笔记路径搬进中区

- 状态：已采纳
- 日期：M3 之后（上一轮的十余条需求交付之后的修补轮）

## 背景

用户的原话：

> `mn-editor__path` 这个居中在中间页，现在高度不固定，我希望在标题栏那一行，你分成三个区域左侧，中间，右侧

两个都成立的现状：

1. **路径行长在编辑器面板里**（`features/editor/MarkdownEditor.tsx` 的 `.mn-editor__path`，26px）。
   它只横跨**中间那一列**（左边被侧栏挤、右边被右停靠区挤），而且**只在编辑视图里存在** ——
   于是"顶部到底多高"取决于两件与布局无关的事：有没有打开笔记（打开就多出 26px，
   下面所有内容整体下跳）、当前是哪个视图（阅读与图谱视图里整行消失）。
   用户说的"高度不固定"指的是这件事，不是那 26px 本身。
2. **标题栏当时是一行 flex**（34px，ADR-0017 之后它就是唯一的标题栏）：
   菜单 + 品牌 + Vault 名 + 统计 + 导出 + 三个窗口按钮平铺，靠 `margin-left: auto`
   把窗口按钮推向右端。它没有任何"锚点"：想在中间放点东西，只能靠左右内容恰好一样宽。

阅读视图与图谱视图里看不到"当前是哪一篇"，一直是个空白 —— 标签栏的高亮是间接信号，
而它在标签多到要横向滚动时还看不见。

## 决策

### 1. 标题栏 = 网格的三区，列宽 `1fr / 2fr / 1fr`

| 区 | 回答的问题 | 内容 |
| --- | --- | --- |
| 左 | 我在**哪个库** | 应用菜单、产品名（Mimenote）、当前 Vault 名 |
| 中 | 我在**哪一篇** | 当前笔记的 Vault 内相对路径 + 「保存中…」 |
| 右 | 这个库**多大** + 出口动作 | 条目统计、导出、三个窗口按钮 |

**为什么是 `grid` 而不是 `flex` + `margin: auto`**：中区要落在**窗口正中**，而左右两区的内容
宽度完全由数据决定（库名长短、统计的位数）。两条等宽的 `1fr` 轨道让"居中"成为网格的**性质**；
flex 那种写法里，"居中"是"两边内容刚好一样宽"这个巧合，库名一长就会歪。

**为什么中区是 `2fr` 而不是 `auto`**：`auto` 会被一条长路径按最大内容宽度撑开，
把右区的窗口按钮挤出窗口。给死"一半宽度"之后，长路径走省略号。

**为什么纵向刻意不写 `align-items`**（保持默认 `stretch`）：三区都撑满 34px，
`.mn-window-controls` 的 `align-self: stretch`（"点关闭不该要求瞄准一个 10px 的方块"）
依赖的就是这个 —— 写了 `center` 就得再给右区单独补一条 `align-self: stretch` 才等价。

左右两区的内容**允许被省略**：Vault 名在 `title` 里有完整根路径，统计在状态栏里有完整一份，
产品名则给了 `flex: 0 0 auto`（永不压缩）。

### 2. 路径只留一处：标题栏中区

删掉 `.mn-editor__path` 与 `.mn-editor__status`（连同 `MarkdownEditor` 对 `note-store.status`
的订阅 —— 它只为那一行存在）。三条后果，都是想要的：

- **顶部高度恒定**：标题栏永远 34px（标签栏仍按既有规则"没有标签就不渲染"）；
- **三种视图里都看得见路径**：阅读与图谱视图不再是"不知道自己在哪一篇"；
- **编辑器的 26px 还给了正文**。

### 3. 标题栏仍然整条都是拖动区

`data-tauri-drag-region="deep"` 一个字没动：三区都只是 `div`（不是 `button`/`input`/`a`），
Tauri 注入的脚本照旧自动跳过窗口按钮与菜单按钮。这条纪律来自 ADR-0017，本轮不推翻。

### 4. E2E 的"当前文档探针"跟着搬

`.mn-editor__path` 一直是自动化里"当前打开的是哪一篇"的主力读法（UI E2E + 应用层 E2E 共约 20 处）。
它换成 `.mn-titlebar__path` 之后，`openNoteInTree` 里那个分支

```ts
// 编辑视图有编辑器工具栏；阅读/图谱视图没有 → 退回"树里这一行被选中"
```

整段删掉了 —— 路径在三种视图里都在，不需要再拿一个间接信号兜底。
**测试变简单不是"顺手省事"，而是那个间接信号本来就是在补偿路径的缺席。**

## 代价与已知边界

1. **中区的宽度上限是窗口的一半** ⇒ 长路径走省略号（完整路径在 `title` 提示里）；
   窗口窄到 1000px 上下时，右区的统计也开始省略（状态栏里那份是完整的）。
   这是"路径必须居中"与"长路径不能吃掉右区"之间唯一可行的折中。
2. **路径不可选中复制**：标题栏带 `user-select: none`（它同时是拖动区），
   而从前那一行在编辑器里是可以选中的。要"复制路径"的场合（粘进文件对话框、写进文档）
   应该走文件树/标签的右键菜单 —— **本轮没有做这个菜单项**，先记在这里。
3. **中区显示的是"当前文档"，不是"画布中心"**：全库图谱视图下二者不是一回事
   （只有关系图的圆心才等于当前笔记）。中区表达的是"最后打开的那一篇"，
   这与窗口标题（ADR-0017 / `window-title.ts`）保持同一口径。
4. **三区内容不可配置**：ADR-0026 的停靠模型只管**视图模块**，标题栏不在它的作用域内；
   想往里加东西仍然是改 `App.tsx`。目前没有"把某个状态挪进标题栏"的需求，不做机制。

## 验证

- 单测 `tests/app-shell.test.tsx`：三区都存在、路径渲染在**中区**、编辑器里那一行确实没了、
  以及 CSS 契约（`display: grid` + `1fr/2fr/1fr`、中区 `justify-content: center`、
  右区 `justify-content: flex-end`、标题栏纵向不写 `align-items`）；
- E2E `e2e/ui.e2e.test.ts`「标题栏分三区：当前笔记路径落在窗口正中，三种视图里都在」：
  路径盒子的中心与窗口中心相差 ≤2px（"居中"是像素级的事，jsdom 测不了）、标题栏高度仍是 34px、
  路径在阅读与图谱视图里仍然在。
