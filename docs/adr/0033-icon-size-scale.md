# ADR-0033：图标尺寸刻度（`IconSize`）与两道闸

- 状态：已采纳
- 日期：修补轮（用户报"图标大小怎么是没有统一规范的"之后）

## 背景

用户的原话：

> 我们的图标大小怎么是没有统一规范的！

查下来的事实：`<Icon>` 当时有 **78 个调用点、9 种字面尺寸** ——
11 / 12 / 13 / 14 / 15 / 16 / 18 / 22 / 26，另有 8 处用默认值 16。于是：

- 同一类东西（页签里的图标）在不同地方是 11、12、13；
- "这里该用多大"完全靠手感，`13` 与 `14` 差的那 1px 谁也说不清是有意还是随手；
- 改起来没有落点：想统一就得先把它们找出来（这次是靠一次全量扫描）。

VI 规范那边给的是"24×24 网格、输出 16 / 20 / 24、描边 1.5–2px" —— 描边我们已经合规
（`Icon.tsx` 里 `strokeWidth="1.6"`），尺寸则完全没有落点。

## 决策

### 1. 五档刻度 + **联合类型**

```ts
export const ICON_SIZES = { xs: 12, sm: 14, md: 16, lg: 20, xl: 24 } as const
export type IconSize = keyof typeof ICON_SIZES
```

`size` 从 `number` 改成 `IconSize`，**写刻度外的数字直接编译不过**。这是这套规范最主要的执行力：
不是"文档里写了一条约定"，而是类型系统在每次写代码时就地问一次。

五档的用法（照着挑，不要凭手感）：

| 档 | px | 用在哪 |
| --- | --- | --- |
| `xs` | 12 | 密集处：树行/页签里的图标、页签与面板头的关闭、角标 |
| `sm` | 14 | 常规控件：面板头、工具条按钮 |
| `md` | 16 | **默认档**：工具栏、正文级、对话框里的动作图标 |
| `lg` | 20 | 空状态与提醒：对话框的警示图标、编辑器占位里的文件图标 |
| `xl` | 24 | 整块插画级空态（门闸页的品牌图标） |

### 2. 旧的九种尺寸怎么映射（一次性收敛）

| 原 | 11 / 12 / 13 | 14 | 15 / 16 | 18 / 22 | 26 |
| --- | --- | --- | --- | --- | --- |
| 新 | `xs` 12 | `sm` 14 | `md` 16 | `lg` 20 | `xl` 24 |

78 处一次改完；**默认值也从裸的 16 变成 `'md'`**（语义相同，但读起来是"刻度里的中档"）。
观感上只有 ±1~2px 的位移，没有结构性变化（UI E2E 全绿）。

### 3. 两类图标**不走**这把尺子

字形图标（callout 的 `✎`/`★` 那一类、编辑器行内的 `✓`）按**字号**走 `em`（1.15em / 1em），
因为它们是**文字**：正文放大时应当跟着放大。把它们也钉成 px 会在用户调大阅读字号时
出现"图标比周围文字小一圈"。这条写进 `Icon.tsx` 的注释里，免得下一个人来"统一"它们。

### 4. CSS 侧也留一把同样的尺子

设计令牌别名层里加 `--icon-xs…--icon-xl`（12/14/16/20/24），给"用 CSS 给某个 svg 定尺寸"
的场合用。它与 `ICON_SIZES` 由单测**钉在一起**（两处数字不一致时红）。

## 两道闸（`tests/icon.test.tsx`）

1. **源码扫描**：`src/` 下 `<Icon ... size={<数字>}>` 必须是 **0 处** ——
   类型系统拦得住"新的裸数字"，但拦不住"有人把 prop 类型放宽"，所以扫描这道闸留着；
2. **实参只能是刻度名**：`size` 的实参若既不是五个名字之一（例如 `size={someNumber}` 这种
   变量写法）也是红 —— 变量会绕过类型检查带来的可读性，正是"又变成手感"的入口。

外加两条：刻度值本身（12/14/16/20/24、升序）与 `--icon-*` 令牌的一致性。

## 代价与已知边界

1. **±1~2px 的观感位移**：收敛必然带来一次微调（11→12、13→12、15→16、18→20、22→20、26→24）。
   这一轮没有逐屏对比截图，靠的是 UI E2E 的布局断言与"没有结构性变化"这个判断；
2. **刻度是 5 档**：遇到"确实需要 18px"的场合没有位置可放 —— 这是刻度该有的约束
   （要么归到 `md`，要么归到 `lg`），但如果将来出现**成体系**的新尺寸需求（例如 32px 的插图），
   正确做法是加一档并在这里记账，而不是就地写数字；
3. **`Icon` 之外的图标不受这把尺子管**：内联 `<svg>` 直接写死宽高的地方（例如 `WindowControls`
   的三个窗口按钮，按 Windows 惯例是 10×10 的几何图形）仍在各自的实现里，
   没有统一进刻度 —— 它们是"图形"而不是"图标字体/图标网格"的一部分；
4. **没有 lint 规则**：闸在单测里，跑 `pnpm test` 才红；真正"写的时候就红"只有类型那一半。
   要做 lint 规则得引入 ESLint 自定义规则，与本仓库"依赖逐个登记理由"的策略冲突，因此不做。
