# ADR-0013：粘贴 / 拖入的图片落进 Vault 的附件目录

- 状态：已采纳
- 日期：M3

## 背景

M2 的 ADR-0007 解决了"**读**本地图片"：`asset:` 协议逐文件授权、`![](相对路径)` 与 `![[嵌入]]`
渲染、点开放大、导出时内嵌成 `data:` URL。但**写**一直是空缺的 —— 编辑器里 `Ctrl+V` 粘一张截图
什么都不会发生，"把图放进 Vault"这件事只能靠用户手动另存文件、再手打一行 Markdown 路径。
这恰好是笔记应用里最高频的图片入口（截图工具 → `Ctrl+V`），缺它的体感是"图片功能只做了一半"。

难点不在"把字节写到磁盘"（`mn_core::atomic::write_atomic` 早就有），而在三件事同时成立：

1. **留在 Vault 内**：写路径来自"用户设置 + 剪贴板给的文件名"，两者都不可信，必须过
   `path_guard`（ADR-0007 已经证明目录级信任会被符号链接绕过）；
2. **不破坏既有输入习惯**：编辑器是 CodeMirror 6，它**自己**处理 `paste` 与 `drop`
   （会把拖进来的文件当文本读），任何"另加一个监听"的做法都会让一次粘贴跑两遍；
3. **命名要可预期**：截图工具给的文件名往往是 `image.png` 或干脆没有名字，连续粘贴多张会互相覆盖。

## 决策

### 1. 前端拿字节，宿主落盘：一条新命令 `attachment_save`

```
attachment_save(dirRel, files: [{ name, dataBase64 }]) -> [{ relPath, sizeBytes }]
```

前端从 `File`（粘贴走 `ClipboardEvent.clipboardData`、拖放走 `DataTransfer`）读出 `ArrayBuffer`
→ 转 base64 → 一次 IPC 交出去 → 宿主校验 + 落盘 + 返回**去重之后**的最终相对路径 →
前端把它按"相对当前笔记"的写法插进文档。

**为什么是字节，而不是"前端把磁盘路径给宿主，让宿主自己 `fs::copy`"**：

- WebView 里拿到的 `File` 只有字节，**没有可用的本地路径** —— 这是浏览器的安全模型，
  不是实现偷懒；
- 更要紧的是**反向的代价**：一条"给我一个路径、我复制它"的命令，等价于"让渲染进程读取任意文件
  并写进 Vault"。这与 ADR-0007 花整篇文档避免的事完全同类（当时是 asset 作用域被符号链接绕过）。
  宿主在这里必须只认**字节**，路径则完全由"附件目录 + 文件名"拼出来并过 `path_guard`。

代价是 base64 把报文撑大约 4/3，用两道闸门兜住：单张 ≤ 8 MiB、一批 ≤ 32 MiB（+ 一次 ≤ 32 张）。
8 MiB 不是随手定的：它与 `asset_read_base64` 的 `MAX_EMBED_IMAGE_BYTES` 同值 —— 否则会出现
"存得进去、导出时却嵌不进来"的组合。

### 2. 用 HTML5 拖放，不用 Tauri 的窗口级 drop 事件

`tauri.conf.json` 里 `dragDropEnabled: false`，WebView 因此按标准 HTML5 处理拖放，
`dataTransfer.files` 可用。**刻意不打开它**去换 Tauri 的 `onDragDropEvent`：

| | HTML5（本方案） | Tauri `onDragDropEvent` |
| --- | --- | --- |
| 落点 | 浏览器算好"落在**哪个元素、第几个字符**" | 只给窗口坐标，宿主不知道那是不是编辑器 |
| 与编辑器协作 | `dragover` 一发就能给出反馈、`drop` 直接拿到插入位置 | 前端要自己把窗口坐标换算成编辑器坐标，还要处理"拖到侧栏/状态栏" |
| 与既有文件树拖拽 | 同一套事件模型（`features/vault` 的拖拽整理已经这么做） | 两套并存的拖放语义 |

顺带的一个硬性要求：`dragover` 必须 `preventDefault`，否则浏览器**根本不会派发 `drop`**
（HTML5 拖放的规范行为）。所以扩展里对"带文件"的 `dragover` 返回 `true` 吃掉它，
而对编辑器内部的文本拖动返回 `false`，把那部分留给 CodeMirror。

### 3. 与 CodeMirror 默认粘贴的协作方式：`EditorView.domEventHandlers`

CodeMirror 6 的 DOM 事件分发是：**插件提供的处理器排在它内置的处理器之前**，
并且"第一个返回 `true` 的处理器吃掉事件（`preventDefault`）、后面的不再执行"。于是规则只有一条：

- **带文件**的 `paste` / `drop` → 返回 `true`（我们接管；即使里面不是图片也接管并**明确报错**，
  因为让它落到 CodeMirror 的兜底路径上会把文件的字节当文本插进文档）；
- **其余**（纯文本粘贴、编辑器内部文本拖动）→ 返回 `false`，行为与加这个功能之前**逐字一致**。

这就是"为什么不自己在 `contentDOM` 上 `addEventListener`"：那样两个处理器会**同时**跑，
一次粘贴被处理两遍。这条规则有专门的测试（`tests/editor-attachments.test.tsx` 里
"粘贴文本不触发附件链路"那一条）。

### 4. 命名与去重规则（纯函数，可单测）

放在 `domain/attachments.ts`（无 React、无 IPC、不碰文件系统），Mock 适配器复用**同一份**实现：

| 输入 | 结果 | 为什么 |
| --- | --- | --- |
| `屏幕截图 2025-01-01.png` + `image/png` | 原样保留 | 用户认得出这是什么 |
| `image.png` / `blob` / 空名 / 无扩展名 | `粘贴图片 2025-01-01 123456.png` | 连续粘三张会互相去重成 `image 1.png`，猜不出内容 |
| `a:b?c.png` | `a-b-c.png` | Windows 非法字符换成 `-`（不删除：删掉会让两个名字撞在一起） |
| `con.png`（保留设备名）/ 全是非法字符的名字 | 换成时间戳名 | 与其造 `con-附件.png` 这种谁都不认识的名字，不如统一退路 |
| MIME 与文件名都给不出图片类型 | **拒绝** | 蒙一个扩展名等于给"任意文件写进 Vault"开门 |
| MIME 是 `image/tiff` / `image/heic` | **拒绝** | 是图片但我们既渲染不了也导出不了；按名字落盘会造出"扩展名撒谎"的文件 |

- 扩展名：MIME 优先（`image/png` → `.png`），MIME 缺失/非图片时退到**原文件名**的扩展名；
- 去重：同名追加 ` 1` / ` 2` …，**绝不覆盖**（宿主查磁盘、Mock 查内存表，用同一份
  `uniqueAttachmentName`）；
- 插入的语法是 `![](相对路径)`，相对路径**优先**（笔记被移动后链接仍然有效），
  地址里语法敏感的字符做百分号编码 —— `空格` 尤其重要，CommonMark 的地址遇到空白就结束了，
  不编码的话 `![](屏幕截图 2025-01-01.png)` 只会把 `屏幕截图` 当地址，图片永远显示不出来。

### 5. 只放行图片（而不是"任意文件进附件目录"）

附件目录里放 `.pdf`、`.zip` 并不会让笔记渲染出问题，但这条命令的**能力面**会完全不同：
一个"给名字和字节就写进 Vault"的通道，若不限类型，就是"任意文件写入"的通用原语
（写 `.exe`、写 `autorun.inf`、覆盖别人的 `.dll`）。白名单把它的能力面收窄成
"写一个图片文件"，与 ADR-0011 对 `export_write_html` 只放行 `.html`/`.htm` 是同一种取舍。

白名单常量只有**一份**（`src-tauri/src/assets.rs::ALLOWED_IMAGE_EXTENSIONS`），
渲染授权、导出内嵌、附件写入三处共用；前端 `domain/assets.ts` 的副本必须在测试里逐项对齐。

### 6. 附件目录（设置项）

默认 `附件`，可在设置页改成 `assets` 之类，**留空表示 Vault 根目录**；不存在时自动创建。
它是**跨 Vault 的用户偏好**（值本身是相对目录，换 Vault 后仍然指向"那个 Vault 里的同名目录"），
因此与自动保存延迟、字号一样存进 `mimenote.settings.v1`。

## 理由

- **一条命令而不是三条**（新建目录 / 写文件 / 返回路径）：附件落盘是"要么都成、要么都不成"的一件事。
  宿主先校验**一整批**（扩展名、大小、base64、目标路径与去重），全部通过才开始写 ——
  于是"三张落盘、第四张被拒"的中间态不会出现，前端也不需要为半成功写一套收尾逻辑。
- **权威判定在宿主**：前端的类型/大小检查只是在**弹提示**（更快、更省一次往返），
  真正的闸门在 `attachment_save` 里；两者不一致时以宿主为准（这也是"Mock 必须镜像宿主行为"的原因 ——
  镜像漂移会让 UI 测试假绿）。
- **回传最终路径，而不是让前端猜**：去重规则、附件目录、扩展名都在宿主/领域层各自有一半，
  由宿主在写完之后回传 `relPath`，前端拿到的就是磁盘上的真名。
- **插图是编辑器的一次事务**：`![](路径)` 独占一段、光标落到**下面一行**。
  光标若停在图片那一行，Live Preview 的规则是"光标所在行露出原文"（ADR-0009），
  用户刚粘完看到的是一串 `![](...)` —— "立刻能看到图"这条要求就落空了；一次 `dispatch`
  也意味着 `Ctrl+Z` 一下能把整次插入撤销掉。

## 代价与已知限制

| 代价 / 风险 | 说明与缓解 |
| --- | --- |
| 报文被 base64 撑大约 4/3 | 单张 ≤ 8 MiB、一批 ≤ 32 MiB、≤ 32 张；超限报 `TOO_LARGE`（**不静默跳过**：用户刚粘了一张图，必须知道它没落盘） |
| 一次粘贴要在内存里过一遍字节 | 只在粘贴/拖放的瞬间、且只对 ≤ 8 MiB 的图片；读取与写盘全在 `spawn_blocking` 上（ADR-0003） |
| 二阶段的写入中途失败会留下**孤儿附件** | 校验全过之后才写，但磁盘满/权限仍可能让第 N 张失败；此时返回 `IO`、**不插任何链接**，已落盘的文件不覆盖不破坏，用户可自行删掉 |
| 与 CodeMirror 默认粘贴的耦合 | 依赖"插件处理器先于内置处理器、返回 `true` 即中断"这一实现细节；已用组件测试钉死（文本粘贴仍走默认路径） |
| SVG 也在白名单里 | 与渲染授权同源；它走 `<img>` 渲染（不执行脚本），且本来就能作为笔记附件存在 |
| 不做图片压缩/转码 | 原样落盘：用户的图不该被悄悄重编码。代价是 4K 截图仍然会以原始体积进 Vault |
| 落点只在"主选区" | 多光标时按主光标插入一次（附件落盘是一次动作一个结果；每个光标各插一遍还得手工删） |
| 超长/极深的目录名 | 单段沿用 `path_guard` 的 255 字节上限；前端把主干截到 120 字节，留出去重后缀的余量 |
| 网络图片仍不支持 | `https://…` 是"下载"（我们的离线姿态不做出站请求），行为保持现状：阅读视图里是占位元素 |

## 影响

- 宿主新增 `src-tauri/src/attachments.rs`（唯一一条"写图片"的命令）与
  `error.rs::UNSUPPORTED_MEDIA` 这个新错误码（前端 `src/ipc/types.ts` 必须同步：它只按白名单
  里的码分支，漏镜像就会被归成 `UNKNOWN`）。
- 前端新增 `domain/attachments.ts`（命名/去重/相对路径/Markdown 语法的纯函数）、
  `features/editor/image-input.ts`（粘贴/拖放接线）；`features/editor/cm/setup.ts` 装配
  `imageInputExtensions()`；`state/vault-store.ts` 新增 `registerAttachment()`（文件树**增量**插入
  条目，不重扫目录，见 architecture.md §3.2）。
- `assets.rs` 的白名单与 `base64_encode` 改为 crate 内共享，并补上与编码成对的 `base64_decode`
  —— 图片的扩展名口径与 base64 实现从此各自只有一处。
- 设置页「编辑器」分区新增"附件目录"（`mimenote.settings.v1.attachmentDir`）。
- 测试：宿主侧 24 个单测（白名单、三道上限、重名去重、目录自动创建/自动拒绝、越界与符号链接、
  扩展名白名单逐项接受、base64 编解码往返、原子写不留临时文件、camelCase 契约）；
  前端 57 个（命名/去重/路径纯函数 + Mock 镜像 + 编辑器粘贴/拖放接线）；
  UI 层 E2E 追加一条"粘贴图片 → 编辑器里出现图片、树里出现新附件"。
