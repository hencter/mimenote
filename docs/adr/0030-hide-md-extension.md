# ADR-0030：界面上不写笔记的 `.md` 扩展名（判据只有 `domain/paths.ts` 一份）

- 状态：已采纳
- 日期：修补轮（ADR-0029 的下一项）

## 背景

用户的一条诉求：

> 隐藏 .md 的扩展名

现状是"凡出现必有扩展名"：标签页写着 `设计.md`、标题栏中区写着 `项目/设计.md`、文件树里是
`设计.md`、反链面板、快速切换（`Ctrl+P`）、搜索命中、窗口标题、回收站列表……都是如此。
这些地方回答的都是同一个问题 —— **"这是哪一篇"** —— 而 `.md` 对这个问题没有任何信息量：
这个 Vault 里的笔记**全都是** `.md`，它只在"要去磁盘上找这个文件"时才有用。

难点不是"怎么去掉三个字符"，而是**在哪些地方不能去掉**：去掉之后，用户还能不能找到磁盘上那个文件？
自动化还认不认得出"当前是哪一篇"？

## 决策

### 1. 判据只有一处：`domain/paths.ts` 的 `displayName` / `displayPath`

```ts
displayName('项目/设计.md')      // '设计'
displayPath('项目/设计.md')      // '项目/设计'
displayName('附件/图.png')       // '图.png'   ← 只剥 .md / .markdown
displayPath('归档.md/笔记.md')   // '归档.md/笔记'  ← 目录那一段不动
```

`isMarkdown()` 是既有判据（`.md` / `.markdown`，大小写不敏感），两个新函数都建在它上面 ——
**没有任何调用方自己写 `replace(/\.md$/)`**。`app/actions.ts` 里那处 `replace` 是"从用户输入推
新建笔记的标题"，属于数据加工而不是显示，刻意不动。

### 2. 隐藏的范围：所有"这是哪一篇"的标识显示

标签页、标题栏中区、文件树行名、反向链接与出链的解析路径、快速切换、全文搜索命中、窗口标题、
回收站列表与恢复提示、冲突横幅、拖拽提示、保存提示 —— 一律用 `displayName` / `displayPath`。

### 3. 保留真实扩展名的三处（**这就是这个 ADR 真正的内容**）

1. **外部产物**：单篇导出 HTML、整库静态站点 —— 那是给 Vault 之外的人看的东西，文件名必须真实。
2. **宿主返回的错误消息原文**：`文件不存在：xxx.md` 这类话是宿主在描述磁盘上的一个文件，
   前端不改写别人的话（改写还会让"照着报错去磁盘上找"这条退路失效）。
3. **路径编辑/预览类对话框**：移动对话框的"将移动到：`归档/设计.md`"、重命名输入框 ——
   用户在那里编辑的就是**路径本身**（重命名的初值本来就不带扩展名，因为宿主收的是"标题"）。

### 4. 悬停提示与 `data-*` 一律给真实路径

- `title`：标签页（`项目/设计.md`）、标题栏路径元素、文件树行（`路径 · 大小`）、回收站行
  —— "想看全名"永远有出口；
- **`data-note-path`（新增）/ `data-tab-path` / `data-rel-path`：真实路径**。
  这一条是给自动化的：可见文字不再是身份，两层 E2E 里"当前打开的是哪一篇"的探针
  全部改成读 `data-note-path`（顺带修掉一个隐患 —— 从前的
  `textContent.includes('项目/设计')` 会被 `项目/设计文档` 误命中）。

### 5. 快速切换的**匹配**也跑在显示串上

`NoteIndexEntry` / `RankedNote` 多了一个 `displayPath`：`lowerPath`、`nameStart`、命中的
`indices` 全部相对它计算，渲染时也用它。为什么不是"匹配 `relPath`、渲染 `displayPath`"：
高亮下标会落到被藏起来的那三个字符上，用户搜 `md` 会得到一串指向不存在位置的空 `<mark>`。
图谱的「定位笔记」复用同一套索引（`features/graph/find.ts`），因此同样受益。

## 代价与已知边界

1. **搜索的匹配面变窄了一点**：`Ctrl+P` 里搜 `.md` 不再匹配到任何笔记（从前能匹配全部笔记的
   尾部三个字符）。这是"显示什么就匹配什么"的必然结果，也是我们想要的；
2. **文件树的过滤框仍然按真实文件名匹配**（`domain/tree.ts` 用 `entry.name`）：输入 `设计.md`
   照样能过滤出那一行 —— 匹配面是显示面的**超集**，属于"宁可多匹配，不要漏"的方向；
3. **图谱卡片标题不在此列**：卡片标题来自图谱数据里的 `title`（宿主给的主干名），
   本来就与扩展名无关；如果哪一天卡片开始画完整路径，要按本 ADR 的决定处理（用户本轮选的是
   "全应用显示层"，没有点名图谱卡片）；
4. **`.md` 之外的扩展名一律保留**：`图.png`、`导出.zip` 去掉扩展名就认不出是什么文件了 ——
   `displayName` 只对 `isMarkdown` 生效。
