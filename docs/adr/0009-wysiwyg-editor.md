# ADR-0009：所见即所得编辑（Live Preview），移除"编辑 + 预览"双栏

- 状态：已采纳
- 日期：M3

## 背景

M1 的编辑器是"CodeMirror 源码 + 右侧预览"的双栏形态。它的好处是**预览永远可信**（渲染管线只有一条），
但对真正写笔记的人是持续的干扰：同一份内容占了两块屏幕，视线要在左右之间来回跳；写一句 `**重点**`
看到的还是星号；拖动分隔条决定"写作宽度"本身也不是用户想操心的事。

用户的要求很明确：**所见即所得，并且移除双栏**。

## 决策

### 1. 编辑器本身变成"渲染后的写作面"（Live Preview 语义）

沿用 CodeMirror 6，但用**装饰（Decoration）**把 Markdown 语法在视觉上渲染出来：

- **块级**：标题按级别改字号/字重、引用加左侧竖线、列表符号退让对齐、任务列表渲染成可点的复选框、
  分隔线渲染成线、围栏代码块隐藏 ``` 行并给等宽底色。
- **行内**：`**粗体**`、`*斜体*`、`~~删除线~~`、`` `行内代码` ``、`[文字](地址)`、`[[wikilink]]`
  在**光标不在该范围内**时隐藏标记只留渲染结果；**光标进入（选区与该范围相交）时立刻露出原始标记**。
- **图片**：`![](相对路径)` 与 `![[图.png]]` 在光标不在该行时替换成真正的 `<img>`（走 ADR-0007 的
  逐文件授权链路），光标进入时露出 Markdown 原文。

"光标进入就露原文"这条规则是 Live Preview 能被信任的关键：**文档内容永远是 Markdown 源码**，
所见即所得只是**渲染视图**，用户随时能定位并编辑到任何一个字符。

### 2. 文档始终是纯 Markdown，装饰只是视图

装饰不写回文档、不改 `doc`：所有渲染都是 `DecorationSet`，由 `ViewPlugin` 按**视口**范围计算。
因此：不需要新的存储格式、不引入富文本模型、`note-store` 的"输入路径零 IO"与"整篇替换（`revision`）"
契约不变，Git diff 依然只看到 Markdown。

### 3. 移除双栏：主区域三选一

`ViewMode` 从 `editor | split | preview` 变成：

| 模式 | 含义 |
| --- | --- |
| `edit` | **默认**。所见即所得编辑（本文档的主角） |
| `read` | 只读渲染视图（旧的预览面板，保留：阅读、检查渲染结果、点链接跳转） |
| `graph` | 知识图谱卡片画布（ADR-0010） |

主区域**一次只渲染一个 pane**；分隔条与 `previewRatio` 一并删除。持久化的旧值会迁移
（`editor`/`split` → `edit`，`preview` → `read`）。

## 理由

- **写作空间**：写笔记是"一列文字"的事，屏幕宽度全给这一列。
- **渲染管线不重复**：`domain/markdown.ts`（markdown-it + DOMPurify）仍是"阅读视图"与其它地方（图卡片预览、
  导出）的唯一 HTML 渲染实现；编辑器里的装饰是**另一套**、更轻的实现（只做视觉与交互，不做 HTML 净化），
  两者职责不重叠、互不替代。
- **可回退**：`read` 视图保留，等于保留了"原样看渲染结果"的能力；装饰写错也不会污染文件。

## 代价与风险

| 代价 / 风险 | 说明与缓解 |
| --- | --- |
| 装饰实现比"渲染 HTML"复杂 | 装饰按视口计算（`O(可视行)`），且核心是纯函数、可单测；`read` 视图还在，出问题可临时退回 |
| 隐藏标记可能影响选择/光标 | 隐藏用 `Decoration.replace` + `atomicRanges`，光标进入范围即露出原文，不允许出现"光标卡在看不见的区间里" |
| 两套渲染可能不一致（编辑器看到的 vs 阅读视图） | 装饰只覆盖高频语法；长尾语法（脚注、HTML、复杂表格）不装饰 —— 宁可"原样显示"也不要"渲染得和阅读视图不同" |
| 大文档滚动性能 | 装饰按视口算、不整篇重算；`doc.revision` 变化时才整体重建 |

## 影响

- `features/editor/**` 成为唯一拥有"编辑器渲染"的模块；`features/preview/**` 只服务 `read` 视图。
- 状态栏的视图按钮从"仅编辑 / 分栏 / 仅预览"变成"编辑 / 阅读 / 图谱"，`Ctrl+E` 循环，`Ctrl+G` 直达图谱。
- E2E 的断言随之调整：**默认视图是 `edit`**，凡是要断言 `.mn-preview__body` 的用例必须先切到 `read`
  （用例里有 `showReadView()` 辅助函数），而"编辑器是否真的载入"改用 `.cm-content` 或树选中态判断。
