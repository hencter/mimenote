# ADR-0035：容器切割树（布局模型层）

- 状态：已采纳（**模型层**；UI 接线是后续交付）
- 日期：修补轮（用户描述"容器切割"之后）

## 背景

用户对布局的最终描述：

> 每个模块都应该有标签 + 内容这样子的布局，然后可以随意被拖动到其他区域的容器，拖拽的内容是标签。

在此之前，界面上有**两套互不相干的机制**：

| | 视图模块（文件树 / 链接 / 标签 / 大纲） | 笔记 |
| --- | --- | --- |
| 归属 | ADR-0026 的**三个固定停靠区**（左/右/底）+ 区内一条列表 | `tabs-store` 的**全窗口唯一一条标签栏** |
| 能不能搬 | 能在三个区之间搬（`Alt+1/2/3`） | **不能**，只能切换 |
| 落盘 | `mimenote.ui.v1` 的 `dockLayout` | `mimenote.tabs.v1` |

用户要的是**一套**：模块与笔记都是"标签"，标签拖到别的容器就是搬过去。于是两者合并成
**一棵二叉切割树**。这一步是架构级的（等于同时替换上面那两套模型），所以先只做**模型层**：
把树、不变式、操作与迁移钉死，UI 再往上贴就不会返工。

## 决策

### 1. 模型：二叉切割树

```ts
type TreeLayout =
  | { kind: 'split'; id; axis: 'row' | 'column'; ratio; a: TreeLayout; b: TreeLayout }
  | { kind: 'leaf';  id; items: LayoutItemId[]; active: LayoutItemId | null }
```

- `split`：一刀切成两半。`row` = 左右并排、`column` = 上下相叠；`ratio` 是前半占的比例（拖分隔条改它）；
- `leaf`：**一条标签栏 + 一块内容**（用户那句"每个模块都是标签 + 内容"）；
- 标签两类：视图模块是**裸词**（`tree` / `links` / `tags` / `outline`），笔记带 **`note:` 前缀**
  （避免与模块撞名，且 `notePathOf` 能一眼取回相对路径）。

### 2. 六条不变式（这个模块存在的全部理由）

1. **每个标签全树恰好出现一次** —— 拖过去就是**移过去**。这不是省事：`note-store` 是单文档模型
   （冲突令牌 / 自动保存 / 撤销历史都只有一份），"同一篇笔记同时出现在两个叶子里"要引入多文档模型，
   是另一个量级的工程。用户也明确选了这一条。
2. **空叶塌缩**（父节点被兄弟替换），但**整棵树至少留一个叶子，且它可以为空** ——
   "还没有打开任何笔记"是正常状态（默认布局就是这样），不是需要塌缩掉的畸形。
   *（这条是写测试时修正的：最初写成"叶子不能为空"，默认布局自己就违规了。）*
3. **比例夹在 [0.15, 0.85]** —— 否则一刀就能把一格拖成 0 像素而再也拖不回来。
4. **认不出的标签一律丢弃** —— 版本升级 / 功能下线之后，老配置不能把界面卡死。
5. **整棵树始终合法**；不合法就退回默认布局（降级方向安全）。
6. **`active` 必须是本叶的标签之一**（叶空时为 `null`）—— 它只回答"这一格显示谁"，
   不参与"谁在哪"。

### 3. 操作面（全部纯函数，返回新树）

| 操作 | 语义 |
| --- | --- |
| `moveItem(layout, item, { leafId, edge?, index? })` | 拖标签的本质：`edge` 为空 = 并进那一格（成为它的一个标签）；`left/right` ⇒ 切出 `row` 的兄弟、`top/bottom` ⇒ `column`，被拖的标签独占新叶 |
| `removeItem` | 关掉一个标签；那一格空了就塌缩 |
| `setActive` | 只认本叶的标签（不在本叶就原样不动） |
| `setRatio` / `evenSplit` | 拖分隔条 / 双击均分 |
| `attachItem` | 打开一篇笔记或显示一个视图模块（没有叶子时建默认叶） |
| `normalizeLayout(raw, { isKnownItem })` | 落盘读取：剔未知 ⇒ 塌缩空叶 ⇒ 修 `active` ⇒ 夹紧比例（顺序刻意如此，反过来会留下被改过比例的残骸）；深度上限 32；整棵不可用则退回默认 |

### 4. 与 ADR-0026 的关系：那是这个模型的**退化特例**

`fromDockLayout(dock, notes)` 给出迁移：左区 → 主叶左侧、右区 → 右侧、底区 → 下侧；
**同一区里的多块模块各占一个叶子**（竖着平分）—— 它们今天就是"平分该区高度"，
而新模型里一个叶子只有一个标签，因此用嵌套 `split` 表达，视觉上仍然 ≈ 平分。

### 5. 测试：六条不变式各一条 + 500 步随机操作

`tests/tree-layout.test.ts`（17 条）：判据（两类标签不撞名）、默认布局、迁移（含"空区不产生节点"、
"没有笔记时空主叶塌缩"）、移动（中心 / 边缘 / 自己那一格 / 非法落点）、移除后塌缩、`setActive` 边界、
比例夹紧、规范化的四种畸形输入、深度上限。

最后一条是**固定种子的 xorshift32 随机操作序列**（500 步，与力场同一条确定性纪律）：
移动 / 移除 / 切换 / 调比例 / 挂新模块混着来，每一步都验六条不变式。树模型最容易死在
"某个操作路径忘了塌缩空叶或忘了去重"上，而那种 bug 靠手写用例很难穷尽。

## 代价与已知边界

1. **UI 还没接**：拖拽落点提示、每叶一条标签栏、分隔条、键盘等价物（`Alt+方向键` 那套）
   都还是后续交付 —— 本 ADR 只到模型层。用户目前看到的仍是"全窗口唯一一条标签栏住在标题栏中区"
   （ADR-0034）与 ADR-0026 的三区停靠。
2. **迁移期两套落盘格式并存**：`mimenote.ui.v1` 的 `dockLayout` 与 `mimenote.tabs.v1` 还在用；
   接线时要"读旧 → 转树 → 只写树"，并且**旧键要保留一轮**（回滚时还能读回来）。
3. **模型不判"标签还存不存在"**：删掉的笔记、关掉的视图模块由上层对账（`isKnownItem` 钩子）。
   模型只保证结构合法 —— 这条分界让它可以被纯函数测试。
4. **极端拖动会改用户意图**：比例夹紧意味着"拖到 0"实际落在 0.15，拖回来时起点不是 0。
   这是刻意的（否则那一格再也点不到），但要知道。
5. **同一篇笔记不能左右对照**：不变式 1 的直接后果。要支持就得先做多文档模型。
6. **`note:` 前缀占用了标签命名空间**：将来若出现"名字以 `note:` 开头的视图模块"会撞名
   （模块名单是内部常量，可控；但加模块时要看一眼这条）。

## 后续修订：迁移与对账（接线的逻辑面）

模型层之后先落了**接线的逻辑面**（`features/layout/layout-sync.ts`，纯函数 + 15 条用例），
因为"读旧格式 → 转树"与"树 ↔ 权威列表对账"这两件事的判据完全能脱离 React 与 localStorage 来钉住，
而落盘与渲染接线风险最大、留给下一批。

- `migrateLayout(raw, { dock, notes, modules })`：已有树 → 规范化；只有旧的 `dockLayout` → 迁移；
  都没有 → 默认布局。迁移完**再过一遍对账**（旧格式里可能压根没写过某个模块）。
- `reconcileLayout(layout, { notes, modules, moduleHome })`：树管"**谁在哪**"、权威列表管"**谁存在**"。
  新打开的笔记挂到主叶末尾、关掉的从树上摘掉（那一格空了就塌缩）、四个模块**永远在树上**。
  **幂等**（连线每帧都可能调到它），并且用户拖过的位置不会被"打开一篇笔记"重置。
- **隐藏 ≠ 移除**（旧语义必须保住）：面板可见性仍归各面板开关，隐藏时那一格在画面上收缩，
  但树里什么都不变 ⇒ 再打开就回原位。所以对账**不会**因为"模块被隐藏"而移除任何模块。

### 这一批的用例抓出的两个真 bug（都写进代码注释了）

1. **切一刀时新节点的 id 会撞**：原先用 `${目标叶}~b` 生成，而切完之后目标叶**仍在树上**
   （它只是多了个兄弟），所以同一个叶被切第二次就造出两个同名叶 —— 对账时连挂四个模块，
   树上出现四个 `main~b`，`findLeaf` / 落盘对位 / React key 全部错位。改为
   `uniqueId()`（在树上找没被用过的名字，`~b`、`~b-2`、`~b-3`…）。
2. **`attachItem` 的默认落点取的是"DFS 第一个叶"**：模块挂上去之后第一个叶是"文件树那一格"，
   于是新打开的笔记会被挂**进文件树**里。改成优先主叶（`main`），没有才退到第一个叶。

### 顺带修正的轴向（与旧模型的几何对齐）

旧模型里"同一侧多块模块**平分该侧高度**"（左/右区上下叠），底区则是左右排。迁移必须照抄这个几何：

```text
row[ column[左带…], column[ row[ main, 右带… ], 底带… ] ]
```

一处**知道的差异**：旧模型里同一区的模块各自占满该区宽度、上下平分，而新模型里每个模块是一个
独立叶子，中间多了可拖的分隔条 —— 观感接近，但可以分别调比例（这正是"容器切割"要的）。
