# ADR-0022：Obsidian 风格 callout（`> [!note] 标题`）

- 状态：已采纳
- 日期：M3 之后

## 背景

需求是"增加类似 Obsidian 的 callout 语法渲染 md"。Obsidian 从 1.0 起把 callout 收进核心语法：
在**引用块的首行**放一个 `[!type]` 标记，后面可以跟标题，类型后面可以跟折叠符：

```
> [!note] 标题（可省略）
> 正文，**行内语法照常**。
> > 嵌套引用
```

这条语法在本应用里有**五个**渲染面，一个都不能漏（否则用户会发现"同一篇笔记在编辑器里
和阅读视图里长得不一样"）：阅读视图、所见即所得（Live Preview）、单篇导出、整库静态站点、
以及知识图谱的节点卡片（ADR-0021 里节点画的就是完整 Markdown 预览）。

## 决策

### 1. 判据只有一份：`domain/callouts.ts` 的 `parseCallout`

它只回答一个纯问题：**"给定引用块首行的内容，它是不是 callout 起始行？是哪种、标题是什么？"**
五个渲染面各自用自己手上的令牌/文本问同一个函数。

覆盖 Obsidian 核心的 13 种类型（`note/abstract/info/todo/tip/success/question/warning/failure/
danger/bug/example/quote`）与常用别名（`hint/important/caution/error/fail/done/faq/summary/tldr/…`），
大小写不敏感。

判据刻意"窄"：必须 `[!` 开头、`]` 紧跟类型 —— 否则 `> [note] 不是 callout` 这种写法会被误判，
而用户在引用里写方括号是很常见的。

**未知类型不当错误**：按 `note` 的样式渲染，但**保留用户写的类型名**作为默认标题
（`[!摘录]` 显示"摘录"）。这样他至少能看出"系统不认识这个词"，而不是被静默改成 `note`。

### 2. 静态渲染靠改写令牌的标签，不自己拼 HTML

阅读视图 / 单篇导出 / 静态站点走同一条管线（ADR-0002），实现是一个 markdown-it 核心规则
（`markdown-core.ts` 的 `mn_callout`）：找到引用块的 `blockquote_open`，判定它是 callout 后：

- 把 `<blockquote>` 改成 `<div class="mn-callout mn-callout--<type>">`（开闭令牌都要改）；
- 把标记那一段（`paragraph_open` + `inline`）改成标题栏 `<div class="mn-callout__title">`，
  内容是"图标字形 + 标题 + 折叠角标"；
- 正文部分原样留在里面。

**为什么不自己拼 HTML**：引用块内部可能有一整个子文档（列表、代码块、表格、嵌套引用），
自己拼就等于把 markdown-it 已经算好的块级结构再实现一遍 —— 那是"两处渲染必定漂移"的经典开局。

一处真实的坑：CommonMark 里 `> [!note] 标题` 与 `> 正文` 是**同一个段落**（软换行，不是新段落），
所以首个 `inline` 令牌的内容是 `"[!note] 标题\n正文"`。标题与正文的分界因此只能在
`parseCallout` 里按**第一个换行**切；正文再用 `md.parseInline` 重新排成标记栏之后的段落
（行内的粗体/链接/`[[双链]]` 都要照常走一遍）。

### 3. 所见即所得用装饰层，折叠在这里是**真的**

编辑器里的字符就是文件里的字符（ADR-0009），所以 callout 只能做成展示层：

- `[!note]`（含折叠符）在光标不在该行时被一个图标 widget 替换（字形 + 类型名 + 折叠角标）；
- **标题保持文档里的真文字**（只加粗上色），于是"编辑器的 DOM 文本 == 文档源码"这条前提在这处也成立；
  只有标题为空时才由 widget 补出类型名（补的是一份推断，不是用户写的字）；
- 光标进入标记行 ⇒ 整行露原文（与其它语法同一条纪律）；
- **`[!note]-` 的正文行真的收起**（逐行挂零高的类名），光标进入这一块就展开；
- 点图标把 `-` ↔ `+` **写回文档**（走既有保存流水线，与任务复选框同一条路径）。

**为什么静态渲染里不真的折叠**：阅读视图与导出件是"读"的地方。读者看不到被收起的内容只会
以为那篇笔记里没有这段文字 —— 折叠的语义是"编辑时默认收起"。所以静态渲染里折叠符只是一个
低调的角标（`.mn-callout__fold`），说明"作者写了它"。

**为什么收起要逐行而不是一个跨行的替换装饰**：ViewPlugin **不允许**替换装饰跨换行
（CodeMirror 会直接抛 "Decorations that replace line breaks may not be specified via plugins"）。
用逐行零高类名（既有 `mn-md-collapsed-line` 的同一手法），DOM 文本仍然等于源码。

### 4. 强调色只有一份表，而且不给下游留谜题

类型 → 颜色定义在 `styles/app.css`：

```css
.mn-callout--note { --mn-callout-accent: var(--mn-callout-note, #448aff); }
```

这些规则**只声明 `--mn-callout-accent`，别的属性一概没有**。于是：

- 阅读视图与导出件直接用它；
- 所见即所得把 `mn-callout--<type>` 这个类名挂到编辑器行上（`calloutLineClass`），
  行内的一切（左边框、图标、标题）读同一个变量 —— 编辑器主题里**不必**再抄一遍 13 种颜色；
- canvas（图谱卡片）走 `canvas/probe.ts`：**探针元素**挂上 `mn-callout--<type>` 再问
  `--mn-callout-accent`。为什么不能直接问 `--mn-callout-note`：那个名字没有任何规则声明过，
  它只出现在 `var()` 的**兜底位置**上，`getComputedStyle` 读不到兜底值。

**被否掉的替代**：把 13 种颜色抄进主题 JSON（那会让色表变成两处，而"阅读视图是蓝色、
画布上是绿色"这类差异没有任何测试能提前发现），或者在画笔里写死色值（更糟）。

### 5. 未知类型要留下痕迹：`mn-callout--unknown`

类型被规范化进类名之后（`[!摘录]` 与 `[!note]` 的类名逐字相同），标记原文已经被换成标题栏 HTML，
"用户写的是不是系统认识的类型"在渲染流里**不可判定**。图谱那张卡片想如实说出这件事，
就只能靠上游多写一个类名：

```html
<div class="mn-callout mn-callout--note mn-callout--unknown">
```

它不影响观感（没有样式挂在它上面），但让下游不必用启发式去猜 —— "标题看起来像类型名"
这种猜测会把 `> [!note] 我的笔记` 误判成未知类型，比少一个诊断字段糟得多。

### 6. 嵌套的归属：`> > [!tip]` 属于**内层**

两层引用读的是同一行，判据若不分层，同一段会被改两次（外层先把 `[!tip]` 换成标题栏 HTML，
内层再解析就只能读到 HTML），结果是"两层引用变成两层 callout"。
所以核心规则在引用块内**先遇到嵌套的 `blockquote_open` 就退出**：标记属于内层，外层保持普通引用。

canvas 那边跟同一条语义：一行上只能有一条左边框，显示的是**最内层**的那个框。

顺带修掉一个既有缺陷：多行引用的续行 `>` 长在 `Paragraph` 里（`> 甲\n> 乙` 是同一个段落），
原先只隐藏了首行的 `>`，第二行一直挂着原文的 `>` 且没有竖线类名。现在按节点行范围算深度、
递归找标记但**不进内层引用**（那属于内层自己那一次遍历）。

## 后果

- **正面**：五处渲染一致且判据唯一；未知类型、别名、折叠符、嵌套都有明确行为；
  色表只有一份；`[!note]` 被 lezer 当成链接（`Link` 节点）这件事被替换装饰接管，
  不会同时出现"链接可点"与"图标可点"两个行为。
- **负面 / 已知限制**：
  1. 静态渲染里 `-`/`+` 不收起（只是角标），只有编辑器里真的折叠 —— 刻意的两侧差异；
  2. 折叠在编辑器里靠"零高行"实现：正文里如果有块级 widget（图片、表格），零高压不住它 ——
     但收起时那些行**不产出任何装饰**（`Build.collapsed`），所以不会出现半截 widget；
  3. 懒续行（`> [!note] 标题` 换行后不写 `>`）在编辑器里不属于"带 `>` 的行"，
     收起时不会连它一起收：这是"按行判读"的边界，写在这里免得后人当成 bug；
  4. 图标用**字形**（`✎ ★ ☑ ‼ …`）而不是 SVG：canvas 与导出件用同一个字形，
     代价是它依赖字体（选了常见字体里都有的符号，且不用 emoji）。

## 后续修订（修补轮）：两个视图的框要长得一样

用户报了两件事，都是"同一段 Markdown 在所见即所得与阅读视图里不一样"：

1. **多个 callout 递进嵌套**：`domain/markdown-core.ts` 的核心规则找"本块的闭合标签"时用的是
   `tokens.findLastIndex(同层 blockquote_close)` —— 那是整个 token 流里**最后一个**同层闭合。
   一层里有多个引用块时，第一个 callout 认领了最后一个的闭合标签，自己的 `</blockquote>`
   留着不改 ⇒ 那个 `<div class="mn-callout">` 永远不闭合，浏览器把后面的一切都塞进它里面。
   改成**从标记段往后**扫第一个同层闭合（CommonMark 的引用块正确嵌套，第一个同层闭合必然是本块的）。
   回归用例判在**结构**上：字符串层会被净化器的容错解析"修好"，看不出真实嵌套。

2. **编辑器里没有边距**：阅读视图那张框是块（`padding: 6px 14px 2px` + 标题 `margin: 4px 0`
   + 末块 `margin-bottom: 8px`），而编辑器里一行就是一个 `.cm-line`，**垂直 margin 会折叠出去**
   （theme.ts 表格那段已经踩过），所以"框的内边距 + 标题的上下留白"只能由**首行/末行的 padding**
   承担：左右 14px、顶 6+4=10px、底 2+8=10px（原来是 10 / 3 / 3）。
   连带修掉一个同源形态问题：**收起时框的底边应该是标记行** —— 收起用的是零高行
   （`font-size: 0`），行元素还在、padding 照样参与布局，圆角与下内边距挂在看不见的行上，
   收起的提示框底下会多出一条空白。现在收起（以及"只有标记行"的光杆标题）走新的位置档
   `only`（同一行同时带 `--first` 与 `--last`，CSS 里一边管顶一边管底，不需要新样式）。

**判据的落法**：内边距的"统一"不是两边各抄一串数字，而是**加法关系** ——
`tests/live-preview-callout.test.ts` 直接从 `app.css` 里读出那三个数，断言编辑器的三处 padding
等于它们的和；UI E2E 再在真实浏览器里量"框边缘 → 框内图标"的距离。

**两处已知的小偏差**（刻意的，写在 E2E 的注释里）：编辑器左侧多约 4px —— `> ` 的 `>` 被隐藏后
**留下一个空格**（0.25em），而阅读视图里整个标记被标题栏取代；上下各差约半个行距 ——
编辑器的行盒比文字本身高。两者都不是内边距的差，要去掉得改"引用标记的隐藏方式"。
