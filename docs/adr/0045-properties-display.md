# ADR-0045：frontmatter 属性展示（Obsidian 式，只读一期）

- 状态：已采纳（一期已交付：展示；编辑是下一批）
- 日期：UI 走查轮（v0.3.0 之后）
- 相关：ADR-0006（标签/frontmatter）、ADR-0042（设计哲学）、ADR-0044（时间挂钩字段）

## 背景

frontmatter 一直只活在标签面板的属性区（朴素 `dl`），阅读视图直接跳过它。
Obsidian 把属性放在笔记顶部（类型图标 + 键 + 类型化值），用户要求对齐。

## 决策

### 1. 一份展示组件两处共用（`components/PropertiesTable.tsx`）

标签面板属性区与阅读视图正文顶部用同一份：类型 → 图标的判据
（键名优先：date/datetime/tags/created/updated，其次值形状）与值渲染
（标签 pills 只读、bool 符号、空值灰显）只有这一份。CSS 同文件
（`properties.css`，只读 `--mn-*`）。

### 2. 阅读视图的数据走现成的 `note_tags`，但先本地判块

新增 IPC 命令是最贵的选项，这里不需要：`note_tags` 本来就回保序字段。
但无 frontmatter 的笔记占大多数，为它们多打一次 IPC 是纯浪费 ——
先用纯函数 `frontmatterRegion` 判块存在（零 IPC），有块才请求；
竞态丢弃与链接那一路同理。拿不到就当没有（正文照常显示，不弹错）。

### 3. 本批只读

值不可点、不编辑：改属性需要新的写命令（`note_set_tags` 只管标签），
那是下一批（届时 Base UI 的日期/下拉/开关输入框正好用上，见 ADR-0042）。
`created` / `updated` 时间挂钩字段在表里正常显示（时钟图标）。

## 代价与已知边界

1. 每打开一篇**有块**的笔记多一次 `note_tags`（小 JSON，与 `note_links` 同量级）；
   无块的零成本；
2. 正文顶部的块与标签面板的块是两份请求（各管各的竞态），不共享缓存 ——
   共享会把两个组件的刷新时序绑在一起，省一次 IPC 不值；
3. 导出件/静态站点**不带**属性块（它们渲染的是正文 HTML，frontmatter 本来就被跳过；
   要带得另起一块，与"导出件内容 = 正文"的契约有关，留待下一批一起定）。
