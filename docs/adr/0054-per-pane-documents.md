# ADR-0054：每格一个文档（多文档仓库）+ 属性区每格都有 + 三处细节

- 状态：已采纳（已交付）
- 日期：v0.3.0 之后（用户需求，原话三句："分栏里每个栏目都可以编辑"、
  "属性面板的显示和隐藏是鼠标悬浮过去才出现，功能面板隐藏需要功能面板进行"、
  "图标没对齐！细节问题"）
- 相关：ADR-0004（唯一写路径）、ADR-0016（外部改动）、ADR-0035（容器切割树）、
  ADR-0045 / ADR-0048（属性展示 / 属性编辑）、ADR-0049（一格一个编辑器）

## 背景

用户截图里的症状很具体：分栏下**左边那格的笔记属性区在，右边那格的整个消失**。

它是三件事叠出来的：

1. `note-store` 是**单文档**模型（全局只有一份 `doc`），于是非当前那格只能挂只读编辑器
   （ADR-0049"一格可写、其余可读"）；
2. `FrontmatterEditor` 的渲染被 `relPath === activePath` 门住 —— 只有"当前文档那一格"有它；
3. 编辑器里 frontmatter 默认**折叠成装饰**（ADR-0048 的 `metadata-fold`），而"唤出它"的入口
   （`笔记属性 ⌃/⌄`、`编辑源码`）只长在那个面板里。

三者叠加的结果不是"右边那格不能编辑属性"，而是**右边那格的 frontmatter 既看不见也点不出来**。

用户的诉求因此不是"把门打开"那么小：要每格都能编辑，就必须让每篇文档各有自己的正文、
脏标记、冲突态与版本令牌 —— 也就是把"当前文档"升级成"文档仓库"。

## 决策

### 1. `note-store` 从"当前文档"改成"文档仓库"，旧 API 一字不改

```ts
docs: Record<relPath, NoteDoc>   // 每篇：正文 + format + (mtime,size) 令牌 + dirty/status/conflict/…
activePath: string | null        // "当前文档" = 大纲 / 标签面板 / 状态栏 / 导出 / 图谱焦点认的那一篇
doc / dirty / status / conflict / …   // ← 仍是 state 字段，但永远是 docs[activePath] 的**派生镜像**
```

镜像字段保留的意义：那 30 多个消费方（状态栏、大纲、标签面板、导出、图谱、窗口关闭守卫、
`hasUnsavedChanges`）**一行都不用改**，而分栏里每一格用自己的 `docOf(relPath)` /
`setTextFor` / `saveNowFor` / `resolveConflictFor`。

所有写入走**唯一**的 `commit()`；它的返回三态必须分清楚：

| 返回 | 含义 |
| --- | --- |
| 路径 | 当前文档换成它 |
| `null` | **清空**当前文档（关闭这一篇 / 整仓清空） |
| `undefined` | 不动（改的是别的篇） |

⚠️ 早先写成 `mutate(...) ?? activePath`，`null` 被当成"没给值"而保留旧路径 ——
后果是**"关闭当前文档"根本关不掉**（`doc` 还在）。这是本轮唯一一个"静默错"级别的坑，
`line-jump` / `app-shell` 里"没有打开任何笔记"的断言当场抓住。

### 2. 写流水线按篇，但**全局单飞**

每篇自己的防抖定时器（`autosaveTimers`）与读取取消令牌（`readTokens`）；
写入仍然**全局串行**（宿主只有一把写锁，排队还顺带免掉"两篇同时保存抢锁"的假冲突）。
`flushAutosave()`（窗口失焦）与 `hasUnsavedChanges()`（关窗拦截）覆盖**所有**篇 ——
分栏之后"同时脏两篇"是常态，漏一篇就是丢一份内容。

打开一篇**已经在仓库里**的笔记（别的格子开着它）**不重读**：重读会把那一格里还没落盘的
编辑吃掉。磁盘上真的变了由 ADR-0016 那条外部改动对账负责，而现在它是**逐篇**跑的
（从前只看当前那一篇；别格里的正文会停在旧版本上，而且看起来完全正常）。

### 3. 每一格：一个编辑器、一份文档、一个属性面板

- `MarkdownEditor` 绑定 `notePath`，正文整篇替换按**这一篇**的 `revision`；
- 这一篇读到之前先只读（否则读回来的整篇替换会把刚打的字冲掉），读到之后**始终可写**；
- 属性面板去掉 `activePath` 那道门：**每格都有**；
- 属性面板的 `seed`（这一版 frontmatter）由 `MarkdownEditor` 在"正文已就位"之后算好传进来。
  顺带修掉一个真 bug：从**没有 frontmatter 的笔记**切回有 frontmatter 的笔记时，
  面板停在折叠态（挂载瞬间读到的还是上一篇的文本；真实 Edge 探针实测 `collapsedOnReturn = true`）。

### 4. 每格自己的笔记路径进 CodeMirror facet

`notePathFacet`（`cm/note-path.ts`）由 `MarkdownEditor` 提供、换笔记时用 `Compartment` 重配置。
读的一侧统一走 `notePathOf(view)`（facet 空时**退回** `note-store` 的当前文档 —— 既有单测直接
`createEditorExtensions`，那条路的行为一个字节都没变）。三个消费方：

- Live Preview 的图片解析（相对**这一篇**的目录）；
- `[[` 补全的候选排序（"与本篇同目录优先"）；
- **粘贴 / 拖入附件**：落盘之后要按**这一篇**算相对路径写链接。右栏粘贴用左栏的路径算，
  会得到"文件存对了、链接指错地方"这种看起来很正常的结果。

### 5. 出链按路径缓存，未知时**不猜**

`links-store` 新增 `outboundByPath` + `ensureOutbound()`。非当前那格的 `[[链接]]` 必须按
**自己那一篇**的出链判断"解析得到 / 悬空"：共用当前文档那一份会让有效链接被判成悬空，
点一下就去新建一篇**早就存在**的笔记。

出链还没取到时**不猜**：装饰层可以暂时画成悬空（不值得闪一下），但点击会被原样吃掉
（`ensureOutbound` 先取回来），绝不凭"未知"去创建。

### 6. 脏 / 冲突标记按篇，冲突横幅一条一条来

`dirtyPaths` / `conflictPaths` 两条**引用稳定**的路径清单（集合没变就不换新数组）：
标签条按它订阅，于是"右边那格脏了"有 ●，而按键不会让标签条重渲染。
关标签的未保存确认也按**这一篇**问（从前只问当前那篇 —— 关掉别格里的脏标签会静默丢内容）。

冲突横幅改为"当前文档优先，否则第一篇冲突的"，并写明是哪一篇。不做多条堆叠：
横幅在窗口顶部，堆两条会把正文挤走，而冲突是要用户**停下来**处理的事。

### 7. 两格的元素形状必须一致（激活一格不再重建编辑器）

从前"当前文档那一格"渲染 `<MainViews/>`、非当前那格渲染内联的 `<section>` ——
React 按位置 + 类型复用子树，两种类型意味着**点一下非当前那格把它变成当前**就会
卸载重建整棵子树：CodeMirror 实例没了（光标、滚动、撤销历史一起丢），
属性面板的展开态也回到默认（用户的动作"点开属性面板"当场被撤销）。

现在两条分支都渲染 `<section class="mn-pane mn-pane--editor"><MarkdownEditor notePath=…/></section>`，
只有"点击是否把它变成当前"不同（`onPointerDownCapture`）。附件查看器（ADR-0032）仍然
优先于编辑器（那是 UI E2E 抓过的回归）。

### 8. 顺带修掉"每次启动把非主叶的笔记搬回主叶"

`installTabsSync` 挂载时的第一次对账发生在 `handleVaultChange` **之前**（`tabs.tabs` 还是 `[]`），
而"空名单"在 `reconcileLayout` 里的含义是"一篇都没开，把树上的笔记标签全剪掉" ——
剪掉之后 `syncFromNote` 再把它们挂回**主叶末尾**。于是"把某篇笔记拖到右边格子里"
每次重启都会回到主叶。

`ui-store` 初始化时早就防了这一手（**刻意不传 `notes`**："还没拿到名单，别动树上的笔记"），
但挂载后的第一次对账漏了。现在 `ReconcileInput.notes` 变成可选：
`undefined` = 名单未知（别动笔记标签），`[]` = 真的一篇都没开（该剪就剪），
判据是 `tabs-store.restoredRoot === 当前 Vault 根`。

### 9. 三处细节

- **类型图标在 24px 槽里居中**：`.mn-select` 的 `justify-content:space-between` 把单个子元素
  顶到行首，而它的内边距本来就不对称（`4px 6px 4px 8px`）——真实 Edge 实测图标整体左偏 2px
  （槽中心 547.64 / 图标中心 545.64）。归零内边距并改居中即可；
- **`single` 的图标从 `dot` 换成 `circleDot`**：`dot` 在 14px 档下墨迹只有 1.17px，
  在"文本 / 标签 / 单选"这一列里看起来像**少了个图标**（用户报的"图标没对齐"里，它是主因）；
- **属性区的显隐控制默认隐形**，鼠标移到属性区（或键盘聚焦）才浮现 —— 与旁边
  「＋ 添加笔记属性」同一套约定。刻意**保留它的盒**而不是 `display:none`：
  收起态下它仍然占位、仍然可以悬停，否则控件既看不见又碰不到，面板再也打不开。

功能面板的隐藏入口放在**面板自己**身上（用户要求）：文件树工具栏与大纲头部各加一个
`×`（与链接面板 / 标签面板头部的关闭按钮同一约定），走 `hideModule` = 与快捷键**同一条开关**，
因此"隐藏 ≠ 移除"（位置留在布局树里）。

## 代价与已知边界

1. **仓库里的文档只在"关标签 / 删除 / 换 Vault"时回收**，不做引用计数：内存随"开过的篇数"
   增长（每篇一个字符串，手指头量级的格子数下可忽略）。不回收是刻意的 —— 宁可多留一份内存，
   也不冒"误删未保存内容"的险；
2. **同一篇笔记仍然不能左右对照编辑**（ADR-0035 不变式 1：一个标签全树只出现一次）。
   那件事要的是"同一篇的两份视图 + 两套光标"，不是多文档仓库能顺带解决的，没有做；
3. **非当前那格的出链是按需取一次并缓存的**：索引在后台重建之后，那一格的"悬空 / 已解析"
   标记要等它被激活或重新取一次才更新（当前文档那一篇不受影响，它走 `refresh`）；
4. `activePath` 的语义仍是"大纲 / 标签面板 / 状态栏 / 导出 / 图谱焦点认的那一篇"；
   点某一格会改它（ADR-0049 定的交互，没变）；
5. **镜像字段与仓库的一致性只靠 `commit()` 这一个写入点**。直接 `useNoteStore.setState({ doc })`
   只在"注入当前文档"这一种旧形态上兜底（下一次写入会把它收进仓库），新代码不要这么写 ——
   绕过去就会让状态栏 / 标签条各说一套；
6. **图标"对齐"的口径是可量的那三条**（`e2e/properties-layout.e2e.test.ts` 钉住）：
   每行图标墨迹中心与它所在 24px 槽中心重合（实测 ≤0.5px）、三行互差 ≤0.5px、
   最小墨迹宽 ≥8px。刻意**没有**做成"所有字形墨迹一样宽" —— 那是字形设计（T 与标签图标
   本来就该有形状差异），不是布局；
7. **每格的编辑器实例仍然是"挂载即创建"**（ADR-0049 的性能纪律）：分栏里格子多了，
   DOM 与测量成本随格子数线性增长；格子数是手指头量级。
