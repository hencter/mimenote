# ADR-0031：VI 落地第一批 —— 设计令牌别名层与默认字号统一 16

- 状态：已采纳
- 日期：修补轮（用户提供 VI 设计文档 v1.0 之后）

## 背景

用户给了一份完整的设计文档（视觉识别 + 界面视觉规范，覆盖阅读与编辑两个主场景），
外加一句更具体的诉求：**"整体默认字体能统一 16 号字体"**。

文档里有两类内容需要分开对待：

- **可以照着落地的**：令牌体系（颜色/字体/圆角/间距全部经 CSS 变量暴露）、焦点环、减少动效、
  阅读最大行宽、字号阶梯、VI 规范名（`--bg-base` / `--text-primary` / `--radius-md` / `--space-4` …）；
- **会与既有决策冲突的**：顶栏 40px / 标签栏 32px / 状态栏 24px（现状 34/36/26）、
  编辑正文用等宽字体、左右/上下分屏、插件自定义 UI —— 这几条要么推翻 ADR-0009（分屏、
  所见即所得的字体口径），要么推翻 ADR-0017/0029 的 34px 契约，本轮**一条都没动**。

## 决策

### 1. 令牌分两层：`--mn-*` 是存储格式，VI 名是公开书写面

- **`--mn-*` 不动**：它是主题 JSON 的键、`REQUIRED_TOKENS` 的清单、用户 CSS 片段里写的东西。
  改名等于把三套内置主题与既有片段全部作废。
- **VI 规范名做别名**（`styles/app.css` 的一段 `:root`）：插件、用户样式、新写的组件都用它，
  语义更清楚。别名必须指向 `--mn-*`、**不许写死颜色**。

主题里**可以**定义、也可以不定义的那些（`--mn-brand-hover`、`--mn-bg-subtle`、
`--mn-font-reading` …）走 **"可选令牌 + 兜底"**：`var(--mn-x, 兜底)`，与 ADR-0028 的
`--mn-edge-out` 同一个套路 —— **不进 `REQUIRED_TOKENS`**，否则所有既有主题会在启动时报缺令牌。

为什么别名能读到主题值：主题是**写在 `<html>` 上的行内变量**（`theme/apply.ts` 的
`root.style.setProperty`），而自定义属性的替换按**元素上的计算值**进行 —— 别名声明在哪个规则里、
写在主题规则之前还是之后都不影响结果。

### 2. 三条判据由单测守住（`tests/design-tokens.test.ts`）

1. 每个 VI 名字都有定义，且指向对应的 `--mn-*`；
2. 别名层里**不许出现**十六进制/rgb 字面量（出现就意味着某个主题换色之后它不跟随）；
3. 指向**可选**令牌的别名**必须**带兜底、且那个可选令牌**不许**混进 `REQUIRED_TOKENS`。

### 3. 默认字号的**真值在设置层**，三档统一 16

这条是踩出来的：改 `styles/app.css` 的 `:root` **没有任何效果** ——
`state/settings-store.ts` 的 `DEFAULT_SETTINGS` 才是真值，由 `features/settings/font-overrides.ts`
写成 `<html>` 的行内变量 **外加一条 `!important` 的作者样式**，压过主题 JSON 与 `:root`。

- `uiFontSize` 13 → **16**、`editorFontSize` 15 → **16**、`readingFontSize` 15 → **16**；
- 主题 JSON 与 `app.css` 里那两份 `--mn-font-size-*` 是**兜底与"令牌清单完整性"**用的，
  同步改成 16，并在三处都写清楚"别在这边改默认值"。

### 4. 字号抬高的连带后果：写死高度的栏要一起量

字号从 13 抬到 16 之后，文字行盒从 19.5px 变成 24px，于是：

- **文件树行高 26 → 30**（`FileTree.tsx` 的 `ROW_HEIGHT`，虚拟列表把它当唯一来源）。
  实测 26px 时上下各只剩 1px，肉眼就是"挤"；
- 其余写死高度的栏（标题栏 34 / 标签栏 36 / 状态栏 26）实测**不裁字**，因此没动
  —— 也就没有推翻 ADR-0017/0029 那条 34px 契约。

新增一条 UI E2E 门禁把这件事钉住：**四栏都不得裁字**（`scrollHeight ≤ clientHeight + 1`）、
**树行上下留白 ≥3px**、以及三档字号（界面/编辑器/阅读）与 `<html>` 上的令牌值都必须是 16px。

### 5. 字体族按"可选皮肤"处理，**没有**采纳 VI 的阅读衬线 / 编辑等宽

VI 2.3 要求阅读正文用 Source Serif / Noto Serif SC、编辑正文用 JetBrains Mono。本轮：

- 新增 `--font-reading` / `--font-editor` 两个**可选**令牌，默认**都回落 UI 字体** ——
  也就是说观感不变；
- 理由：这两个字体在中文字体缺失时（Windows 上很常见）会掉到**宋体**一类难看的回退上，
  而"阅读用衬线"是一次需要有意为之的观感改动；编辑正文改等宽还会与 ADR-0009
  （"正文用界面字体、等宽只给代码"）冲突。
- 想启用只改一处：主题 JSON 里加 `--mn-font-reading`（或用户 CSS 片段里写 `--font-reading`）。

### 6. 间距阶梯先定义、不套用

`--space-1/2/3/4/6/8/12`（4/8/12/16/24/32/48）与 `--font-size-xs…lg` 都已定义并有单测：
把界面上那三十多处 `6px/10px/14px` 的字面量收敛到这一套是**单独一轮**的事 ——
收敛会改观感（间距不再"差 2px 无所谓"），要配逐屏对比，不该混在这一轮里。

## 代价与已知边界

1. **别名层是单向的**：VI 名字能**读**不能**写** —— 在别处写 `--bg-base: red` 不会影响
   `--mn-bg`，界面照旧。主题作者要改值仍然改主题 JSON（或那个可选令牌）。
2. **老用户的字号不会被动变化**：`settings-store` 读的是 localStorage 里存下来的值。
   已经动过设置页的用户要看到"统一 16"，得点设置页「外观」里的**「恢复默认字号」**
   （它按新的三个默认值恢复）—— 这一点在给用户的回复里必须说清楚，否则会变成
   "你改了默认值，我这儿怎么没变"。
3. **界面里仍有一批 10–13px 的硬编码小字**（状态栏 12px、树上的角标 10px、若干提示 11px…）：
   它们是**绝对 px**，不跟着基础字号长。所以"统一 16"目前覆盖的是**基础层**
   （正文、文件树、标签页、标题栏、按钮与输入框），小字要到第 6 条那一轮才收敛。
4. **VI 里的高度与现状仍不一致**：顶栏建议 40px、标签栏 32px、状态栏 24px（现状 34/36/26）——
   本轮没动，因为改高度要同步 E2E 的布局不变式（`主体 = 窗口 − 标题栏 − 标签栏 − 状态栏`）
   与 ADR-0017/0029 里那条 34px 契约。要做的话是一次独立的、可见的改动。
5. **分屏、编辑正文等宽、插件自定义 UI** 三条仍待用户拍板（都会推翻既有 ADR，见"背景"）。
