# ADR-0044：frontmatter 时间挂钩（可选，防同步丢 mtime）

- 状态：已采纳（已交付）
- 日期：v0.2.0 之后（用户需求：同步传递丢元数据时用正文保时间）
- 相关：ADR-0002（Markdown 是唯一事实来源）、ADR-0004（mtime 版本令牌）、
  ADR-0006（frontmatter 改写纪律）、ADR-0008「后续修订」（判定键的漏检窗口）

## 背景

同步盘/拷贝/压缩包传递文件时，文件系统的 `mtime`/`birthtime` 经常被改写或丢掉
（同步客户端重建文件、解压不保留时间、跨文件系统复制只留"复制的那一刻"）。
而 frontmatter 跟着**正文**走 —— 只要内容到了，时间就到了（这正是 ADR-0002
"Markdown 是唯一事实来源"的直接推论：时间也是内容的一部分，就该放在内容里）。

## 决策

### 1. 字段与格式：`created` / `updated`，UTC RFC 3339（`Z` 后缀）

- 小写短名（Obsidian 风格），与用户已有的 `date`/`datetime` 等业务字段不重名、不抢占；
- 用 UTC 而不用本地时区：同步的意义就是"与机器位置无关"，`+08:00` 在夏令时/
  跨时区机器之间互传时会引入本不存在的歧义；
- 日期换算零依赖（Howard Hinnant 算法，`mn-core::timestamps`），workspace 里没有
  chrono，为两个字段加一个时间库不值。

### 2. 语义：`created` 只写一次，`updated` 每次保存刷新

- `created`：新建时写入，此后**永不覆盖**（出生只有一个真相；用户手改也不动）；
- `updated`：每次保存刷新为现在 —— 保存本身就是一次修改，写 `now` 永远是真话
  （即使用户手改了这一行，本次保存也确实发生过）；
- 没有 frontmatter 的旧笔记**不擅自建块**（保存时只改已有的块；新文件才带块）：
  给干净文件戴帽子是惊吓，不是功能；
- `created` 缺失时回填，fallback 链：文件 birthtime → 文件 mtime → 现在
  （平台越不支持出生时间越往后退；一旦落盘就不再变）。

### 3. 落点：宿主写路径（与标签同一纪律）

- 同一把写锁、同一个原子写、同一套 mtime 令牌冲突语义：挂钩跑在"令牌校验之后、
  写盘之前"（冲突时不写盘，也就不碰时间；挂钩只改两行，判据不受影响）；
- 改写走 `mn-core::frontmatter::set_scalar_field`（最小 diff：原键拼写、注释、
  CRLF/BOM 不动；`Block` 数组形态永不动）；
- 索引用**盖章后的文本**更新（否则索引里永远缺那两行）；
- `tag_rename` / `tag_move` 等批量改写路径**不挂钩**：它们改的是别人的文件，
  顺手给几百篇 bump `updated` 是噪音；
- 开关是**可选的，默认关**（设置页 Vault 分区）：打开后每次保存都改正文头两行，
  默认替用户做等于在 diff 里制造"没动过的地方变了"。

### 4. 回写不同步编辑器内存（刻意）

盖章后的文本与编辑器内存差两行，但**不**往编辑器里 dispatch 对齐：
autosave 路径上整篇替换会污染撤销历史、冒险光标映射，且预览本来就不渲染
frontmatter。漂移只差时间戳行，重开/重载即收敛（`tag_set_tags` 那种面板触发的
单次写才做"一次往返对齐"，见 `note_set_tags` 的 `text` 出参）。

## 代价与已知边界

1. 同一秒内连存两次：`updated` 秒级精度下文本完全相同，仍然会正常写盘一次
   （mtime 毫秒部分照样推进；不为此加"文本相同则跳过"的特例 —— 保存语义保持简单）；
2. 跨时区阅读：UTC 时间人类要换算一眼才看懂；这是为机器准确性付的代价，
   人类可读的业务时间请继续用本地时区的自定义字段；
3. 导出件/静态站点原样带出这两行（它们是正文的一部分，不特殊处理）。
