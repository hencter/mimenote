# ADR-0010：知识图谱是"卡片画布"，不是力导向小圆点图

- 状态：已采纳
- 日期：M3

## 背景

知识图谱在 Obsidian 里的形态是：一堆**小圆点 + 力导向布局**，悬浮或按住 `Ctrl` 才显示笔记名，
想看清内容只能点开。用户的评价很直接：

> "知识图谱之前在 Obsidian 里面只有一个点需要按住 Ctrl 才能预览，我希望在这里可以直接变成一个个卡片进行预览，
> 关联的内容比如 wiki 链接在笔记卡片上的连接点使用虚线，出卡片使用实线进行预览，
> 文件夹可以用来展开集合，不需要人为处理，这个知识图谱相当于一个画布，类似 Canvas 但是和整个 Vault 是有映射的"

也就是三个明确诉求：**卡片化（信息直接可见）**、**方向可见（入链/出链一眼可分）**、**结构自动成组（不用手工摆）**。

## 决策

### 1. 节点 = 卡片，信息直接写在卡面上

每篇笔记是一张**固定尺寸的卡片**：标题（frontmatter `title` 优先，否则文件名主干）、相对路径、
标签（最多 3 个）、出入度（`→3 ←2`）。不需要悬停、不需要按住修饰键。

### 2. 布局：按文件夹自动成组，零手工

- 数据里每个节点自带 `folder`（POSIX 目录，Vault 根为 `''`）；画布按它把卡片装进**文件夹容器**
  （嵌套：`A/B` 在 `A` 里面），容器随内容自动增长。
- 顶层散笔记放进"（Vault 根）"容器。
- **默认全部展开**；点容器可收起（收起后它变成一张紧凑的"文件夹卡片"，显示名字与笔记数）。
- 卡片可以拖（位置按 `Vault 根 + relPath` 持久化），并提供"重新自动排布"清掉手工位置。
- **刻意不用力导向**：力导向的布局每次打开都不一样、节点一多就"糊成一团"，而且**没法表达"文件夹"**
  这种本来就存在的层次结构。整齐的装箱布局牺牲一点"有机感"，换来可预测、可复现、能容纳容器。

### 3. 连线：入链虚线、出链实线

- 用一层 `<svg>` 画在卡片下面，线从**卡片边缘的连接点**出发并带箭头（从中心穿卡片会挡住文字）。
- **选中/预览某张卡片时**：指向它的边（**入链**）画**虚线**，它指出去的边（**出链**）画**实线**；
  其它边淡化。
- 没有选中时所有边是统一的淡色细线 + 箭头；悬空链接（目标笔记还不存在）画虚线 + 端点小圆，
  表示"这里的链接指向一个还不存在的东西"。

这个区分不是装饰：**虚线 = "谁在引用我"（上下文），实线 = "我引用了谁"（延伸）**，
两种阅读意图不同，用线型分开后不需要点击就能同时看到。

### 4. 卡片可直接预览内容

单击卡片即在画布内滑出预览面板（正文用 `domain/markdown.ts` 渲染，与阅读视图同一套净化管线）；
双击则打开这篇笔记进编辑器。刻意不做"按住 Ctrl 才预览"：那是为了在小圆点图上挤出信息而做的妥协，
在卡片画布上没有存在的必要。

### 5. 数据来自索引，一次拿全图

新增只读 IPC `graph_data`：节点 = 索引收录的笔记（含 `folder`/`tags`/度数），边 = 索引里的链接
（`resolved` 与悬空都保留，按 `(from, to)` 去重并带 `count`）。**不做文件 IO**，与链接/标签/搜索索引同一份数据。
节点数超过 **8000** 时只返回度数最高的一部分并把 `truncated` 置为 true（画布给出提示）——
"与整个 Vault 有映射"意味着要给大 Vault 一个可控的上限，而不是让一次 IPC 的报文无限增长
（画布本身按视口裁剪，1 万节点的布局 46 ms，拖不动浏览器不是问题；报文体积才是）。

## 理由

- **信息密度**：卡片画布在"看清结构"这件事上比小圆点图强一个量级 —— 标题、路径、标签、度数都在卡面上。
- **不制造新的事实来源**：画布只是索引的另一种视图，链接关系仍由 `mn-index` 唯一裁定（ADR-0002）。
- **可预测**：自动成组 + 可持久化的手工位置，让"每次打开都长得不一样"这件事不会发生。

## 代价与已知限制

| 项 | 说明与缓解 |
| --- | --- |
| 力导向的"集群感"没有 | 有意为之（见决策 2）；文件夹容器本身就是最强的集群信号 |
| 交叉连线在容器密集时会重叠 | 线只在"两端都可渲染"时绘制；选中卡片时高亮其入/出链、淡化其它，读图时以选中卡片为中心 |
| 上层布局不做"连线最短化" | 复杂布局会带来不可预测的跳动；当前优先"稳" |
| 8000 节点上限 | 超过即 `truncated`，按度数取最相关的一部分；真正需要看全图时按文件夹收起分组。上限的修订记录见本节下方 —— 初版是 3000，几千篇的真实 Vault 会被截断掉四分之一，与"与整个 Vault 有映射"的目标冲突，于是抬到 8000（报文 ≈ 1.0 MB） |
| 拖拽位置是本地偏好 | 存 localStorage（跨 Vault 用根路径做键），不进 Vault 目录 —— 保持笔记文件夹干净 |

## 影响

- `features/graph/**` 拥有画布（布局纯函数 + 组件 + 自己的 CSS）；`state/graph-store.ts` 存视图状态与手工位置。
- 主区域新增第三种视图 `graph`（ADR-0009 的三模式之一），`Ctrl+G` 直达。
- `docs/architecture.md` §3.1 增加 `graph_data` 一行；`README` 的快捷键与手工验收清单同步。
