# ADR-0024：任务列表（`- [ ]` / `- [x]`）的渲染与**唯一一份判据**

- 状态：已采纳
- 日期：M3 之后（ADR-0023 的下一轮）

## 背景

用户报告：

> Markdown 的渲染没有 `- [ ]` 和 `- [x]` 待办列表的渲染样式。

事实核对下来是这样的：`markdown-it` 的默认 preset **没有** GFM 的 task-list 插件（我们也没装），
所以 `- [ ] 待办` 在 token 流里就是一个普通列表项，正文是纯文本 `[ ] 待办` —— 阅读视图老老实实
把它画成"项目符号 + 字面的方括号"，导出件与静态站点同病。

而**图谱画布**早就自己识别了这件事（`features/graph/canvas/blocks.ts` 里的 `stripTaskMarker`），
文件里还留着一条注释：

> 将来阅读视图接上插件时，两边的判据应当合并成一份（那时这里的正则就该删掉，改成读 token 属性）。

于是同一篇笔记在五处渲染面上有三种表现：所见即所得里是复选框（`TaskCheckboxWidget`）、
画布上是 `☑/☐`、阅读视图与导出件里是字面的方括号。这一轮把这条缝补上。

## 决策

### 1. 判据只有一份：`domain/task-list.ts`

`parseTaskMarker(text)` 是唯一判据（纯函数、零依赖、可在 Worker 里跑），口径是 GFM：

- 标记必须出现在**段落最前面**：`- [x] 完成` 认，`- **[x]** 手写` 与 `- [[链接]] [x]` 不认
  （用户手写的方括号是有含义的文字）；
- `[ ]` 是未完成，`[x]` / `[X]` 是已完成；
- 三态：`undefined` = **不是任务项**（而不是"未完成"）—— 这个区分决定了画布上画不画勾选框。

配套的还有 token 内部属性的读写两端（`TASK_CHECKED_ATTR` / `taskCheckedValue` /
`taskCheckedFromAttr`）：解析层写、消费层读，中间不许再判一次。

### 2. 结论写在 token 上，消费方只读

`markdown-core.ts` 加一条核心规则 `mn_task_list`：认出任务项 → 把标记从文字里删掉 → 把结论写进
`list_item_open` 的属性。四类消费方各自读它，**都不自己再判**：

| 消费方 | 怎么用 |
| --- | --- |
| 阅读视图（HTML） | `list_item_open` 渲染规则写状态类名 + 追加复选框 |
| 导出件 / 应用内打印 / 静态站点 | 同一条渲染管线（`buildExportCss → contentRules` 里镜像同一组样式） |
| 图谱画布 | `blocks.ts` 读属性 → `checked` → 画笔把 `☐/☑` 画在项目符号那一栏 |
| 所见即所得编辑器 | 另有语法树（lezer 的 `Task` 节点），见第 5 条的已知差异 |

内部属性在渲染前被摘掉，**不会**进 HTML（有专门用例钉住）。

### 3. 复选框是 `<input type="checkbox" disabled>`，不是 `<span>`

- 静态站点是"一个目录"（ADR-0019）：某个页面被单独拷走、`site.css` 没跟上时，`<span>` 画法会
  整个消失，而原生控件照样由浏览器画出来；
- `role="checkbox"` 挂在一个不可聚焦的 `span` 上是 ARIA 滥用，原生 `input` 的"复选框 / 已选中 /
  已禁用"是现成的、屏幕阅读器认得的约定；
- `disabled` 是语义的一部分：**阅读视图与导出件是只读的**，勾选要改文档，而改文档的唯一通道是
  编辑器（ADR-0009 的同一条边界）。

代价是净化白名单必须开一个口子：`FORBID_TAGS` 里的 `input` 单独放开。白名单只能表达"允许
`input`"，表达不了"只允许禁用状态的 checkbox"，所以那条不变量由 DOMPurify 的
`afterSanitizeAttributes` 钩子在同一次遍历里**强制**（凡不是 `type=checkbox` 且带 `disabled`
的 `input` 当场移除），边界有测试：`<input type="text">`、未禁用的 checkbox、`type=radio disabled`
全部被剥掉。

### 4. 样式：复选框推进"项目符号那一栏"，已完成只变暗

尺子就是同一份文件里的 `ul, ol { padding-left: 1.6em }`，所以复选框用
`margin: 0 0.6em 0 -1.6em` 负边距推进去，任务项的文字与同级普通条目**左边界对齐**。
已完成项只把文字变暗，**不用** `text-decoration: line-through`：删除线在 Markdown 里已经是
`~~删除~~` 的含义，两种意思不能共用一个记号。打印时 `accent-color` 强制成黑色（屏幕上的强调色
打到纸上会发灰）。

### 5. 已知差异（如实记账）

- **`- [x]`（标记后面什么都没有）**：lezer 的任务规则是 `/^\[[ xX]\][ \t]/`，要求标记后面还有
  空格或制表符，所以这种写法在**编辑器**里不是任务项，在阅读视图里是（我们选了 GFM 口径：
  空待办再回头勾是真实用法，而反向不一致会让待办在导出件里消失）。要对齐得在编辑器那侧加一条
  行内规则，本轮没做。
- **`renderPlainText`（字数统计与摘要用）**不剥标记：它不走渲染管线，为它另立一份判据与第 1 条
  的目标相悖。用户可见影响只有"统计里多几个字符"。
- 阅读视图的复选框**不可点击**（理由见第 3 条）：要勾选请去编辑器。

## 后果

- **正面**：同一篇笔记在阅读视图、导出件、应用内打印、静态站点、图谱卡片五处**长得一样**；
  判据从三份收敛成一份，`blocks.ts` 里那条"将来合并"的注释被兑现（本地正则删掉了）。
- **负面**：净化白名单多了一个口子（由钩子兜住边界）；编辑器与阅读视图在"空任务项"这一种写法上
  仍不一致（见第 5 条）。

## 被否掉的替代

| 方案 | 为什么否掉 |
| --- | --- |
| 引 `markdown-it-task-lists` 插件 | 判据会变成第四份（插件一份、画布一份、编辑器一份、白名单一份）；插件还会把 `<input>` 塞进 HTML，净化那关照样要自己兜 |
| 阅读视图也画 `<span aria-checked>` | 见第 3 条：拷贝走的单页会失去复选框，且是不可聚焦元素上的 ARIA 滥用 |
| 让复选框可点击改文档 | 阅读视图 / 导出件是只读的（ADR-0009 的边界）；改文档要走编辑器的变更通道（`updateListener → note-store.setText`） |
| 让画布继续用自己的正则 | 正是这条注释要消除的东西：同一篇笔记在画布上认、阅读视图不认，最难查 |
