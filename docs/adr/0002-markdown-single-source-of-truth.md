# ADR-0002：Markdown 文件是唯一事实来源，索引可重建

- 状态：已采纳
- 日期：M1

## 背景

笔记应用的数据可以放在"应用私有数据库"里，也可以放在"用户可读的文件"里。这决定可移植性、Git 可用性、以及崩溃后的数据可恢复性。

## 决策

1. Vault 是**普通文件夹**，笔记是**纯 Markdown 文件**，人类可读、可被 Git 管理、可被任何编辑器打开。
2. 应用侧所有派生数据（索引、缓存、图谱、反链、标签）都是**可从文件重建的缓存**，删除后最多损失性能，不损失内容。
3. 应用自身状态（主题、快捷键、布局、片段开关）写入 Vault 内 `.mimenote/`（配置）或系统标准配置目录（跨 Vault 的偏好）。

## 理由

- 数据主权：用户换工具时零迁移成本。
- Git 友好：文本 diff 天然可读，可以按笔记粒度做历史。
- 容错：索引损坏时删除重建即可，不需要"数据库修复"。
- 迁移简单：Obsidian 的 Vault 可直接打开（M2 起支持其 frontmatter/wikilink 语法）。

## 代价与缓解

| 代价 | 缓解 |
| --- | --- |
| 索引不是权威，需处理外部变更（用户在 VSCode 改文件） | 保存前 mtime 校验（ADR-0004）；M2 引入 `notify` 文件监听做增量重索引 |
| 纯文本无内建富结构，复杂查询需自行解析 | 解析结果全部落 SQLite，查询只打数据库 |
| 大量小文件的 IO 开销 | 迭代式扫描 + 忽略规则 + 只索引变更文件（M2） |

## 影响

- 写入必须"看起来像人类写的"：保留 BOM、保留原始换行风格（`\r\n` / `\n`）、不重排内容。
- 不允许把用户数据放进不可见的二进制 blob。
- `.mimenote/` 必须可被安全忽略（提供 `.gitignore` 建议片段，M2 文档化）。
