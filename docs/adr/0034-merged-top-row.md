# ADR-0034：顶行合并 —— 标题栏、文件标签与窗口按钮同一行

- 状态：已采纳
- 日期：修补轮（用户定稿外壳布局）

## 背景

用户在很短的时间里给了三条外壳要求：

1. **文件标签要在内容叶子的容器上方**（与"容器切割"那套模型一致：每个叶子 = 标签条 + 内容）；
2. **最大化/最小化回到顶部标题栏，但与文件标签栏同一行**；
3. **左上角的菜单按钮 → 左侧文件导航叶子的右下角**（已单独交付）。

其中第 2 条有个必须先说清的副作用：**标签栏在没有打开的笔记时整行不渲染**
（`TabBar` 返回 `null`）。窗口按钮要是和它同一行，"没开任何笔记"时最小化/关闭按钮就会
跟着消失 —— 那是不能接受的。所以在动手前先问了一句，用户选了**合并成一行**：

> 顶行 = 品牌/库名 · 文件标签 · 统计/导出 · 窗口按钮

## 决策

### 1. 一行装下窗口的全部顶级信息

`.mn-titlebar` 的三区（ADR-0029 定的网格 `1fr / 2fr / 1fr`）保持不动，**中区的内容从
"当前路径"换成"文件标签栏"**，右区不变（统计 + 导出 + 三个窗口按钮）：

```
┌─────────────────────────── 36px ───────────────────────────┐
│ ✦ Mimenote  库名 │ [标签][标签][标签] │ 统计 · 导出 │ — □ ✕ │
└────────────────────────────────────────────────────────────┘
```

- 这一行**永远在**（它就是标题栏），所以窗口按钮不会因为"没有标签"而消失；
- 标签条自己横向滚动（`.mn-titlebar__center { overflow: hidden }`），标签再多也挤不掉右侧的按钮；
- **行高 34 → 36**：标签要 36（16px 文字 + 上下留白）才不挤；窗口按钮靠
  `align-self: stretch` 跟着这一行，自动变高。

### 2. "我在看什么"挪到状态栏

中区让给了标签，当前笔记/附件的路径落到**状态栏最左边那一格**（`displayPath` +
`title` + `data-main-path`）。理由：标签上已经写着文件名，悬停标签能看全路径；
而状态栏那一条本来就放得下完整相对路径，而且它在三种视图与附件查看器里**都**在。
"保存中…"也跟着挪过去（原来挂在路径旁边）。

### 3. 一个必须一起处理的坑：`deep` 拖动区 vs 标签

标题栏整条是拖动区，且带 `deep`（会往下传）。Tauri 跳过 `button/input/a`，
但**标签是 `role="tab"` 的 `div`，它跳过不了** —— 不声明例外的话，按住标签会被当成
**拖窗口**（点击切换、以后的拖动重排全会失灵）。

因此标签条自己声明 `data-tauri-drag-region="false"`（与窗口按钮同一个手法），
拖动区仍然覆盖：标题栏的空白、左区的品牌之间、以及标签条里那一截
`.mn-tabs__filler`（`flex: 1 1 0`，只在标签没占满时吸收剩余宽度）。

### 4. 布局不变式跟着改：**不要再减一次标签栏**

UI E2E 里那条契约算式原来是

```
主体 = 窗口 − 标题栏 − 标签栏 − 状态栏
```

标签条现在**住在标题栏里面**，再减一次就把它的高度扣了两遍（36px 全部转成了"主体少 36px"），
7 处断言同时红。改成

```
主体 = 窗口 − 标题栏 − 状态栏
```

`readLayout` 仍然保留 `tabs` 的矩形（标签栏那条用例要用它量"有没有被这一行包住"），
但**不再参与求和**。

### 5. 测试与文档里跟着改的选择器

| 旧 | 新 | 说明 |
| --- | --- | --- |
| `.mn-app > .mn-tabs` | `.mn-titlebar .mn-tabs` | 标签条不再挂在 `.mn-app` 上 |
| `.mn-titlebar__path` / `__path-text` | `.mn-statusbar [data-main-path]` | 路径搬到了状态栏 |
| `barHeight === 34` | `=== 36` | 行高为了标签抬了 2px |
| `.mn-titlebar__center { justify-content: center }` | `flex-start` | 中区从"居中放路径"变成"左对齐放标签" |

`tests/tabs.test.tsx` 里那个复刻 `App.tsx` 结构的 `Shell` 测试壳也跟着改了 ——
它本来就是"接线说明书"，结构一变它必须跟着变，否则它测的就不是真实应用的结构。

## 代价与已知边界

1. **一行比两行挤**：品牌/库名与统计/导出被压进同一条 36px 的带子里，窄窗口下它们先走省略号
   （既有规则没变）；标签条拿到的是窗口的中间 50%，标签很多时靠横向滚动；
2. **窗口按钮在第二行之下就没了**：它们现在在最顶行的右端，符合"跟标签同一行"的要求，
   但这与"窗口按钮必须贴屏幕右上角"的 Windows 习惯在**最大化状态**下略有出入
   （在无边框窗口里，标题栏那一行就是顶部，所以这一点实际上不成立）；
3. **路径的可发现性下降**：它从窗口顶部正中挪到状态栏左侧 —— 标签上已有文件名，
   但"完整相对路径"要低头看状态栏。用户明确选了这一条；
4. **应用层 E2E 需要重建后再跑**：外壳结构变了，而那一层跑的是打包进 release 二进制的旧前端。
   本轮跑的是 UI 层（真实 Chromium + dist）与单测，应用层的 34 条要在 `tauri build --no-bundle`
   之后重跑（下半轮补）。

## 后续修订（ADR-0038）

本文档的"顶行 = 品牌/库名 · 文件标签 · 统计/导出 · 窗口按钮"只存活到 ADR-0035 之后：
容器切割树把标签送进各自的格子，中区回归纯拖动区；Issue #8 又指出"统计/导出与窗口按钮
共撑一条独立标题栏"本身就是要取消的东西。ADR-0038 因此做了三件事：

1. **独立标题栏退役**：`.mn-titlebar` 与 `.mn-titlebar__*` 整组删除，内容从窗口最顶边开始；
2. **业务控件下移**：统计/库名 → 状态栏，导出 → 文件树工具栏；
3. **窗口按钮住进右上叶标签条右端**：标签条自带 `data-tauri-drag-region="deep"`
   （Tauri 自动跳过 `role=tab` / `button`，标签点击不受影响），标签滚动区与按钮槽分成两段，
   槽不随标签滚动 —— 本文档"标签条自己声明 `data-tauri-drag-region="false"`"的做法因此不再需要。

布局契约式随之再改一次：

```
主体 = 窗口 − 状态栏
```

上面"代价与已知边界"里的第 1、2 条随标题栏一起作废；第 3 条（路径在状态栏）与第 4 条
（应用层 E2E 要重建）仍然有效。
