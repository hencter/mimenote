# ADR-0037：打开笔记默认**顶掉**当前那条标签（中间那格是"你正在看的那一篇"）

- 状态：已采纳（已交付）
- 日期：修补轮（ADR-0036 连线搬进 canvas 之后）
- 相关：ADR-0035（容器切割树：每格一条标签条）、ADR-0034（标签进格子之前的那一轮）

## 背景

用户在看完 ADR-0035 的渲染器换树之后提了一句：

> 中间的这个叶保持在中间，默认的新文件替换中的叶标签
> 即已打开的直接被新的替换掉

在此之前，"打开一篇笔记"的语义是**追加**：点文件树里的第三篇，中间那格的标签条上就多出第三条。
用户要的是**替换**：中间那格始终是"你正在看的那一篇"，新打开的那篇顶掉它。

同一句话里的"中间的这个叶保持在中间"当面确认过，指的是**默认落点**（新笔记默认落在中间那一格 ——
现在的实现就是这样），不是"把主叶的位置锁死"，也不是"主叶找不到时要修 bug"。

## 决策

### 1. 默认替换，位置排在末尾

真正的动作在 `state/tabs-store.ts` 的 `syncFromNote`（标签列表的**唯一**写入者）里：
新笔记进编辑器时，列表里那条"刚才正在看"的标签被它顶掉（`insertReplacingTab`）。

新标签排在**末尾**，而不是接着被顶掉那条的位置：标签条上的顺序由**布局**决定
（`attachItem` 把新标签挂在那一格标签序列的末尾），而 `Ctrl+1..9` / `Ctrl+Tab` / 「关闭其他」
都按 `tabs` 的顺序算 —— 列表顺序若在这里另搞一套，"第 2 个标签"在键盘与鼠标下会变成两个东西。

### 2. 已经在标签里的笔记 = 切换，不替换

打开一篇**已经打开**的笔记是"切过去"，列表与位置都不动（原来就是这个语义，这里只是明确写下来）。

### 3. "在新标签里打开"必须有路走：文件树 `Ctrl/⌘ + 点击` 与中键

多标签的机制没有被删掉（`Ctrl+Tab` / `Ctrl+1..9` / 「关闭其他」/ 把标签拖到另一格 / 左右并排），
只是默认不再堆积。于是要有一个显式入口，否则那些机制全成了摆设：

- 文件树行上 `Ctrl/⌘ + 点击`（`onClick` 里读 `ctrlKey || metaKey`）；
- 文件树行上**中键**（`onAuxClick`，并挡掉中键自带的自动滚动）。

两条路都走 `app/actions.openNoteInNewTab`，它在 `tabs-store` 里举起一面**一次性旗子**
（`openNextNoteInNewTab`），这一次打开就退回"追加"。为什么是旗子而不是参数：列表的唯一写入者
`syncFromNote` 是 note-store 的**订阅回调**，没有参数可传 —— 同一种做法在这个文件里已经有先例
（`switchingVault`）。旗子在 `syncFromNote` 的每条分支上都会被消费掉，所以"打开失败"也不会把它
留给下一次打开。

### 4. 只有**冲突态**才拦：确认框说的必须是真话

`app/actions.openNote` 在切换之前问一次（仅当那篇正处在**冲突态**）：

> 「A」在磁盘上被外部改动过，还没决定怎么处理；打开「B」会放弃这次改动，当前显示的那条标签也会被它顶掉。

拒绝 = 这次打开整体取消（标签与文档都不动）—— 与「关闭标签」被拒绝时的结果一致。

**"有未保存的修改"不弹确认**，理由是可验证的：`note-store.open` 的语义是"切走前先落盘"
（`if (current.dirty && current.conflict === null) await saveNow()`），所以普通的未保存内容在切换时
会被保存下来、什么都不丢 —— 在那里弹一个"会丢修改"的确认是**假话**，而且会把确认框训练成噪音
（边打字边点文件树都要弹一次）。冲突态才是**唯一**不落盘的分支（磁盘上的改动必须由用户决定
"覆盖还是重新加载"）。这条由 `tests/tabs.test.tsx` 的两条用例分别钉住（弹 / 不弹）。

### 5. 被顶掉的那条：光标位置照记

替换前在 `openNote` 里对"正要离开的那一篇"记一笔光标/滚动位置（`captureCaretFor`）——
与 `closeTab` 的处理一致。必须在**切换之前**调：切换之后编辑器里已经是新文档，
那时再 capture 记下的是别人的位置（替换发生在订阅回调里，所以这件事只能由动作层来做）。

## 代价与边界

1. **不能再靠"多开几篇"来对照两篇笔记** —— 要对照就走新标签入口（`Ctrl+点击`）或把标签拖到另一格
   （左右并排）；这是用户要的默认，不是能力上的删减。
2. **被顶掉的标签不再留在列表里**，所以"我刚才那篇去哪儿了"要靠"在文件树中定位"或历史记录；
   未保存内容不会丢（见决策 4）。
3. **中键与 `Ctrl/⌘+点击` 是隐式入口**：文件树行上没有提示文字，只有习惯（浏览器就是这么用的）。
   真要更显眼就得在行右键菜单里加一项「在新标签中打开」—— 没有做，记在这里备查。
4. **只在文件树上提供了新标签入口**：快速切换 / 全文搜索 / wikilink / 标签面板打开的都是"替换"。
   它们的语义本来就偏向"跳到那篇"，与"打开新文件"不同。
5. 布局层没有跟着改：`reconcileLayout` 仍然把新笔记挂到主叶末尾、把不在列表里的笔记从树上摘掉 ——
   "替换"只是"先摘掉那条、再挂上新的"的合成结果。

  ⇒ 不弹确认**且那次编辑真的落在盘上**。
