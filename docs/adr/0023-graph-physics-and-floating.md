# ADR-0023：图谱的浮动态、从 wiki link 引出的连线、可调大小的卡片与浮动笔记

- 状态：已采纳
- 日期：M3 之后（ADR-0021 的下一轮）

## 背景

ADR-0021 把图谱做成了"以当前笔记为圆心的关系图 + canvas 卡片"，位置是**环形布局的纯函数**。
用户接着提了四件事：

> 视图需要笔记节点之间有类似 obsidian 关系图谱的连接线张力控制等，并且浮动显示，就像在画布上漂浮一样；
> 然后连接线不是凭空渲染在卡片边缘，需要通过虚线从对应的 wiki link 处到卡片边缘再转为实线；
> 我希望的是每个节点包含完整的笔记预览（已有）**还有可调节大小的卡片**；
> （以及）Obsidian 那种浮动的笔记需要什么前端库？如果没法实现的话能结合 rust 构建一个高性能的那种库吗？

## 决策

### 1. 力导向：环布局给**种子**，力场只负责**松弛**

这是本轮最关键的一条纪律。ADR-0021 的决策 2 说"坐标是数据的纯函数"（空间记忆），
而力导向天生是"每次跑都可能不一样"。两者不是二选一：

- **种子**来自环形布局（`layoutEgo`）：它保证"离中心几跳"一眼可分、且每次打开位置相同；
- **力场**（`features/graph/force.ts`）只在这之上做松弛：向心力把它收拢、斥力让卡片不重叠、
  弹簧力把有链接的两张拉向 `linkDistance`；
- 落定（`settle()`）在给定参数下是**确定性**的：同一份输入 + 同一组参数 ⇒ 逐字节相同的位置。
  实现上靠"自写 xorshift32（`seed` 决定抖动）+ 固定遍历顺序 + 不用 `Math.hypot`"。
- 用户按住某张卡片时（拖动）它变成 `fixed`：不再被移动，但仍然推开别人 —— 这就是"漂浮"的手感。

参数与预设（`force-presets.ts`）：向心力 / 斥力 / 弹簧强度 / **自然长度（张力最直观的那个旋钮）** /
阻尼 / 速度上限 / 只让几跳以内的边参与弹簧 / 强度衰减。五个预设：均衡、紧凑、舒展、漂浮、聚焦。

**代价如实记账**：默认档会把环半径收紧到种子的约三分之二（实测一跳 562 → 377、二跳 1124 → 672）——
"谁在内谁在外"保住了，但"半径 = 布局算出的那个数"不再成立；想尽量保住半径用「舒展」档（实测一跳 493）。

### 2. 连线从正文里那段 wiki link 引出（用户要的那条）

每条边渲染成**两段**（`features/graph/link-edge.ts`）：

1. **卡片内**：从正文里 `[[甲]]` 那段文字的左侧出发，画一段**虚线**到卡片边界（`leadPath`），
   起点还有一个小圆点（"线从哪句话出来的"）；
2. **卡片外**：从边界交点画一条**张力曲线**到目标卡片边界（`spanPath`），带箭头。

三处判断写清楚：

- **怎么把边匹配到某一段文字**：四种写法依次尝试（逐字 → 归一化（trim/去 `.md`/忽略大小写） →
  **整数份重复**（`[[甲]][[甲]]` 会被 blocks 层合并成一个 run）→ `href` 兜底
  （`[[甲|别名]]` 的别名不在 `GraphEdge` 里，只能靠 run 的 `href = data-target`））。
  **绝不用"包含"**：`[[甲虫]]` 不能被 `[[甲]]` 命中（有测试钉住）。
- **找不到就如实降级**：正文没读到、卡片被截断、或者作者写的是 `[文字](路径.md)` ⇒
  `fromLink: false`，退回"从卡片边界出发"，并且在 tooltip 里说明"正文里没找到对应的链接写法"。
  不假装命中。
- **卡片外的曲线用张力参数**：控制点摆在弦的 1/3、2/3 处再沿垂直方向偏移 `tension × 弦长 × 0.25`。
  只做纯垂直偏移会让端点切线垂直于弦（线先横冲再拐）；二次贝塞尔只有一个自由度，
  会把"绷多紧"和"端点切线"绑死。`tension = 0` 时控制点落在弦上 ⇒ 退化成直线且不跳变。

### 3. 卡片尺寸可调：宽度是**真尺寸**，高度是**上限**

- 拖动卡片右下角的把手（画笔画的）改**宽度**；宽度变了换行就变了，所以高度上限会一并重置成"自动"
  （否则用户会觉得"我拉宽了，怎么反而看着更短"）。
- HUD 上给四个高度档（自动 / 短 400 / 中 900 / 长 2000）：卡片高度本来就由内容决定，
  上限只在"这篇太长、我只要看开头"时才有意义 —— 给档位比给连续滑块更容易选中想要的那个量级。
- 尺寸按 **Vault + relPath** 持久化（`mimenote.graph.sizes.v1`）：它是"我怎么看这一篇"的偏好，
  换一个 Vault 还要重调一遍是不能接受的。落盘里的越界/非法值一律夹回来或丢掉（有测试）。

### 4. 浮动笔记：**不引库**，用已有的指针约定自己写

用户问过"需要什么前端库 / 要不要用 Rust 写一个"。结论与理由：

- **不需要库**。这一层要的只有三件事：按住标题栏改 x/y、拖右下角改 w/h、别跑出可视区域。
  自己写就是 `起点 + 位移 + clamp`，而且能和画布既定的约定对齐（`data-mn-graph-nopan`
  表示"这一块不参与画布平移"、`setPointerCapture` 的 `try/catch` 兜住 jsdom）。
  引入 `react-rnd` / `react-draggable` / `floating-ui` 会各带一套事件模型（触摸手势、
  自己的 capture 策略、自动边界、portal），还要额外维护一条供应链（`docs/dependencies.md` 的第一条原则）。
- **不需要 Rust**。力导向在 ≤300 个节点（宿主的 ego 上限）下，单步是 4.5 万对斥力的算术，
  瓶颈在**绘制**（一帧 1.1 ms）而不是数学；真要更快，第一步是把模拟搬进 Web Worker（仍是 TS）。
  Rust 的正确位置是**别的**事情：如果将来要做"脱离主窗口的真浮窗"，走 Tauri 2 的多窗口
  （`WebviewWindow`）—— Rust 负责开窗与传数据，前端复用同一套预览组件。这一轮不做。

浮窗的取舍：**不持久化**（下次打开还挂着一堆不知道从哪来的浮窗，比什么都没有更困惑）；
可多个、点一下置顶（store 里的 `z` 单调递增）；`Esc` 优先关**最上面那个**
（`Esc` 在用户心里的意思是"关掉最上面那层"）；面板里的滚轮不缩放画布。

### 5. 漂浮的刷新率：20fps，而不是 60

位置一变，画布上的卡片与 SVG 层的连线都要重画，而后者是 React 渲染。20fps 下"缓慢漂移"
看起来已经是连续的，代价只有 60fps 的三分之一（`FLOAT_FPS` 常量与注释写明了这一取舍）。
**下一步**（如果真要 60fps）：把连线也搬到 canvas 上 —— 那时"整张图谱都是 canvas"才真正成立
（ADR-0021 刻意留下 SVG 是因为正交折线、箭头、悬空虚影与 `<title>` 都已经在那里实现好了）。

## 后续修订：力度管理面板与**碰撞**（用户："图谱应该有力度管理，笔记之间应该有碰撞！"）

### 1. 碰撞是**约束**，不是第四股力

原来的斥力只是"倾向"：它让卡片**倾向于**分开，但参数一极端（节点多、向心力强、`repelStrength` 调小）
就会出现肉眼可见的叠压。用户要的是"不许叠"这个**几何事实**，所以加的是位置层面的约束
（`collidePass`）：每步积分之后，把每一对相交的矩形沿**最小平移向量**推开（各推一半；
被钉住的节点不动、把整份修正让给对面），跑 `collideIterations` 轮。

被否掉的替代：**只把斥力调大** —— 它永远只是趋势，而且要在大卡片密集处推得开，就得调到
稀疏处像爆炸；**把碰撞做成速度冲量** —— 与阻尼打架，而且用户要的不是动量。

### 2. `COLLIDE_SLOP = 1e-6`：一个实测逼出来的浮点陷阱

只推到"刚好相切"时，任何一次后续修正带来的浮点噪声（≈ eps × 坐标 ≈ 1e-12）都能把这一对
**翻回相交** —— 于是"某一轮什么都没动"（零重叠的证据）永远不可达：`settle()` 会跑满步数上限、
最后留下 3–8 处 1e-9px 级的相交。加一微米的"皮"之后归零，而且落定从 600 步提前到 285 步。

`settle()` 的第三个停止判据因此是**"碰撞求解有一整轮什么都没动"** —— 它同时证明了当前状态零重叠
（那一轮没动过任何节点 ⇒ 没有任何一对相交），比"修正量小于阈值"强得多。

### 3. 实测数字（密集输入：13 张挤在半径 80 的圆上 / 12 张挤在原点 ±15px）

| 输入 | settle | 之后相交对 | 最深重叠 |
| --- | --- | --- | --- |
| 密集（默认力度） | 285 步 | **0** | **0** |
| 密集（`collideStrength: 0`，对照） | 247 步 | 16 | 151.85px（一整个卡片宽级的可见重叠） |
| 密环，1 轮 vs 4 轮（力一直热着） | 6 步 | — | **65.60px → 18.70px** |
| 弹簧持续挤压：`strength` 0 / 0.5 / 1 | 200 步 | — | 320px（完全重合）/ 48px / **0** |

**`collideStrength: 1`（硬约束）⇒ 落定后零重叠**，这条现在是面板上的承诺，也是宿主的
`data-graph-overlaps` 与端到端用例断言的 0。

### 4. 代价与边界（如实记账）

- **「漂浮」档是唯一不能保证零重叠的**：它的力永不降温（`alphaDecay: 0`），弹簧每步挤进来多少、
  软约束就补回去多少。密集合成输入上稳态约 **14.7px**，真实 ego 输入上 **0.07px**（等于没有）。
  要严格零重叠就得放弃"永不冻结"这个卖点，因此这一档在界面上**明说**了这一点。
- **「紧凑」档不再能压到以前那么紧**（一跳 307 → 394）：它过去靠"让卡片叠着"变紧，
  现在这条路被正确地堵死了。要更紧只能改布局层（卡片尺寸/环半径），力场这一层给不了。
- **面板上每一项都要能解释**：滑杆旁边写的是"往两边拧分别会发生什么"（斥力、阻尼、衰减这些词
  对没写过物理模拟的人没有意义），并且**整份参数跨会话保存** —— 用户拧过的滑杆重启后还在。
  关掉碰撞只有 `collideStrength: 0` 一条路（轮数夹在 1..4），不让两个旋钮都能关同一件事。

## 后果

- **正面**：节点会漂浮、有张力可调；连线**从正文里那句话出来**（这是"图谱与笔记是同一份东西"
  最直接的表达）；卡片能调大小；一篇笔记可以拎出来浮在画布上读。
- **负面 / 已知限制**：
  1. 力场会把环收紧（见决策 1 的实测数字），"半径 = 几跳"变成"大致成正比"；
  2. 从文字引出的虚线只在**焦点视图**里有：全库视图的卡片是紧凑卡片（没有正文位置），
     那里仍然从卡片边界出发；
  3. 匹配不到文字时降级成边界出发（`fromLink: false`），tooltip 会说明原因，但用户看不到"为什么"；
  4. `[[甲|A]][[甲|B]]` 相邻且同 href 时会被合并成一个 run，只能给一个锚点；
  5. 自环（笔记链接自己）的引线退化成一个点（`exit === entry`）；
  6. 浮窗不持久化；`Esc` 的语义是"先关浮窗"（焦点在浮窗里时由浮窗自己处理，见 `FloatingNote`）；
  7. 漂浮是 20fps 的"慢漂移"，不是 60fps 的物理动画（见决策 5）。

## 被否掉的替代

| 方案 | 为什么否掉 |
| --- | --- |
| 纯力导向（丢掉环形种子） | 每次打开位置都不同，空间记忆失效（ADR-0021 决策 2 的同一理由） |
| 引库做浮窗（react-rnd / floating-ui / react-draggable） | 三件简单的事换来一套额外的事件模型 + 一条供应链（见决策 4） |
| 用 Rust 写力导向 | 瓶颈在绘制不在数学；先把连线搬到 canvas 或搬进 Worker 才是有效的一步 |
| 连线用"包含"匹配来"尽量命中" | `[[甲虫]]` 会被 `[[甲]]` 命中 —— 宁可降级也不能指错人 |
| 卡片固定高度（而不是上限） | 短笔记会被撑成一堆空白，长笔记会被压扁 |
| 浮窗持久化 | 下次打开还挂着一堆不知道从哪来的浮窗（Obsidian 的 hover editor 同样不保留） |
| 漂浮跑 60fps | 每帧一次 React 渲染（连线在 SVG 层）；20fps 的慢漂移已经连续，代价只有三分之一 |
