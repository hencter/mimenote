# ADR-0047：OKF 原生支持 + Hugo frontmatter 参照 + CLI 起步

- 状态：已采纳（第一批已交付）
- 日期：v0.3.0 之后（用户需求：文档原生 OKF + 本地 SSG CMS + CLI 端开工）
- 相关：ADR-0002（Markdown 唯一事实来源）、ADR-0006（frontmatter 纪律）、
  ADR-0019（静态站点）、ADR-0045（属性展示）

## 背景

Google OKF v0.2（Open Knowledge Format）：目录式 Markdown + YAML frontmatter
知识包，`type` 唯一必填，`index.md` / `log.md` 为保留文件，另有信任/生命周期
家族（`generated` / `verified` / `sources` / `status` / `stale_after`）。
Hugo 的 frontmatter（`title` / `date` / `draft` / `tags` / `slug` / `url` /
`aliases`）是另一份参照：它是 SSG 的事实标准，字段语义经过十年沉淀。

我们的笔记天然接近 OKF（Markdown + YAML），差的是三件事：
嵌套字段读不出来、包级合规没人检查、SSG 只活在应用里。

## 决策

### 1. 解析器加一层映射（`mn-core::frontmatter`，本批）

- 新增 `Map(Vec<FrontmatterField>)` / `MapList(Vec<Vec<FrontmatterField>>)`，
  覆盖行内流式 `{k: v}` 与块内一级映射（含 `- k: v` 续行）；
  再深的结构忽略（文档里写死"一层"，不猜）；
- 首项定形态（块列表）、混排丢纯文本项（病态输入，记录在案）；
- 编辑路径（`set_tags` / 改名 / 标量 upsert）**永不碰**映射形态（原样返回）：
  看不懂的结构不配拥有改写权；
- 标签抽取跳过映射（`tags: {a: b}` 不贡献标签，与 Bool/Null 同等待遇）；
- TS 镜像同步（`map` / `mapList`），属性表结构化渲染（子行 / 分组），
  `check:ipc` 无需改动（联合加法，清单只核对字段名）。

### 2. 合规检查是新模块（`mn-core::okf`，本批），不是索引的附庸

- 纯函数，输入 `(路径, 全文)` 列表：缺块/缺 `type`/空 `type` = Error；
  无链接的 `index.md` = Warning；链接不可达 = Error（近似口径：
  裸名先拼同目录，带 `/` 走全路径后缀，再退主干；外链/锚点/嵌入跳过）；
- 未知 `type` 不是问题（规范原话：消费者必须容忍）；
- `suspendisse`：悬空 wikilink 在本应用日常语义里是"待建概念"，
  在 OKF 里是不合规 —— 检查器定位是**发布前门禁**，不是写作实时标红。

### 3. CLI 端开工（`apps/cli`，二进制 `mimenote-cli`，本批）

- 与桌面应用共用 `mn-core`；首批命令只有 `okf check <vault> [--json]`
  （退出码 0 合规 / 1 有 Error / 2 用法 IO 错误）；
- 二进制名刻意不叫 `mimenote`：`target/debug/mimenote.exe` 是桌面应用的，
  同名会互锁（实测踩过，见提交说明）；
- **红线**：HTML 渲染永不进 CLI（渲染管线只有前端一份，复刻第二份等于
  两个真相）。`export-site` 的 HTML 构建永远走应用内导出；
  CLI 只碰文本层（检查、索引生成这类）。

### 4. Hugo 映射（`draft` 与 `slug` / `url` 已交付；本节的原始结论见文末「后续修订」）

| Hugo | 我们 | 落点 |
| --- | --- | --- |
| `title` / `date` | 已有（属性表展示） | — |
| `draft` | **已交付**（第二批） | 站点导出跳过 `draft: true`（**计划层过滤**，不删文件、不改磁盘）；只认字面 `true`，结果里逐条列出被跳过的路径 |
| `slug` / `url` | **已交付**（第二批） | 允许覆盖本页输出路径（`slug` 留在原目录、`url` 以 `/` 开头时相对输出根）；`..` / 盘符 / UNC / 保留名 / 非法字符一律拒绝覆盖并如实记一条 |
| `aliases` | 无 | 不做（双链解析是文件名口径，别名会引入第二套身份） |
| `tags` / `categories` | `tags` 已有；无 categories | 不做（单标签体系，层级标签已覆盖分类需求） |
| `created_at` / `updated_at`（OKF 风格） | `created` / `updated`（ADR-0044） | 显示层都认（时钟图标）；合规检查不看时间字段（只有 `type` 必填） |

## 代价与后续

1. `index.md` 生成器（`okf index`）是下一批：需要 §6 全文逐条实现，
   本批只读不写；
2. `okf_version` 只认不验（best-effort 原则）；
3. 检查复杂度 O(文件 × 链接)，万篇库约秒级 —— CI 门禁可用，编辑器实时检查不可用。

## 后续修订（第二批：`draft` 与 `slug` / `url` 的实际语义）

上表里"下一批"的两行已经交付。**原始结论保留在上面**（它记录了当时"只定映射、不动实现"的
决定），这里追加实际实现出来的语义与代价 —— 实现过程中的取舍与上表当初的设想有出入的地方，
以本节为准。

### 4.1 判据落在哪里：`apps/desktop/src/domain/site-frontmatter.ts`

- **判据只有一份**（纯函数，可单测）：`parseSiteFrontmatter`（读三个字段）→
  `pagePathForSlug` / `pagePathForUrl`（算路径）→ `buildSiteExportPathPlan`（覆盖 + 撞名 + 草稿
  一次算完）。导出流程、结果提示、索引页**只消费**它的输出，谁也不自己判一遍。
- 为什么在 TS 里另写一小段 frontmatter 解析（而不是走 `mn_core::frontmatter`）：只取三个标量字段，
  区块识别复用 `domain/frontmatter.ts` 的 `frontmatterRegion`（含 BOM、`+++` / `;;;`、未闭合不算），
  而走宿主解析要把 `notes_read_batch` 换成"连属性一起回带"的新批量命令 + 索引侧改动。
  **代价**：只认顶格的 `key: value`；带子键的 `slug:` 块、块数组、`url: |` 一概当没写（退回默认路径）。
- 导出因此**整库读两遍**（一遍预扫定草稿与覆盖、一遍渲染）。代价是 I/O 翻倍，
  换来的是进度分母从一开始就准、草稿的图片一次都不会被收集；不做"边渲染边过滤"是因为那会让
  链接表、反链、索引页都按一个不存在于输出的页面算（幽灵页）。

### 4.2 `slug`：留在原目录

`slug: "abc"` → `笔记/甲.md` 输出为 `笔记/abc.html`（**原目录 + 该文件名主干**）。

- 理由：Hugo 的 `slug` 就是"这一节里的文件名主干"，节由文件在内容目录里的位置决定 ——
  留在原目录才是它的本义。
- 代价：想把它放到站点别处得写 `url`；`slug` 里的 `/` 一律拒绝（那是一个路径，不是主干）。

### 4.3 `url`：Hugo 语义（`/` 开头相对输出根，否则相对本页目录）

- `url: "/docs/a/"` → `docs/a/index.html`（尾随 `/` 按 Hugo 的 pretty URL 换成 `index.html`，
  于是站内相对链接算术不必为"目录型页面"再开一条分支）。
- `url: "a/b"` → `笔记/a/b`（相对本页所在目录，与 Hugo 一致）。
- 代价：`url` 以 `/` 开头时**丢掉"原目录"这一层信息** —— 这一页的地址不再能从源路径推导出来
  （索引页会把它与 `slug` 改名的那些一起列出来）；`url: "/x/"` 还会占掉同目录里本该叫
  `index.html` 的那一页（撞名清单会如实报出，先到者占住）。

### 4.4 安全：任何覆盖都不得逃出输出根

被拒绝（**退回默认路径 + 如实记一条**，绝不静默、也绝不因为拒绝而不导出这一页）：

| 形态 | 例 |
| --- | --- |
| `..` 越界（含根相对里的 `..`） | `../../evil.html`、`/../x.html` |
| 盘符 / UNC / 反斜杠 | `C:/evil.html`、`//host/share`、`..\\evil.html` |
| Windows 保留设备名 | `con.html`、`nul`、`com1` |
| 非法字符与尾部点空格 | `a?b`、`a#b`、`a%20b`、`abc.` |

判定比"文件名不允许的字符"更严：拒绝的代价只是退回默认地址，而放过去的代价是
写盘整批失败、或浏览器按 URL 规则解析出另一个文件（`#` 截断、`%20` 当转义、`?` 变查询串）。

### 4.5 草稿只认严格 `true`

`draft: true` 才跳过；`draft: "false"` / 缺失 / `draft: yes` / `on` / `1` **不跳过**。

- 理由：YAML 1.1 里 `yes` / `on` / `y` 都是布尔真，但"顺手写一行"与"我确定要下架这篇"是两件事。
  误判会让整篇笔记不进导出（站点里凭空少一页、多一条打不开的链接），比多导出一篇草稿严重。
  `draft: "true"`（带引号）照收 —— 它没有任何歧义，而漏判换来的是"作者以为下架了、其实还在站点里"。
- **代价（必须知道）**：指向草稿的链接会变成死链。计划是索引算的（索引不认识 `draft`），
  所以 `href` 照样非空，而目标文件不会写出去 —— 站点里会出现 404。
  这与"悬空链接渲染成不可点文字"不同（那种情况索引已经知道目标不存在）。
  要彻底解决得把 `draft` 下沉到索引层（`mn-index` 的 `SitePage` 带一个"不导出"标记），
  那是下一批的事：本批的边界是"不动 Rust 侧"。
- 草稿与"被拒绝的覆盖"**不进**导出结果的 `skipped`（那是"没能导出"的语义），
  而是单独进 `overrides`：提示与索引页才不会把"按作者要求跳过"说成"出错了"。
