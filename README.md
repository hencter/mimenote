# Mimenote

本地优先、可高度自定义、高性能的 Markdown 知识库桌面应用。

**你的笔记就是普通文件夹里的普通 Markdown 文件** —— 可被 Git 管理、可被任何编辑器打开、随时可以整体搬走。
应用不联网、不遥测、不上传；所有派生数据（未来的索引、图谱）都可以从文件重建。

> 当前状态：**M1 / M1.5 / M2 已交付，M3（体验完善）范围已全部交付**（含拖拽整理文件与跨目录移动的全库链接改写）。
> 范围与后续里程碑见 [`docs/milestones.md`](docs/milestones.md)，架构与决策见 [`docs/architecture.md`](docs/architecture.md)。

## M1 做了什么

| 能力 | 说明 |
| --- | --- |
| 打开 Vault | 系统目录选择框，或命令行 `mimenote.exe <目录>` 直接打开 → Rust 侧迭代式扫描（不跟随符号链接、忽略 `.git`/`node_modules` 等）→ 一次调用返回概要与完整条目表 |
| 文件树 | **虚拟列表**（固定行高 + overscan，10 万条目也只挂载几十行 DOM）、键盘导航（↑↓←→/Enter/Delete）、中文与数字自然排序、子串过滤并自动保留祖先 |
| 编辑器 | CodeMirror 6 + **所见即所得（Live Preview）**：标题/引用/列表/任务复选框/代码块/分隔线/**GFM 表格**/**callout** 在正文里直接渲染，**列表标记也真的渲染出来**（无序画 `•` / `◦` / `▪`，有序画**算出来的序号** —— 源码写 `1. 1. 1.` 就显示 `1. 2. 3.`、`3.` 开头就显示 `3. 4.`，序号右对齐在等宽栏里所以正文左边界齐平；光标进入该行整行露原文），`**粗体**`、`*斜体*`、`` `代码` ``、`[文字](链接)`、`[[双链]]` 在光标不在该处时隐藏标记、光标进入即露出原文；图片 `![](…)` 与 `![[…]]` 直接显示；**表格**按分隔行决定每列对齐、列多时横向滚动而不是把正文挤宽、单元格里的行内语法（粗体/代码/链接/`[[双链]]`/图片）照常渲染，光标一进表格就**整块**露出原文（列宽是全表共享的，"只露一行"会让竖线对不上、视线反复重定位），表格在引用块/列表里或超过 200 行时原样显示；**callout**（`> [!note] 标题`，ADR-0022）的标记换成图标、标题保持可编辑的真文字、`[!note]-` 的正文**真的收起**（光标进入即展开）、点图标把 `-` ↔ `+` 写回文档（走同一条保存流水线）；**输入路径零 IO、零全量重渲染**（装饰按视口计算，见 ADR-0009） |
| 链接补全 | 敲下 `[[` 自动弹出当前 Vault 的笔记候选（`![[` 之后连图片等附件一起列），边打字边过滤、`↑↓` 选择、`Enter`/`Tab` 确认、`Esc` 取消、`Ctrl+Space` 手动唤出；排序与宿主消歧规则一致（**同名多篇都能选到**，冲突时自动写成相对当前笔记的路径），代码块/行内代码/frontmatter 里不弹，弹层关闭时 Tab/Enter/Esc 的既有语义一字不变 |
| 表格格式化 | `Ctrl+Alt+F`（或命令面板「格式化表格」）把光标所在的 Markdown 表格对齐：按**显示宽度**算列宽（中文算两列，否则永远差一点）、保留 `:---`/`:---:`/`---:` 三种对齐、单元格里的转义竖线 `\|` 不当分隔符；只改空白与竖线位置，**内容一个字符都不动**，已经是整齐的表格再按一次不会产生任何 diff |
| 视图 | 主区域三选一：**编辑（所见即所得）/ 阅读（渲染后）/ 知识图谱**；"编辑 + 预览"双栏已移除（ADR-0009） |
| 保存 | 防抖自动保存（默认 600ms）+ Ctrl+S；写入串行化；**原子替换**（同目录临时文件 → fsync → rename）；状态栏显示每次写入实测耗时 |
| 冲突保护 | `mtime` 版本令牌；文件被外部修改时**拒绝静默覆盖**，弹出横幅让用户选「覆盖 / 重新加载」 |
| 外部改动自动同步 | 在应用之外改 Vault（资源管理器 / 别的编辑器 / **同步盘把别的设备的改动落下来**）→ 几秒内**文件树与索引自己跟上**，不再需要手动重扫（ADR-0016）：宿主用 `notify` 监听 Vault 根（Windows 上是 `ReadDirectoryChangesW`），把事件**去抖合并**（静默期 **500ms**、风暴硬上限 **2s**）后重扫条目表，并在**后台**增量重建索引（不阻塞输入、可取消）。**当前打开的笔记**：没有未保存修改 → 自动重新加载并提示"已在磁盘上更新，已重新加载"；**有** → 进**既有的冲突横幅**（绝不自动覆盖、也绝不静默丢弃）。**应用自己写的文件不会被当成外部改动**（判定的是"磁盘 vs 条目表"，而保存/新建/改名/搬迁都会立刻更新条目表），并且 `.mimenote/` 内部（缓存库每轮构建都在写）、原子写的 `.mimenote-*.tmp`、扫描器本来就跳过的路径（`.git`/`node_modules`/隐藏项）一律忽略；换 Vault / 关闭 Vault 会停掉旧监听（副作用可逆） |
| 换行保真 | 识别并保留 CRLF / LF 与 UTF-8 BOM，避免"保存一次 = 全文 diff" |
| 预览 | `markdown-it`（关闭 raw HTML）+ DOMPurify 二次净化的实时预览；`useDeferredValue` 降优先级。**任务列表** `- [ ]` / `- [x]` 渲染成**禁用的原生复选框**（ADR-0024；已完成的任务**加删除线**，ADR-0027 推翻了"只变暗"的旧取舍，编辑器里删除线只圈文字、不划复选框 ——判据只有 `domain/task-list.ts` 一份，结论写在 token 上由阅读视图 / 导出件 / 应用内打印 / 静态站点 / 图谱卡片五处消费；阅读视图是只读的，勾选请去编辑器；净化白名单为它单独放开 `input`，并由 DOMPurify 钩子强制"只有禁用的 checkbox 能活下来"；已完成只变暗、不用删除线）。**callout**（`> [!note] 标题`，ADR-0022）与阅读视图、单篇导出、静态站点、图谱卡片**同一份判据、同一套样式**：13 种类型（含 `hint`/`caution`/`done` 等别名，大小写不敏感）、未知类型按 `note` 渲染但**保留用户写的类型名**当标题、`[!note]-`/`[!note]+` 渲染成低调的折叠角标（静态渲染里不真的收起 —— 读者看不到内容只会以为那篇笔记里没有它）、`> > [!tip]` 归内层。**大文档做了三件事**（ADR-0020）：① **图片授权不再触发整篇重渲染** —— 授权回来的图片**就地**把占位元素换成真图（从前每 200 张授权就会把整篇重渲染一遍，1000 张图 = 6 次全量渲染）；② **wikilink 补类名线性化**（从前每个元素都做一次 `outbound.find` 且两侧都归一化，2000 条链接就是几千万次比较）；③ 超过 **1 MiB** 的文档把 **markdown-it 解析搬进 Web Worker**（净化与 DOM 落地只能在主线程，占大头；界面上用 `data-mn-render="worker\|sync"` 标出走的哪条路），Worker 不可用时自动回落同步路径。仍未做：**分块 + 视口窗口化**（那才是消灭十万级 DOM 元素的办法，见 ADR-0020 的"本轮没有做"） |
| 双链与反链 | `[[笔记]]` / `[[笔记\|别名]]` / `[[笔记#小节]]` / `![[嵌入]]` 解析与点击跳转；右侧链接面板显示**反向链接与出链**（点反向链接会跳到来源笔记里写出这条链接的那一行）；悬空链接标黄并**点击即创建**；同名多篇按「同目录 → 更短路径 → 字典序」消歧并标记 |
| 重命名 | 文件树 `F2`（或工具栏铅笔）改名：宿主**同步改写全库指向它的链接**（保留别名/锚点、跳过代码块、BOM 与换行保真）并增量更新索引；正在编辑的笔记**原地换路径**（保留光标与撤销历史），其他被改写的文件自动重新加载 |
| 拖拽整理文件 | 把笔记**或文件夹**拖到另一个文件夹即可移动：拖到文件夹行 = 移到那个文件夹、拖到另一篇笔记上 = 移到它所在的目录、拖到树的空白区域 = 移到 Vault 根目录；悬停时目标行给出明确落点反馈（已经在该目录则标成不可放置）。移动用**原子 `rename`**（跨卷退回复制 + 删源）、**改写全库指向它的链接**（跨目录写成相对新位置的路径，避免裸名链接被重新解释到别的同名笔记）、增量更新索引与文件树；目标目录已有同名文件时**拒绝覆盖**并提示。**拖文件夹时多一条守卫**：拖进它自己或它的**后代**是无效落点（悬停时给出原因，宿主也拦同一件事），否则等于把目录搬进自己里面。目录不存在会自动创建（`F6` / 工具栏的「移动到文件夹」按钮 / 命令面板「移动到文件夹…」是同一条链路的**键盘入口**） |
| 目录重命名 / 目录移动 | 文件树里选中文件夹按 `F2` 改名、或拖到另一个文件夹 / 用 `F6` 移动：**整棵子树的路径跟着变**（`项目/子项目/细节.md` → `工程/子项目/细节.md`）**并且全库指向子树里每一篇的链接被精确改写**（`[[项目/甲]]`、`[[子/丙]]`、相对路径、裸名 wikilink 按需重算；BOM/换行保真、跳过代码块），索引与文件树增量更新。磁盘上**整棵目录一次原子 `rename`**（跨卷退回复制 + 删源）；目标同名目录**拒绝**（绝不覆盖、也绝不把两棵子树合并）。正在编辑的笔记在子树里时**原地换路径**（保留光标与撤销历史），标签页整棵子树换前缀（顺序不乱）。1000 篇的目录实测 **2–10 s**（与被引用的篇数成正比；见 ADR-0015） |
| 标签与属性 | `mn-core` 抽取 frontmatter 的 `tags`/`tag` 字段与正文行内 `#标签`（跳过代码块、行内代码、HTML 注释、标题行；`#父/子` 层级；`#Rust` 与 `#rust` 归为一个）；右侧**标签面板**显示本篇标签、frontmatter 属性表与全库标签（可点标签展开"哪些笔记用了它"→ 点笔记直接打开）。**改标签不用再手动编辑正文**：frontmatter 标签旁边有 `×`，下面一个输入框（回车提交；一次可加多个、**逗号分隔**，开头的 `#` 与首尾空白会被清掉，标签里可以有空格），改完立刻写盘 —— 面板、全库标签与索引（标签/搜索/图谱）同步跟上，正在编辑的笔记**不丢撤销历史**。写盘沿用 ADR-0004 那条路（先落盘 → 令牌校验 → 原子写 → 索引增量同步）：磁盘被外部改过就返回 `CONFLICT` 并走**同一条冲突横幅**，绝不静默覆盖（见 ADR-0006「后续修订」）。正文行内 `#标签` 在**加/删**时只读（带「正文」角标，点 `×` 会说明"请到正文里删"）。
**重命名 / 合并**：面板每一行（本篇标签与全库标签概览）都有 `✎` 入口 → 三段式对话框（输入 → **预览"这会改 N 篇"**（不落盘）→ 确认）→ **全库**改写：frontmatter 的 `tags` 与 `tag` 两个字段、以及正文行内 `#标签` 一起改（跳过围栏代码块、行内代码、HTML 注释、标题行 —— 判据与抽取器是同一个扫描器）；「连同子标签」默认开，`父→母` 时 `父/子→母/子`（只换前缀那一段，后缀逐字保留）；合并时同一篇里重复的提及会被去掉。**跳过如实汇报**（"改了 12 篇，3 篇没改（磁盘被外部改动）"），改过的文件重试安全（幂等，不写盘）。**按标签过滤文件树**：文件树头部一个标签选择器 → 只留用了这些标签的笔记（祖先目录保留、多选是**并集**、「含子标签」是显式开关、计数显示"只显示 M / 共 N 篇"、`Esc` 一键回到全量）；**选项行末尾的「排除」= 有 A 且没有 B**（"不含"以单独的胶囊列出、可与多个标签组合、与"含"互斥），命中集合由宿主的 `tag_filter` **一次**算完（层级展开也在那边做，不再逐个标签问）；它是**只读收窄**，拖拽/F2/新建/删除照旧，只有"拖到树的空白区域 = 移到根目录"在过滤期间被禁用（列表短、空白大，误拖会静默搬家）。
**层级编辑**：全库标签概览里每个标签旁的 `⇥` 打开「移到…」对话框 —— 输入**父标签**把它挂过去（`#甲` → `#父/甲`），**留空 = 提回顶层**（`#父/甲` → `#甲`），也可以点「移到顶层」一键清空。规则是**只换祖先、不动名字**（`#父/甲/孙` 移到 `#母` 下面是 `#母/孙`）；连同子标签一起移动默认开（`#甲/子` → `#父/甲/子`）。**移动 ≠ 合并**：目标标签已经存在时**拒绝**并提示用「重命名 / 合并」——静默合并会让你以为只是换了个位置。非法移动（挂到自己、挂到自己的子标签下、父标签里写了 `父//子`、已经在那里了）在**写盘前**就被拦下，理由原话显示；它与重命名共用**同一条写路径**（同一把写锁、同一份令牌对账、同一个原子写、同一处索引同步），对话框也共用（三段式预览 → 确认 → 如实汇报）。仍推迟：标签面板上的**拖拽成树**、多选一起移动 |
| 快速切换与命令面板 | `Ctrl+P` 在当前 Vault 的笔记里模糊搜索（子序列匹配 + 命中高亮，1 万篇下按键路径仍是一次 O(n) 扫描）；`Ctrl+K` 列出全部命令并执行（依赖 Vault 的命令置灰并说明原因）；两者共用同一个面板，`↑↓`/`Enter`/`Esc` 与点选都支持 |
| 全文搜索 | `Ctrl+Shift+F` 搜索正文（SQLite FTS5 + `bm25` 排序，中文与多词都支持）；结果按笔记分组显示行号与片段并高亮命中词，回车/点击打开命中笔记并**把光标落到那一行**（滚到视口正中、该行闪一下；同一篇笔记的多条命中各跳各的行）。索引是**缓存**：`<Vault>/.mimenote/cache/search.db`，删掉即自动重建 |
| 附件预览（这一轮） | 文件树里点一张**图片**不再只是选中它： 文件树里点一张**图片**不再只是选中它：主区换成只读查看器，走 `asset:` 逐文件授权把图真的显示出来（`naturalWidth > 0`），带「适应窗口 ↔ 实际大小」开关与"像素尺寸 · 文件大小 · 路径"信息行（ADR-0032）。三条纪律：**只读**（编辑仍然只发生在 Markdown 上）、**不进标签页**（标签页仍然是"我开着哪几篇笔记"）、**非桌面环境不假装**（浏览器预览里显示一句说明而不是永远转圈）。标题栏中区跟着换成"我正在看的那张图"，打开一篇笔记 / 点状态栏视图按钮 / 换 Vault 都会回到笔记。判据只有 `domain/viewable.ts` 一份。**纯文本**也走同一根主轴：`.txt / .log / .json / .csv / .toml / .yaml / 源码…` 用等宽、保留空白、带「折行 ↔ 不折行」开关的纯文本查看器显示（宿主 `note_read` 本来就不限扩展名，**一个新 IPC 都没加**）；`.zip`/`.db` 这类二进制**不**按文本打开（乱码比"打不开"更像 bug）。结构化查看器（JSON 折叠树 / CSV 表格 / frontmatter 属性面板）是下一片，挂同一根主轴 |
| 本地图片 | 预览与编辑器都渲染本地图片（`![](附件/图.png)`、`![[附件/图.png]]`；相对路径、`../`、根绝对三种写法），**两处都能点击放大**（阅读视图与所见即所得里的图片是两套不同的元素，灯箱都认）。**尺寸用 Obsidian 的写法**：`![[图.png\|300]]` 定宽、`![[图.png\|300x200]]` 定宽高（数字以外的别名仍是图注 —— `![[图.png\|一张示意图]]`）。图片经 **asset 协议逐文件授权**：路径先由 `path_guard` 逐级检查符号链接与越界，只放行通过校验的那一个文件（见 ADR-0007）；**点击放大**（灯箱：缩放/平移/`Esc` 关闭，同一篇里有多张时用「上一张 / 下一张」或 `PageUp`/`PageDown` 翻页并显示"第 N / 共 M 张"，被超大图封顶裁短时角标提示"点击查看原图"），加载失败**回退成占位元素**而不是裂图；独占一段的图片渲染成块级居中，段落里与文字混排的图片仍随文字排 |
| 粘贴 / 拖入图片 | 编辑器里 `Ctrl+V` 粘一张截图（或从资源管理器**拖入**图片）即写进 Vault 的**附件目录**（默认 `附件`，可在设置页改，不存在则自动创建）并插入 `![](相对当前笔记的路径)`：保留原文件名、同名追加 ` 1`/` 2` 绝不覆盖、通用名（`image.png`/`blob`/无扩展名）换成带时间戳的名字；紧跟的光标落到图片下一行，因此**插入即可见**（所见即所得）且 `Ctrl+Z` 一次可撤销。宿主只接受图片扩展名（与渲染授权同一份白名单）、单张 ≤ 8 MiB、一批 ≤ 32 MiB，路径一律过 `path_guard`、走原子写（见 ADR-0013）；拖入非图片会**明确拒绝并说明原因**（不静默失败），纯文本粘贴完全不受影响 |
| 知识图谱 | `Ctrl+G` 打开后默认是**关系图**（ADR-0021/0023）：以**当前打开的笔记**为圆心，只显示与它相关的子图，**离中心几跳就是半径**（同心环作为**种子**），**深度可调 1..5 跳且双向**（出链与反链都算一跳），每张卡片正面就是那篇笔记的**完整 Markdown 预览**（标题/段落/列表/引用/代码/表格/图片占位/提示框，与阅读视图同一套块清单）。种子之上跑**力导向浮动态**：张力（弹簧自然长度）/斥力/向心力/阻尼可调、五个预设（均衡 / 紧凑 / 舒展 / 漂浮 / 聚焦），节点像漂浮一样被张力牵着走；**按住一张卡片**它就停在原地而其余继续漂（HUD 上有「松开卡片」），**拖动时卡片跟着光标走、被撞上的那张自己让开**（交互会给力场重新加热，所以邻居是被斥力/弹簧推开的、不只是"撞上去才动"；拖动中的那张画在最上层，不会滑到别人下面；漂浮开着时力场有一个很小的强度底值，静止时也在缓慢呼吸）。HUD 上的「**力度管理**」把每一个旋钮都摆出来逐项调（向心力 / 斥力 / 弹簧强度与长度 / 阻尼 / 速度上限 / 弹簧范围 / 碰撞强度与轮数 / 强度衰减），整套参数跨会话保存，手调之后角标会如实说"这不只是原来那一档了"；**笔记之间会碰撞**：斥力只是"倾向"，碰撞才是"保证"—— 落定之后卡片**不会重叠**（宿主的 `data-graph-overlaps` 恒为 0，端到端用例钉住；「漂浮」档力永不降温，密集时可能留下 0.07 像素级的重叠，界面里明说了）。**连线不是从卡片边缘凭空开始的**：正文里 `[[甲]]` 那一段文字先画一段**虚线**引到卡片边界，出了卡片才变成实线与张力曲线（张力滑块可调，`0` 就是直线），**分界处严丝合缝**（两段端点逐坐标相同、虚线相位收在边界上、两端都是 butt 线帽），而且卡片内那段**单独成层画在卡片之上** —— 卡片是不透明底画在 canvas 上的，引线留在下面会被整段盖掉、看起来就是"线从卡片边缘开始"；找不到对应文字时**如实降级**成"从卡片边界出发"并在 tooltip 里说明。卡片画在 **canvas** 上（一帧只画视口内的卡片：80 张全在屏幕里也只要 ≈1 ms），缩放时文字**重新排版**而不是被放大成模糊的一团；**卡片大小可调**（拖右下角把手改宽度、HUD 上选高度上限档位，按 Vault 持久化）。方向键在卡片间移动选中项、单击预览正文、双击进编辑器打开（**这也顺带换掉了圆心**——圆心跟着当前笔记走）；选中一张卡片后可以**浮窗打开**：可拖动、可缩放、可多个并存、点一下置顶，`Esc` 先关最上面那个浮窗（浮窗不持久化——它是临时的阅读姿势）。HUD 上还有"关系图 / 整个 Vault"两个按钮、深度加减、"定位笔记…"（按名字直达，卡片在折叠的容器里会自动展开再定位）。**整个 Vault** 视图仍保留原来的全库结构视图：文件夹自动成组可收起、卡片可拖动并持久化位置、连线**入链虚线出链实线**、指向还不存在的笔记时标出**用户写下的目标名**（节点上限 8000）。视图与深度记在 `localStorage`，不按 Vault 分 |
| 图谱卡片与连线（这一轮） | **卡片正面就是完整正文**（ADR-0025）：`Frontmatter` 不再画在卡片上（判据仍是 `domain/frontmatter.ts` 那一份）；**「仅标题」档**把每篇压成一行高（不排正文，引线如实降级）；缩放手柄**同时调宽与高**，高度档新增**「全文」**（不截断，与数值档互斥 —— 长文的卡片会非常高）；单击 = **选中**（相关连线高亮），"读全文"交给浮窗，**停靠预览面板已移除**；按住一张卡片后**失去焦点即松开**（点空白或选中换走，都会加热力场让它继续漂）。连线按用户建议重做过（ADR-0028）：**语义色相** —— 暖色 = 我指向它、冷色 = 它指向我、中性 = 环与环之间；**越远越细越淡**（跳数编码线宽与透明度，强调/淡化是在这个基准上**乘性调制**）；**环向走线** —— 同一环的边沿"卡片最远的角之外"的弧走、跨环的边朝外鼓，都不再横穿圆心那块最挤的地方（HUD 上的「沿环走线」可关）；悬停正文里某段 `[[链接]]` 时对应连线提亮、引线也一起亮；引线本身加粗加深但仍是虚线 |
| 视图模块停靠（这一轮） | 文件树 / 链接 / 标签 / 大纲四块面板都能**拖到左、右、底部三个停靠区**里的任意位置（同一区内还能重排，见 ADR-0026）：拖动时目标区给出落点提示、空区会先出现一条"能放"的轨道；键盘等价物是 `Alt+1/2/3`（搬到左/右/底部）与同区内的 `Alt+方向键`；每块面板有一个标题头（拖动 + 右键菜单 + `×` 隐藏）。**可见性仍归各自的开关**，所以 `Ctrl+B` / `Ctrl+Shift+L` / `Ctrl+Shift+T` / `Ctrl+Shift+O` 一字未改 |
| 模块右键菜单（这一轮） | 一个通用右键菜单接入四处：**文件树行**（打开/在这里新建/重命名/移动到文件夹/定位/复制相对路径/展开折叠全部/删除到回收站）、**标签页**（关闭 / 关闭其他 / 关闭全部 / 在文件树中定位）、**停靠模块标题头**（移到左/右/底部、同区上下移、隐藏）、**图谱卡片**（在编辑器中打开 / 浮窗打开 / 居中显示 / 松开这张卡片 / 恢复自动尺寸）。菜单项**直接执行既有命令**，与 `F2` / `F6` / `Delete`、工具栏按钮完全同一条链路；点击外部、`Esc`、`↑↓`、超出视口自动夹回都齐 |
| 文件树排序（这一轮） | 工具栏上的排序菜单可配置**依据**（名称 / 修改时间 / 大小 / 类型）、**方向**与**目录是否在前**（ADR-0027）：判据只有 `domain/tree.ts` 一份，`mtimeMs: null`（目录、附件）恒排最后且不随方向翻转，兜底键永远升序（结果与输入顺序无关）；默认仍是"目录在前 + 名称自然序"，与从前逐字节一致 |
| 最近打开的 Vault（这一轮） | 左侧栏**底部**固定一栏"最近 · N"：最多 8 个 Vault、按根路径去重、最新在前、每条可 `×` 移除；点一条即切换（先落盘未保存内容）；`closeVault` 不清它 —— 它就是为"切走再切回来"准备的 |
| 设置与菜单 | 标题栏**菜单**按分类列出全部命令（带快捷键，`↑↓`/`Enter`/`Esc` 可用）；**设置页**（`Ctrl+,`）四个分区：外观（主题/界面字号/编辑器字号/**阅读视图字号**）、编辑器（自动保存延迟/Tab 宽度/**显示行号**（可关：关掉之后正文宽出十几像素）/附件目录）、Vault（CSS 片段开关、索引状态与重扫）、关于（版本与 Vault 统计）；所有设置即时生效（编辑器那几项走 CodeMirror 的 `Compartment`，**不重建编辑器**：文档、光标、选区与撤销历史都不动）并持久化 |
| 多标签页 | 打开过的笔记在**窗口最顶上那一行**排成标签（横跨全宽，在标题栏**上方**、侧栏之上 —— ADR-0026 把它从主区域里搬了出来）：点击切换、`×` 或中键关闭、`Ctrl+W` 关当前、`Ctrl+Alt+←/→` 循环、`Ctrl+1..9` 直达第 N 个；未保存（●）与冲突（⚠）标记只出现在激活标签上；**切换前自动落盘**（复用 `note-store` 的保存流水线，不另开写路径）；按 Vault 根持久化，重开时回到上次的工作现场 |
| 导出 | `Ctrl+Shift+S` 导出**自包含 HTML**：正文用与阅读视图同一套净化管线渲染，本地图片经 `asset_read_base64` 内嵌成 `data:` URL、主题令牌取成字面值 —— 产物是单个文件，可直接在浏览器打开或发给别人；`Ctrl+Shift+P` 导出 PDF（把同一份正文挂到只在 `@media print` 可见的容器后调系统打印对话框，"另存为 PDF"，打印结束即清理） |
| 整库导出静态站点 | `Ctrl+Alt+S`（或标题栏「导出」里的第三个选项）把**整个 Vault** 导出成一个静态站点（ADR-0019）：每篇笔记一个 HTML（**镜像目录树**：`项目/设计.md` → `项目/设计.html`）、`[[双链]]` 变成指向另一份 HTML 的**相对链接**（悬空的渲染成不可点的文字，不做假链接）、每页底部列出**反向链接**、图片按 `assets/<原路径>` **复制**（不内嵌 `data:`，同一张图不会在几千个页面里各存一份）、整站一份 `assets/site.css`（复用单篇导出的排版，外加导航/索引/反链样式）、根目录一个 `index.html` 按目录分组列出全部笔记。**零 JavaScript**：双击 `index.html`（`file://`）就能读，折叠用 `<details>`、明暗跟随系统。输出目录**必须选在 Vault 之外**（写进 Vault 会触发重扫、还会被同步盘整站上传）；非空目录必须是我们上次导出过的（靠 `mimenote-export.json` 标记），**从不删除任何文件**；同一个 Vault 导出两次**逐字节相同**（页面里没有时间戳，同步盘不会整站重传）。进度按篇显示、**可中途停止**，没导出的、悬空的、撞名的、上次残留的都在结果与索引页里逐条列出 |
| 大纲面板 | `Ctrl+Shift+O` 打开**标题树**（当前笔记的 `#` 标题，按层级缩进、随输入实时更新）：点一条就跳过去 —— 编辑视图把光标放到那一行（不改正文、不进撤销历史），**阅读视图**滚到对应标题并高亮一下，图谱视图先切回编辑视图（同一个操作只给一种结果）。**两个视图里都有"当前章节"高亮**：编辑时跟光标行（取"最后一个不晚于光标行的标题"，所以光标落在正文里仍属于上面那一节），阅读时跟滚动位置（视口顶部那一节）；读屏软件会念"当前"。长笔记还能**按级别过滤**（顶部 H1–H6 开关，默认全亮；按 Vault 记住选择）与**逐节折叠**（收起一条会藏起它下面所有更深的标题，直到同级或更浅的那条；折叠不持久化，下次打开要的是完整结构）。当前章节若刚好被过滤或折叠藏起来，面板会如实说"当前章节（第 N 行）没有显示在列表里"，**不会**把高亮挪到别的条目上。只认 ATX 标题（`# 标题`），代码块里的伪标题、frontmatter 里的 `#` 都不算 |
| 阅读视图 | 渲染后正文 + 每个代码块右上角一个**复制按钮**与语言标签（鼠标移到代码块上或聚焦时显示；复制走 `navigator.clipboard`，失败有 `execCommand` 兜底，两条都失败会显示"复制失败"而不是假装成功）；图片点击放大（灯箱）、`[[双链]]` 与内部链接点击跳转、悬空链接点击即创建 |
| 窗口标题 | 系统窗口标题跟着当前笔记走（`笔记名 — Mimenote`，名字**不带 `.md`**，有未保存修改时加一个圆点）：任务栏、Alt+Tab 与截图里都能看出这是哪篇笔记 |
| 设计令牌与默认字号（这一轮） | 全部颜色/字体/圆角/间距/字号都经 CSS 变量暴露，**两层命名**（ADR-0031）：`--mn-*` 是存储格式（主题 JSON 的键），VI 规范名（`--bg-base` / `--text-primary` / `--brand-primary` / `--radius-md` / `--space-4` / `--font-reading` …）是**公开书写面**，插件与用户样式片段用它；指向主题可选令牌的别名一律带兜底，因此既有三套主题一个字都不用改。**默认字号三档统一 16px**（界面 / 编辑器 / 阅读），真值在设置层、设置页三档仍可各自调（11–18 / 12–28 / 12–30）；文件树行高随之 26 → 30；新增门禁：四栏不得裁字、树行上下留白 ≥3px。字体族仍是 UI 字体 + 等宽只给代码（阅读衬线/编辑等宽留作可选皮肤：主题里给 `--mn-font-reading` / `--mn-font-editor` 即可） |
| 笔记名不带 `.md`（这一轮） | 界面上凡是"**这是哪一篇**"的地方都只写文件名主干：标签页、标题栏中区路径、文件树行、反向链接与出链的解析路径、快速切换（`Ctrl+P`）、全文搜索命中、窗口标题、回收站列表 —— 判据只有 `domain/paths.ts` 的 `displayName` / `displayPath` 一份（ADR-0030）。**想看全名随时有出口**：悬停标签页 / 标题栏路径 / 文件树行，提示里都是完整文件名。**三处刻意保留真实文件名**：① 导出件与静态站点（给 Vault 之外的人看的东西）；② 宿主报错原文（`文件不存在：xxx.md` —— 那是它在描述磁盘上的文件）；③ 移动对话框这类"编辑路径"的地方（那里用户编辑的就是路径本身）。附件（`图.png`）与非 Markdown 文件一律原样，只有 `.md` / `.markdown` 会被隐藏；自动化的身份探针（`data-note-path` / `data-tab-path` / `data-rel-path`）也仍然是**真实路径**——可见文字不是身份 |

| 删除保护 | 必须二次确认；文件移入 Vault 内 `.mimenote/trash/` 并写台账，不做 `unlink`。**能拿回来**（ADR-0018）：菜单 / 命令面板搜「回收站」→ 列出删过的条目（名字、原路径、删了多久、大小），一条条「恢复」或「恢复为…」。恢复到**原来的位置**；那里已经有别的文件时**绝不覆盖**，改用「恢复为…」换个名字放回去；删过整个目录再恢复时，会把你顺手建了哪些目录**如实说出来**。台账里有、回收站里已经没有的那些（手工清过回收站）会标成"文件已不在回收站"并禁用恢复 —— 不让用户点两次才明白 |
| 可定制 | 命令注册表 + 快捷键、JSON 主题（CSS 变量，内置深色 / 浅色 / **「纸墨」（暖白纸感的阅读主题，这一轮新增）**）、Vault 内 `.mimenote/snippets/*.css` 用户样式片段（可整体卸载） |
| 安全 | 路径越界/符号链接逃逸/Windows 保留名拦截、严格 CSP、能力声明最小化（`core:default` + `dialog:allow-open` + `dialog:allow-save`）；写 Vault 之外的单文件只有 `export_write_html` 一条命令且只接受 `.html`/`.htm`（见 ADR-0011）；**写 Vault 之外的目录树**只有整库导出的两条命令，且输出目录必须在 Vault 之外、站内路径逐段校验、扩展名只允许 `.html`/`.css`/`.json`、**从不删除任何文件**（见 ADR-0019）；写 Vault 之内的图片只有 `attachment_save` 一条命令，且只接受图片扩展名、单张 ≤ 8 MiB、路径一律过 `path_guard`（见 ADR-0013） |

## 快速开始

### 前置要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 22（实测 26.2.0） | 前端构建与测试 |
| pnpm | ≥ 10（实测 11.7.0） | 包管理（`corepack enable pnpm`） |
| Rust | stable（实测 1.96.0） | Rust 宿主 |
| MSVC Build Tools / VS 2022 | Windows 需要 | 链接 Tauri 宿主 |
| WebView2 Runtime | Windows 11 自带 | 渲染前端 |

### 安装与运行

```bash
pnpm install                 # 安装前端依赖（Cargo 依赖在首次构建时自动拉取）

pnpm tauri:dev               # 启动桌面应用（开发模式，热更新）
pnpm dev                     # 仅启动前端（浏览器里跑 Mock Vault，用于调界面）

# 直接用某个文件夹启动（命令行参数 / 快捷方式 / "打开方式"）
target\release\mimenote.exe D:\我的笔记
```

首次 `pnpm tauri:dev` 需要编译约 400 个 crate（本机约 4~5 分钟），之后为增量编译。

### 构建

```bash
pnpm tauri:build                      # 出安装包（Windows: NSIS + MSI，需要下载打包工具）
pnpm --filter @mimenote/desktop exec tauri build --no-bundle   # 只出可执行文件 → target/release/mimenote.exe
```

> ⚠️ **必须用 Tauri CLI 构建（`pnpm tauri:build`），不要直接 `cargo build --release`。**
> `tauri-build` 通过 `TAURI_ENV_DEBUG` 环境变量判断"开发 / 生产"，这个变量只有 Tauri CLI 会设置；
> 直接跑 cargo 时它会退化为 `cfg!(debug_assertions)`，于是**生产二进制里被写入了 devUrl**，
> 启动后窗口会去连 `http://127.0.0.1:1420` 并显示"网络错误"。
> 同理，`target/debug/mimenote.exe` 也总是要连 dev server —— 调试请用 `pnpm tauri:dev`。

### 测试与质量门禁

```bash
pnpm check        # 类型检查 + 前端测试 + Rust 测试（一条命令跑完）
pnpm typecheck    # tsc --noEmit（TS 严格模式，含 noUncheckedIndexedAccess）
pnpm test         # vitest（前端单元 + 集成测试）
pnpm test:rust    # cargo test --workspace
pnpm lint:rust    # cargo clippy --workspace --all-targets -- -D warnings
pnpm fmt:rust     # cargo fmt --all
pnpm test:e2e     # 两层端到端测试（见下）
```

### 端到端测试（E2E）

分两层，各自解决不同的问题：

| 层 | 命令 | 被测对象 | 平台 |
| --- | --- | --- | --- |
| **真实应用** | `pnpm test:e2e:app` | `tauri build` 产出的 **release 二进制**：真实 WebView2、真实 IPC、**真实磁盘写入** | 仅 Windows（需要 WebView2 的远程调试） |
| **UI 层** | `pnpm test:e2e:ui` | **系统 Edge** + `dist/` 构建产物 + 内存 Mock Vault：真实 Chromium 布局与交互 | 跨平台，秒级，适合 CI |

运行前提：

```bash
pnpm --filter @mimenote/desktop build                          # UI 层需要 dist/
pnpm --filter @mimenote/desktop exec tauri build --no-bundle   # 应用层需要 release 二进制
```

#### 为什么是"Playwright + WebView2 CDP"而不是 tauri-driver

Tauri 官方文档的 E2E 路径是 `tauri-driver` + WebdriverIO：`tauri-driver` 是一个 **WebDriver 服务端**，
而 Playwright 不走 WebDriver 协议，两者无法对接；走那条路还要一个与 WebView2 版本**精确匹配**的
`msedgedriver.exe`。WebView2 支持 `--remote-debugging-port`（通过环境变量
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 传入），Playwright 的 `chromium.connectOverCDP()`
可以直接接管它 —— 于是既保留了 Playwright，又能跑真实二进制。

实现见 `e2e/support/harness.ts`，其中记了两个坑：

1. 端口被别的程序（浏览器、其它调试实例）占用时，WebView2 会退到 IPv6 `[::1]`，
   而 IPv4 上仍是别人在监听 —— 探到的 404 是别人的。**必须先申请一个空闲端口**。
2. 不通过 `Emulation.setDeviceMetricsOverride` 测窗口缩放：WebView2 的 CDP 不暴露该域，
   缩放场景放在 UI 层（真实 Chromium）验证。

两点按键相关的设计取舍：

- **界面缩放不走浏览器缩放**：窗口关掉了 WebView 的缩放热键（`zoomHotkeysEnabled: false`），
  否则 `Ctrl+=` / `Ctrl+-` / `Ctrl+0` 会被 WebView 抢去缩放整个界面 —— 那正是图谱缩放的三个键位，
  而且界面上没有任何"按错了怎么恢复"的提示。字号请用设置页的**界面字号 / 编辑器字号**（会持久化）。
- **注册过的组合键优先于编辑器**：全局快捷键装在**捕捉阶段**，因此 `Ctrl+G` 在编辑器里也是"打开图谱"
  —— 编辑器侧的键位处理（CodeMirror 的 `Ctrl+K`「删到行尾」、搜索面板范围内的 `Ctrl+G`「查找下一个」）
  会 `preventDefault()`，冒泡阶段的全局监听收到时已经晚了（实测症状：焦点在编辑器里按 `Ctrl+G` 打不开图谱）。
  `Mod+K`/`Mod+P`/`Mod+Shift+F` 由面板自己的监听独占；`Ctrl+F`（编辑器内搜索）不是注册命令，
  仍归 CodeMirror，搜索面板里用 `Enter` 或 `F3` 跳下一个。

### 手工验收清单

用仓库自带的示例 Vault：`examples/demo-vault/`。

1. `pnpm tauri:dev` → 应用启动，显示 Vault 门闸页
2. 「打开文件夹作为 Vault」→ 选择 `examples/demo-vault` → 文件树出现，状态栏显示条目数与扫描耗时
3. 点击 `项目/设计文档.md` → 编辑器载入内容并**直接以所见即所得方式显示**（标题、引用、代码块、任务列表就地渲染）；按 `Ctrl+E` 切到"阅读"看渲染后的整篇（表格、代码块、引用都在）
4. 输入文字 → 状态栏短暂显示「保存中…」→「已保存 hh:mm:ss」并给出写入耗时（应 < 50ms）
5. 切换主题（状态栏右下角下拉）→ 编辑器与预览颜色立即跟随，无需重启
6. 调色板按钮 → 停用/启用 `example.css` 片段，观察预览标题/引用的变化
7. **冲突验证**：用记事本打开 `README.md` 并改几个字保存 → 回到应用里输入一个字 → 顶部出现冲突横幅 → 选「用我的内容覆盖」或「丢弃我的修改并重新加载」
8. **原子写验证**：保存时观察 Vault 目录，正常情况下不应残留 `.mimenote-*.tmp`
9. **删除验证**：选中 `附件/示例说明.txt` 按 `Delete` → 二次确认 → 文件出现在 `.mimenote/trash/`，台账 `.mimenote/index.jsonl` 多一行
10. **重命名验证**：选中 `项目/设计文档.md` 按 `F2` → 输入新名字回车 → 文件树里的行改名；打开 `项目/路线图.md` 看预览里的 `[[设计文档]]` 是否已跟着改成新名字（用 `git status`/编辑器看磁盘内容也行）
11. **标签与属性验证**：按 `Ctrl+Shift+T` 打开标签面板 → 当前笔记的 `#标签` 与 frontmatter 属性列出来；点某个标签 → 展开"哪些笔记用了它" → 点笔记直接打开。**改标签**：在输入框里填 `新标签` 回车（或用逗号一次填两个）→ frontmatter 里应多出这一项、面板与「全库标签」立刻跟上；点某个 frontmatter 标签的 `×` → 它从磁盘上消失。正文里的 `#标签` 带「正文」角标，点它的 `×` 只会提示"请到正文里删"（面板不动那个文件）
12. **命令面板 / 快速切换验证**：`Ctrl+P` 输入"设计"回车 → 打开对应笔记；在编辑器里按 `Ctrl+K`（应弹出面板，而不是删掉一行后半截）→ 输入"主题"回车 → 主题切换
13. **全文搜索验证**：`Ctrl+Shift+F` 输入"原子写"→ 结果里应出现 `项目/设计文档.md`（带行号与片段）→ 回车打开它，**光标应落在命中那一行**（该行被滚到视口中间并闪一下，直接打字就写在那一行）；中文与多词（如"原子 写"）都应命中；删掉 `.mimenote/cache/search.db` 后重开 Vault 应自动重建
14. **本地图片验证**：打开 `项目/设计文档.md` → 预览顶部应显示出图片（`附件/示例图片.png`）。若显示占位方块，说明该图没拿到授权（文件不存在、路径越界、或扩展名不在白名单里）
15. **大 Vault 验证**：把示例 Vault 复制成多份或生成 1 万个小文件，打开后滚动文件树应保持顺滑（DOM 行数恒定），`Ctrl+P` 输入时也不应卡顿
16. **所见即所得验证**：打开 `项目/设计文档.md`，编辑器里应直接看到渲染后的标题/引用/代码块/任务列表，而**不是** `#` 与反引号（表格、缩进代码块、脚注、HTML、公式按设计**不做装饰**，原样显示）；把光标移进某段粗体（`**…**`）应立刻露出星号，移开又隐藏；任务列表 `- [ ]` 可以直接点
17. **知识图谱验证**：`Ctrl+G`（在编辑器里按也一样，不会被 CodeMirror 的"查找下一个"抢走）→ 每篇笔记是一张卡片、文件夹自动成组；点卡片右侧出现正文预览；`路线图.md` 的卡片被选中时，**指向它的线是虚线、它指出去的线是实线**；点文件夹标题可收起/展开；拖动空白处平移、`Ctrl+滚轮` 缩放、`0` 适应窗口；双击卡片回到编辑器；回编辑器改一行并等自动保存 → 图谱卡片上的入度/出度与连线**自己跟上**（不需要手动刷新）
18. **设置与菜单验证**：标题栏左侧菜单按钮 → 按分类列出全部命令（带快捷键）；`Ctrl+,` 打开设置 → 改编辑器字号应立即生效、**阅读视图字号只影响阅读视图正文**（编辑器字号不动）、改自动保存延迟后输入不再频繁写盘；「Vault」分区能看到索引进度与重扫按钮
19. **多标签页验证**：依次打开两篇笔记 → 主区域顶部出现两个标签，当前那篇高亮；点另一个标签切过去（编辑器内容与路径都跟着换，切换前未保存的内容已落盘）；`×` 或中键关掉当前标签 → 自动接到相邻标签；`Ctrl+W` 关当前标签（有未保存修改会二次确认）；关掉应用再重开同一 Vault → 上次的标签列表与当前那篇都回来了
20. **导出验证**：打开 `项目/设计文档.md` → `Ctrl+Shift+S` 导出 HTML 到桌面 → 关掉网络、直接用浏览器打开那个文件：**图片也在**（内嵌成 `data:` URL）、样式与主题一致、没有外部请求；再按 `Ctrl+Shift+P` → 系统打印对话框里选"另存为 PDF" → 产物是同一份正文（打印结束后应用界面里不应残留打印容器）
21. **拖拽整理验证**：把 `项目/设计文档.md` 拖到另一个文件夹上（例如 `日记`）→ 悬停时目标文件夹整行高亮（若拖到自己所在的 `项目` 上则标成不可放）；松手后树里出现在新目录、原目录不再有它；打开 `项目/路线图.md` 看预览里的 `[[设计文档]]` 是否已改成 `../日记/设计文档`（用 `git status`/编辑器看磁盘内容也行）；把当前打开的那篇拖走 → 编辑器路径立即跟着变、内容不动；再拖回 `项目` 应能改回原样。用键盘做同一件事：选中笔记按 `F6`（或 `Ctrl+K` → 「移动到文件夹…」）→ 输入 `日记/子目录` 回车 → 目录不存在时会**自动创建**（不用先手工建文件夹）
22. **粘贴截图验证**：打开任意一篇笔记，用系统截图工具（`Win+Shift+S`）截一张图 → 在编辑器里 `Ctrl+V` → 图片**立刻出现在光标处**（光标会自动落到图片下面一行）、状态栏短暂显示保存；文件树里 `附件/` 下多出一个文件（截图工具给通用名时是 `粘贴图片 2025-01-01 123456.png`，`git status` 也能看到）；按一次 `Ctrl+Z` 应能把这次插入整条撤销。再连粘三张：三张文件名互不相同（不会互相覆盖）。从资源管理器拖一张 `.png` 到编辑区 → 插到**鼠标释放的位置**；拖一个 `.pdf` 进来 → 应弹出"只接受图片文件"的提示且**什么都不写**。把设置页（`Ctrl+,` → 编辑器 → 附件目录）改成 `assets` 再粘一张 → 文件应落在 `assets/` 下、笔记里写的是 `../assets/…`；清空该输入框 → 图片直接落在 Vault 根目录。往编辑器里粘一段**文本**（例如从别处复制一行命令）→ 行为应与以前完全一样
23. **大纲面板验证**：打开一篇有多个标题的长笔记（例如把 `项目/设计文档.md` 复制几份、加几个 `#`/`##`）→ `Ctrl+Shift+O` 打开右侧大纲：标题按层级缩进、随输入实时更新（新敲一个 `##` 会立刻出现）；在代码块里写 `# 伪标题` 应**不**出现在大纲里；点一条 → 编辑视图里光标落到那一行（正文一个字没变，`Ctrl+Z` 不会撤销"跳转"）；按 `Ctrl+E` 切到阅读视图再点另一条 → 正文滚到那个标题并高亮一下。**过滤与折叠**：点掉顶部的 `H3` 开关 → 列表里立刻没有三级标题了（缩进不跳）；把开关全点掉 → 出现"当前过滤条件下没有标题。"与「显示全部级别」；点条目左边的三角收起一节 → 它下面更深的标题一起消失、三角仍在（再点即展开）；**把光标移到被收起的某一节里**（或按 `Ctrl+E` 滚到那里）→ 面板顶部应出现"当前章节（第 N 行）没有显示在列表里"，且**没有**别的条目被高亮成"当前"；换一篇笔记再回来 → 折叠恢复成全展开（折叠刻意不持久化），而级别过滤按 Vault 记住（关掉应用重开仍在）
24. **索引复用验证**：打开一个大 Vault（或把示例 Vault 复制成一万篇）→ 第一次打开状态栏有"索引中"的过程；**关掉应用再重开同一个 Vault** → 应几乎立刻可用（`<Vault>/.mimenote/cache/search.db` 被复用，不再重读全部文件）；随后只改一篇笔记并保存 → 下次打开仍然很快；把 `search.db` 删掉 → 下次打开回到"整库重建"（属预期：缓存是可丢弃的派生数据）
25. **阅读视图复制代码**：`Ctrl+E` 切到阅读视图 → 鼠标移到某个代码块上，右上角出现"复制"按钮与语言标签 → 点一下变成"已复制"（再粘到别处验证内容正确、末尾不多个空行）
26. **窗口标题与自绘标题栏验证**：打开一篇笔记 → 系统窗口标题（任务栏 / Alt+Tab）显示 `笔记名 — Mimenote`；在编辑器里改一个字（未保存）→ 标题多一个 `•`；等自动保存完成 → 圆点消失。**标题栏**：窗口顶部**只有一条**栏（系统标题栏已经关掉，见 ADR-0017）—— 按住它中间那块空白拖动，窗口要跟着走；**双击**它 → 窗口最大化/还原；拖到屏幕上沿也应贴边最大化。右侧三个按钮：点 `—` 最小化、点 `▢` 最大化（图标随之变成"还原"样式）、点 `✕` 关闭窗口（关闭前若有未保存内容，走既有的确认链路）。**让按钮状态与窗口保持一致**：用 `Win+↑` 或双击标题栏最大化 → 那个按钮应自己变成"还原"（状态是从真实窗口读回来的，不是本地开关）。**三区（ADR-0029）**：左区是菜单 + `Mimenote` + Vault 名，**中区是当前笔记的相对路径**（正好落在窗口横向正中），右区是条目统计 + 导出 + 三个窗口按钮；打开/关闭笔记时**这一行的高度不变**（不再有"多出来的一行 26px 把正文顶下去"），编辑器里也不再重复显示路径。切到**阅读视图**与**图谱视图** → 中区的路径仍然在（这是搬家的直接收益）。把窗口拖窄 → 中区路径与右区统计**先走省略号**，三个窗口按钮始终留在可视区内（悬停路径能看到完整路径）
27. **目录改名 / 目录移动验证**：选中 `项目` 文件夹按 `F2` → 改名框预填的是**目录名**（不带扩展名）→ 输入 `工程` 回车 → 文件树里整棵子树都换了前缀（`工程/子项目/细节.md` 这类深层文件也在）；打开 `工程/子项目/细节.md` 看预览里的链接是否仍然解析得到（悬空会画成虚线）；再把 `工程` **拖到树的空白区域**（或按 `F6` 输入空目录）→ 应提示"已经在 Vault 根目录"（无效落点，什么都不做）。把 `工程` 拖到它自己的子目录上 → 悬停时该行标红并提示"不能把文件夹移动到它自己的子目录里"；同理把文件夹拖到**它自己那一行**上→ 提示"不能把文件夹移动到它自己里面"。改完记得把名字改回 `项目`（见已知限制）
28. **外部改动自动同步验证**（ADR-0016）：打开 `examples/demo-vault` → 在**资源管理器**里新建一个 `测试同步.md` → 约半秒后文件树里出现它（**不要**按 `Ctrl+Alt+R`）；再在**记事本**里改一改 `项目/设计文档.md` 保存 → 若它当前没有被编辑，编辑器里的正文自己变成新内容并提示"已在磁盘上更新，已重新加载"；接着在应用里输入几个字（不要保存）→ 再用记事本改同一个文件 → 出现**冲突横幅**（而不是自动覆盖）；点「丢弃我的修改并重新加载」应看到记事本里的内容。最后验证"自己写的文件不算外部改动"：反复输入并等自动保存 → 状态栏正常显示"已保存"，**文件树不闪、不重扫**（日志里没有一行"检测到外部改动"，见 `%LOCALAPPDATA%\app.mimenote.desktop\logs\mimenote.log`）；关掉 Vault（或换一个 Vault）后，再改旧 Vault 里的文件**不应该**有任何反应（旧监听已停）
29. **标签重命名 / 合并验证**：先造两篇笔记，一篇 frontmatter 写 `tags: [旧名]`、正文里写 `#旧名`，另一篇同样写 `#旧名`，再在其中一篇的**代码块**里放一行 `#旧名`。点标签面板里 `旧名` 旁边的 `✎` → 输入 `新名` → 应看到**预览"这会改 N 篇"**（这一步还没落盘：用 `git diff` 或记事本确认磁盘没变）→ 确认 → 两篇文件的 frontmatter 与正文都变成 `新名`，而**代码块里的那行没动**；面板与「全库标签」里 `旧名` 消失、`新名` 出现。**合并**：把 `新名` 改成另一篇已有的标签 → 同一篇里重复的提及会被去掉。**跳过如实汇报**：先改之前用记事本动一下其中一篇（制造外部改动）→ 结果里应明确说"X 篇没改（磁盘被外部改动）"，而不是只报成功。**层级**：给 `父` 改名为 `母`（「连同子标签」默认开）→ `父/子` 应变成 `母/子`
30. **文件树按标签过滤验证**：文件树头部点标签选择器 → 勾一个标签 → 树里只剩用了它的笔记（**祖先目录仍在**，计数显示"只显示 M / 共 N 篇"）；勾两个标签（多选是**并集**，界面上写着"含任意一个"）；选中 `父` 而「含子标签」开着时，`父/子` 的笔记也在；按 `Esc` 或点「清除」→ 立刻回到全库。过滤期间拖一篇笔记到**树的空白区域** → 应被明确拒绝并说明原因（这是刻意的：空白处等于"移到根目录"，而根目录在收窄视图里看不见）；拖到另一行上仍然正常。**排除**：在选项行末尾点「排除」→ 选中的那一类被剔出去（"不含 #xxx" 会以胶囊形式单独列出来，点 × 可单独取消）；同一个标签点「排除」会从"含"移到"不含"（互斥）。再叠一个文本过滤词 → 两个条件是"与"的关系（只在可见行之间导航，虚拟列表也按过滤后的行数算）
31. **回收站恢复验证**：在文件树里选中一篇笔记按 `Delete` → 确认框里应写明"可在「回收站」里恢复" → 确认。然后 `Ctrl+K` 搜「回收站」回车：列表里能看到它（名字、原路径、"刚刚"、大小）→ 点「恢复」→ 文件应**逐字**回到原位置、文件树里重新出现那一行、列表里不再有它。再删一次，这次**先手工把同名文件建回来**（在应用里新建一篇同名的，或用记事本写一个）→ 点「恢复」→ 应明确报"原位置已经有别的文件了"并提示用「恢复为…」，磁盘上那个占位文件**一个字节都不能变**；点「恢复为…」把路径改成 `归档/拿回来.md` 回车 → 应成功并提示"顺手建了 1 个目录"，树里在 `归档` 下出现它。最后试**整目录**：删掉一个文件夹 → 恢复 → 树里整棵回来（宿主会做一次静默重扫）
32. **标签层级编辑验证**：先造三篇笔记：一篇 frontmatter 写 `tags: [甲, 别的]`、正文里写 `#甲`；一篇写 `tags: [甲/子]`；再在其中一篇的**代码块**里放一行 `#甲`。`Ctrl+Shift+T` 打开标签面板 → 在「全库标签」里找到 `甲` → 点它旁边的 `⇥` → 对话框标题是"调整标签层级"、输入框**初值是空的**（顶层标签没有父标签）→ 输入 `父` 回车 → 预览应说**"这会改 2 篇笔记"**（`甲` 与 `甲/子` 各一篇；这一步还没落盘，用记事本确认磁盘没变）→ 点「确定移动」→ 两篇文件的 frontmatter 与正文都变成 `父/甲` / `父/甲/子`，而**代码块里的那行没动**；面板与「全库标签」里 `甲` 消失、`父/甲` 与 `父/甲/子` 出现。**提回顶层**：点 `父/甲` 旁边的 `⇥` → 输入框里预填着 `父` → 点「移到顶层」（输入框清空）→ 回车 → 预览 → 确定 → 它变回 `甲`。**非法移动**：再点 `甲` 旁边的 `⇥`，父标签里填 `甲` 自己 → 回车 → 应**停在输入阶段**并弹出一条错误提示（原文是"不能把标签挂到它自己下面"，**不是**"路径不合法"），磁盘一个字节不变；再试填 `甲/子`（它自己的子标签）应报"会造出改不完的层级"；先建一个名为 `父/甲` 的标签再移动 `甲` → 应报"「父/甲」已经是一个标签了；要合并请用「重命名」"。最后验证**面板跟着挪**：展开 `父/甲/子` 那一节，然后把它上面的 `父/甲` 移到 `母` 下 → 展开的那一节应变成 `母/甲/子`，而不是空着
33. **整库导出静态站点验证**：先在一个**不在 Vault 里、也不在同步盘里**的位置建一个空目录（例如 `D:\站点测试`）。`Ctrl+Alt+S`（或标题栏「导出」→ 第三个选项）→ 选那个目录 → 看着进度跑完（"正在导出 N / M 篇…"，可以点「停止导出」中途停下）。然后用**文件管理器**打开 `index.html`（双击，走 `file://`）：索引页按目录分组列出所有笔记；点一篇进去，正文排版与应用里的阅读视图一致（**断网也一样**）；点正文里的 `[[双链]]` 能跳到另一篇；页面底部的「反向链接」能点回来源；指向不存在笔记的链接是**灰色不可点**的文字（悬停有说明）；图片都在（`assets/` 目录里），且 `index.html` 与每篇 HTML 里**没有任何 `data:image/`**（图片是复制的，不是内嵌的）；整站**没有 JavaScript**（用记事本打开任一 HTML，搜 `<script` 应为 0 处）。**确定性**：什么都不改，再导出一次到同一个目录 → 目录里的文件内容**逐字节不变**（`index.html` 也一样；只有 `mimenote-export.json` 里的时间戳会变）。**拒绝**：把输出目录选成 Vault 里的某个目录 → 应被明确拒绝（提示里说清"会触发重扫、还会被同步盘整站上传"），Vault 一个字节不变；选一个**非空且不是我们导出的**目录 → 也被拒绝（避免几千个文件散进用户自己的目录）。**取消**：跑到一半点「停止导出」→ 应提示"已经写出 N 个文件、这次没有写索引页与标记文件"，并且那个目录里**确实没有** `index.html`
34. **隐藏 `.md` 验证**：打开一篇笔记 → 逐处确认**没有扩展名**：窗口顶部标签页上写着 `设计`（不是 `设计.md`）、标题栏中区是 `项目/设计`、左侧文件树那一行也是 `设计`、`Ctrl+P` 输入 `设计` 列出的候选同样不带 `.md`、反链面板里的来源名、任务栏/Alt+Tab 的窗口标题都一致。**全名没丢**：把鼠标停在这三处（标签页 / 标题栏中区 / 文件树行）→ 提示里是**完整文件名**（`项目/设计.md`）。**不该隐藏的地方**：`Ctrl+Shift+S` 导出的 HTML、`Ctrl+Alt+S` 的静态站点里，页面文件名与站内链接仍然是 `设计.md` → `设计.html` 的真实映射；打开**移动对话框**（`F6`）时"将移动到："那一行给的是带 `.md` 的真实路径；把它移进一个不存在的目录，磁盘上的文件名一个字符都没变。**附件不受影响**：`附件/图.png` 在文件树里仍然带 `.png`（去掉就认不出是什么文件了）。最后在编辑器的 `[[` 补全里敲 `设计` → 候选仍然能选中那一篇（补全早就是这个口径）

35. **附件预览验证**：在文件树里点一张图片（例如 `附件/图.png`）→ 主区应换成查看器：图片**真的显示出来**（不是占位方块、不是空白），信息行有"宽 × 高 · 大小 · 路径"，右上角一个「实际大小 / 适应窗口」开关（点一下按原始像素显示、再点回适应窗口）。标题栏中区应变成**那张图**（不是之前那篇笔记）。**回到笔记**有三条路，随便试一条：点文件树里的一篇笔记 / 点状态栏的编辑按钮 / 换一个 Vault —— 查看器都该关掉。**不该发生的事**：看一张图**不该**在标签栏冒出标签（标签栏只装笔记）；点一个 `.txt` / `.zip` 附件仍然只是选中它（不提供预览）。浏览器预览（`pnpm dev`）里点图片会显示一句"浏览器预览模式读不到本地文件"的说明 —— 那是预期，真实渲染请在桌面应用里看
### 已知限制与风险

见 [`docs/architecture.md` §8/§9](docs/architecture.md)。当前最主要的几条：

1. **所见即所得是"渲染视图"，不是富文本**：文档始终是纯 Markdown，装饰只在光标不在该处时隐藏标记。表格、缩进代码块、脚注、引用式链接、HTML、数学公式**不做装饰**（原样显示，见 ADR-0009）；frontmatter 只是淡色不隐藏（保留可编辑与可 diff）
2. 重命名与**跨目录移动（拖拽整理）**都已交付：改名保持"最小 diff"（裸名链接仍是裸名），跨目录移动则把链接一律改成**相对新位置的路径**（`[[乙]]` → `[[子/乙]]`），因为裸名靠"同目录优先"消歧、换了目录可能落到另一篇同名笔记上；移动还会**改写被移动笔记自身正文里的相对链接**（`![](../附件/图.png)` 随新位置重算，见 ADR-0012）。**目录重命名与目录移动也已交付**（ADR-0015）：整棵子树的路径与全库链接一起改，复用同一条搬迁链路与同一个 DTO；文件夹可拖、`F2`/`F6` 对文件夹同样可用，**拖进自己的后代**是无效落点。目录搬迁**没有进度与取消**（1000 篇实测 2–10 s，只给一次 toast，成本与被引用的篇数成正比）。仍然没做：**引用式定义行**（`[id]: ../附件/图.png`）里的相对目标不改写；带反斜杠或越出 Vault 根的目标跳过；被移动笔记里的**裸名 wikilink**（`[[乙]]`）不动 —— 它按文件名主干解析，同名笔记多时移动后可能改指另一篇。
   新文件名里含 `#`/`^` 时，指向它的链接**不会被改写**（wikilink 语法无法表达这种目标），宿主会记日志并跳过
3. **标签现在是可写的**：加/删（`note_set_tags`，只动 frontmatter）、**全库重命名/合并**（`tag_rename`：frontmatter 的 `tags`/`tag` + 正文行内 `#标签` 一起改，跳过代码块与行内代码）、**文件树按标签过滤**（宿主的 `tag_filter` 一次算完：含任意一个 / 不含任何一个 / 可带后代）、**层级编辑**（`tag_move`：挂到某个父标签下或提回顶层，复用重命名那条写路径）都已交付，判同只有一处（`normalize_tag`）。仍然要知道的边界：① **正文行内 `#标签` 在"加/删"时是只读的**（那等于改正文；面板标出「正文」角标并提示"请到正文里删"）；② 重命名/合并**批量写盘没有进度与取消**（约 8 ms/篇：100 篇 ≈ 1 s、700 篇 ≈ 5–6 s），单篇失败只进跳过清单、**整批不回滚**（回滚要把已写文件再写一遍，风险更大），有跳过时界面会如实说明并建议重试（重试幂等）；③ 缩进代码块（4 空格）里的 `#标签` 仍会被当成标签改（继承抽取器的既有口径）；④ 文件树的标签过滤是**只读收窄**：查询失败时整轮不收窄（宁可不过滤，也不给"少了几篇"的假收窄），过滤期间"拖到树的空白区域 = 移到根目录"被禁用（列表短、空白大，误拖会静默搬家）；⑤ 过滤条件变了才会重新取数，所以**刚做过层级编辑/重命名的那些标签要等下一次重扫或手动「重新过滤」才反映到树上**（树收窄的依据是打开时那份命中集合，不是实时倒排）；⑥ 参数口径：面板显示的是 `tags` 与 `tag` **合并**后的列表，而加/删的写入目标是 `tags`（没有 `tags` 时才写 `tag`）—— 所以两者同时存在时 `tag:` 里的标签点 `×` 删不掉，面板会明确说"它来自 `tag:` 字段"（重命名/合并会改这两个字段里的任何一个）；⑦ 层级编辑仍缺三样：标签面板上的**拖拽成树**、**多选一起挂到某个父标签下**、父标签输入的**前缀补全**（现在只有 `datalist` 的原生提示）。搜索与反向链接**回车会跳到命中行**（`app/actions.ts` 的 `openNoteAt`），但**出链不定位**（链接写在哪一行 ≠ 目标笔记里的哪一行，`#锚点` 也没有"锚点 → 行号"的接口）
4. **图谱的自动刷新是"保留视角"的一档**：保存成功与索引就绪都会触发一次刷新（画布正显示时），但**刷新不重建手工拖动过的位置**；手工拖动会覆盖自动布局（「重新自动排布」一键复位）；折叠状态不持久化（每次默认全展开）
5. 删除走 Vault 内回收站（**不做 `unlink`**），未对接系统回收站。**恢复的界面已交付**（ADR-0018）：菜单 / 命令面板 → 「回收站」，可「恢复」到原位置或「恢复为…」换个名字放回去；那里已经有别的文件时**绝不覆盖**（记录与文件都留在回收站里），孤儿记录（台账里有、回收站里没有）会标出来并禁用恢复。仍然要知道的边界：**回收站没有"永久删除"与"清空"** —— 本轮只做"拿回来"，清空要用户自己去文件管理器里做（之后台账会出现孤儿记录，界面已如实标出）；恢复**整目录**走一次静默重扫（1 万笔记约 0.1–0.3 s，复用索引缓存），单篇是就地更新、不重扫；**不做自动改名**（原位置被占用时必须手改名字 —— 自动改名会让"我明明恢复了、怎么找不到"变成新的困惑）
6. 冲突检测基于 mtime（同毫秒内两次独立修改理论上有漏检窗口）；**索引复用**也基于同一把钥匙（`(path, mtime, size)`），因此"同毫秒 + 同字节数"的外部改动同样会漏检 —— 要兜住得引入内容哈希（M5）
7. **大文档预览（ADR-0020）**：1 MiB 的中文笔记实测（jsdom，看占比）—— 解析约 **9%**、DOMPurify 净化约 **46%**、`innerHTML` 落地约 **42%**、全篇 `querySelectorAll` 约 **5%**。因此：**净化与 DOM 落地只能在主线程**（DOMPurify 在没有 `window` 的环境里连 `sanitize` 都没有定义，实测 threw `TypeError`；DOM 构建更是主线程独占），Worker 只承担解析那一段（超过 1 MiB 才启用，`data-mn-render` 标出走的是哪条路）。本轮真正消掉的是两处**放大**：图片授权不再触发整篇重渲染（就地补图）、wikilink 补类名从二次方降到线性。**仍未做分块 + 视口窗口化** —— 它才是消灭十万级 DOM 元素（5 MiB 文档约 24 万个元素）的办法，会打破大纲定位/灯箱/代码块挂按钮三处"整篇都在 DOM 里"的前提，留待下一轮。另外：编辑器装饰按视口计算，但**光标移动也会重算**（"进入即露原文"的必然代价）；大纲面板跟着正文重算（`useDeferredValue` 降级，输入不被它拖慢）。"当前章节"高亮**两个视图里都成立**：编辑视图取"最后一个不晚于光标行的标题"（光标行由编辑器在装配层节流上报，只有行号真的变化才写入），阅读视图取"视口顶部最后一个标题"（滚动监听是 passive 的，计算落在 rAF 里，序号没变就不回调）；阅读视图**没有挂预览**时不猜（没有依据就不高亮）
8. **图片粘贴/拖入只支持图片**：非图片整批拒绝（不做部分成功）、不做出站请求（网络图片仍是占位元素）、SVG 走 `<img>` 但不做转码（4K 截图按原样落盘）；多光标时只在主光标处插入一次
9. E2E 未覆盖：多窗口、插件（M4）、以及"标签/搜索/图谱在超大 Vault 下的表现"（功能已覆盖，规模未覆盖）
10. **外部改动自动同步（文件监听）的边界**（ADR-0016）：判定"是不是外部改动"用的是**磁盘状态 vs 条目表**（`mtime` + 字节数），所以**同一毫秒内、字节数又完全相同**的外部改动会漏判（与冲突检测/索引复用同一把钥匙，要兜住得引入内容哈希）；条目表被 `max_entries` 截断的超出部分每来一次事件都会触发一次重扫；**应用自己改名/搬迁**时被改写的那些文件（`updated_links`）会在条目表里留下旧 mtime，换来一次"多余但无害"的重扫（不弹提示）；同步盘的中转文件里，`.` 开头的隐藏项与 `Thumbs.db` 这类忽略名不触发重扫，而同步过来的正常文件（含 `xxx (冲突副本).md`）会被当成新增（这正是用户期待的"同步下来了"）；**网络盘 / UNC 路径**下通知完整性由对端决定（部分 NAS 不发通知），此时退化为"可能要等一次手工重扫"，不会报错；**外部改动之后当前笔记的反链面板**要等它自己的刷新时机才更新（图谱与搜索是索引驱动的，会自己跟上）。监听起不来只记一条日志 —— **`Ctrl+Alt+R` 的手工重扫始终是兜底**
11. **搜索索引（`.mimenote/cache/search.db`）会长得比想象中大，而且它就躺在 Vault 里**：一个真实的 4267 篇 / 50 万行 Vault 实测 **207 MB**（正文合计只有 22 MB）—— 体积来自"索引建在**行**上"（50 万个文档）与 FTS5 默认的位置表，不是文本重复（`lines_fts` 是 external content，文本只存一份），也**不是**段膨胀（那个库里 FTS5 只有 1 个段）。它**是可丢弃的派生数据**（删掉下次打开自动重建），所以：**Vault 在同步盘里时，建议在同步客户端里排除 `.mimenote/`**（否则每次重建都会让同步客户端上传一份 200 MB 级的文件）；应用自身不受影响 —— 扫描器与文件监听都跳过 `.mimenote/`。**段合并**已按实测接进增量收尾（段数 ≥ 8 时合并一次，查询快 1.68–2.2×，代价约 0.9 s 在后台线程上）；体积层面的缩小方向（`detail=none` 会牺牲短语查询、按篇索引要动"排名后取行号"的主线）见 ADR-0008「后续修订」第 3、4 节，本轮未做
12. **静态站点（ADR-0019）的边界**：输出目录**必须选在 Vault 之外**（写进去会触发应用重扫，而 Vault 在同步盘里时还会把整站上传）；**站内没有搜索**（整站零 JavaScript：`file://` 下浏览器禁止 `fetch()`，而 FTS5 库实测 207 MB 也不适合随站点分发 —— 需要时用 `Ctrl+F` 或索引页）；**不做增量重导出**（每次都整库重渲染；计划本身是 O(索引) 且不读文件）；**从不删除旧文件**（Vault 变小之后旧页面会留下，结果与索引页点名，想彻底重来就先删掉那个目录）；**图片先写页面、后复制**，中途中断会留下短暂死图；**标题口径**取"frontmatter `title` ?? 文件名主干"（与图谱卡片同口径，能在不读文件的前提下算出来），因此**可能与单篇导出差一级**（单篇还多一条"正文首个 H1"回落）；**锚点只认标题纯文本**（同名标题的链接落到第一处）；单个页面文件**离开站点目录后样式会丢**（样式是整站共享的一份 `assets/site.css`）；大 Vault 仍是**主进程分片渲染**（每批 24 篇让出一次主线程，进度可见、可取消 —— 真正的离屏渲染是 M5 的计划）

## 性能预算与实测

| 指标 | 目标 | 状态（M3） |
| --- | --- | --- |
| 冷启动到可交互 | ≤ 1500 ms | 未建立自动基准（M5） |
| Vault 扫描（1 万文件 + 100 目录） | ≤ 800 ms | **实测 120–147 ms**（`cargo run -p mn-core --release --example scan_bench`，M2 末复测） |
| 打开 1MB Markdown | ≤ 100 ms | 状态栏显示每次读取耗时，可直接观察 |
| 输入延迟 | ≤ 16 ms | 结构性保证：输入路径零 IO、编辑器不因文本变化重渲染、预览 `useDeferredValue`；命令面板按键路径最坏 3–6 ms（1 万笔记，见 `features/palette/match.ts`） |
| 主线程单任务 | ≤ 8 ms | Rust 侧所有文件 IO 走 `spawn_blocking` |
| 保存（本地） | ≤ 50 ms | 状态栏显示每次写入耗时（含 fsync） |
| 文件树滚动 | 60 fps | 固定行高虚拟列表，DOM 行数 = 可视行 + overscan，与总数无关 |
| 全文搜索查询 | 交互可接受 | 见下表（合成基准：1 万笔记 / 29.1 万行） |
| 知识图谱渲染 | 交互可接受 | 1 万节点：布局 46 ms（一次性）、网格索引 7 ms、**视口裁剪 0.09 ms/帧**（当帧只渲染约 60 张卡片）；平移/缩放只改一层 CSS `transform` |
| 大文档阅读视图（1 MiB / 65549 个元素） | 未定目标（一次性渲染） | jsdom 各阶段占比：解析 **≈9%**、净化 **≈46%**、`innerHTML` 落地 **≈42%**、全篇扫描 **≈5%**；因此净化与 DOM 留在主线程、解析在 >1 MiB 时进 Worker，另两处放大（图片授权重渲染、链接补类名二次方）已消除（ADR-0020） |
| 图谱数据（`graph_data`） | 一次 IPC 可接受 | 1 万笔记 / 2 万条链接：组装 **55–85 ms**、报文 1.0 MB（节点上限 8000 —— 几千篇的真实 Vault 因此能完整映射，超出才按度数截断）；含 5% 悬空链接时 163–364 ms（悬空解析是 `resolve_target` 的全库后缀兜底，见 `mn-index` 注释） |

全文搜索实测（`cargo test -p mn-index --release -- --ignored --nocapture`，合成 Vault：1 万笔记、每篇约 29 行、共 **29.1 万行**，FTS 库 113.8–114.7 MB）：

| 项 | 实测 |
| --- | --- |
| 索引构建（与链接/标签同一次遍历，后台、可取消） | 链接+标签 **5.5 s**；含 FTS5 **10.3 s**（其中 FTS 自身约 2.8 s，**快于链接那一轮**） |
| 查询：真实场景（命中约 100 行） | **3 ms** |
| 查询：命中 1000 行 | **66–79 ms** |
| 查询：命中 29 万行（查询词在每一行里都出现） | **0.9–1.2 s** |
| 单独的全量计数 `COUNT(*)` | 12–17 ms（**不是**瓶颈） |
| 索引体积 | ≈ 被索引文本的 **2.7 倍**（中文逐字 token 的固有比例） |

慢的那一档是**排序的固有成本**：`bm25()` 要给全部命中打分，`ORDER BY score LIMIT 50` 也必须先算完
（已实测 `CROSS JOIN` / `CTE+LIMIT` / 去掉 `ORDER BY` / 加大页缓存 / mmap 变体，都在同一量级，
说明没有便宜的优化空间；拆解显示打分 + JOIN 回行表 + 三键排序占约 90%）。面板对请求做了 150ms 防抖 +
竞态丢弃，不会因为连续输入堆积查询；索引未就绪时面板显示"正在构建"提示而不是报错。

索引**整体跨会话复用**（ADR-0008「后续修订」+ ADR-0014）：链接、标签、FTS5 落进同一个缓存库、
共用同一份 `(路径, mtime, 字节数)` 判定键。**Vault 没变时一份笔记文件都不读**：

| 场景（1 万笔记 / 30.1 万行 / 缓存库 117 MB，release） | 打开 Vault 耗时 |
| --- | --- |
| 旧行为（每次整库重建） | **9.8–10.5 s**（链接/标签 4.9–5.1 s + 搜索 4.4–4.7 s） |
| Vault 没变（复用 10000 篇） | **0.25–0.34 s**（对账 0.17–0.23 s + 装载 0.04–0.05 s，写 0 行） |
| 改了 1 篇（复用 9999 篇） | **0.26–0.31 s** |

代价是**写路径**多了一点：冷启动整库重建多写约 3 万行（+5%）、每次保存多一次小事务（**+0.68 ms/篇**）。
`<Vault>/.mimenote/cache/search.db` **损坏**时自动重建，锁冲突/磁盘满/只读只降级、**不删缓存**。
仍未做：文件监听（`notify`）触发的增量、内容哈希二级令牌（M5）。

扫描过程中发现并修掉的一个真实性能坑：用 `fs::symlink_metadata(path)` 逐文件取元数据，
1 万文件要 2227ms；改用 `DirEntry` 的缓存元数据后降到 145ms（**14 倍**）。
细节与约束见 [`docs/architecture.md` §6](docs/architecture.md)。

## 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 窗口一片空白，提示"无法访问 127.0.0.1" | 用 `cargo build --release` 而不是 Tauri CLI 构建的：生产二进制里被写入 devUrl。改用 `pnpm tauri:build`（见"构建"一节） |
| 点开笔记后编辑区是空白 | 已修复（CodeMirror 实例漏创建）。若再出现，跑 `pnpm test:e2e:ui` 一眼就能定位 |
| E2E 报"找不到应用二进制" | 先跑 `pnpm --filter @mimenote/desktop exec tauri build --no-bundle`（release 才内嵌前端资源） |
| E2E 应用层在非 Windows 上被跳过 | WebView2 的远程调试只在 Windows 上存在；这是显式跳过而不是"通过" |
| `pnpm tauri:dev` 起不来，`pnpm dev` 正常 | 检查 1420 端口是否被占用（`vite.config.ts` 与 `tauri.conf.json` 都约定 `127.0.0.1:1420`） |
| 保存报 `IO` 错误 | 目标目录可能是 OneDrive 同步目录或只读；日志文件里有系统错误码（`detail` 字段） |
| 提示"文件已被外部修改" | 这是**保护**：别处改过同一文件。选择覆盖或重新加载（见 ADR-0004） |
| 界面上看不到本地图片 | M1 已知限制，图片渲染为占位元素，M2 引入 `asset:` 协议 |
| 需要看日志 | `%LOCALAPPDATA%\app.mimenote.desktop\logs\mimenote.log`（超过 2MB 会自动重建） |

## 安全与隐私

- **默认离线**：运行时无任何网络请求；CSP 为 `default-src 'self'`、`script-src 'self'`，`connect-src` 仅允许 Tauri IPC。
- **能力最小化**：`capabilities/default.json` 只放开 `core:default` 与 `dialog:allow-open`；文件访问全部经过自定义 IPC 命令与路径防护。
- **路径防护**：拒绝 `..`、绝对路径、盘符/UNC、Windows 保留名与 ADS；逐级检查符号链接，目标必须仍在 Vault 内。
- **不破坏用户数据**：写入原子替换、删除进回收站、冲突必须人工决策。
- **XSS 防护**：Markdown 关闭 raw HTML + DOMPurify 二次净化（有专门的攻击载荷测试）。
- **用户样式片段**只从用户自己的 Vault 目录读取，不加载远程 CSS。

## 假设

本实现基于以下已确认的假设（来自需求澄清）：

1. **Windows 优先**，代码保持跨平台（路径与文件 API 全部使用跨平台语义，未写死 `\`）。
2. 技术栈：Tauri 2 + Rust + React + TypeScript + Vite + CodeMirror 6 + Zustand；SQLite FTS5 在 M2 引入。
3. **第三方插件推迟到 M4**，M1 只提供内置扩展点（命令、快捷键、主题、CSS 片段、编辑器扩展）。
4. **不做同步/协作**，只保证纯 Markdown 且可被 Git 管理。
5. 目标规模 **1 万笔记**，使用上文默认性能预算。
