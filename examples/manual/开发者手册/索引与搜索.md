# 索引与搜索

## 索引是缓存（ADR-0002）

链接/标签/全文搜索全是派生数据：删掉 `.mimenote/cache/` 最多下次打开慢十几秒，
内容零损失。内存索引 + 落盘复用两条腿走路。

## 判定键与 30× 加速

打开 Vault 时按 `(path, mtime_ms, size)` 对账：没变的笔记**一个文件都不读**
（1 万笔记 9.8s → 0.3s）。链接/标签/FTS 三者共用同一张 `notes_meta`、
同一个事务（失败一起回滚，不留"内容新、键旧"的中间态）。

## 已知的漏检窗口与补丁

- 同一毫秒 + 同字节数的改动会被判成"没变"：二级令牌是内容哈希
  （`notes_meta.content_hash`），`note_read` 打开时顺手比对、对不上就地重建；
- 写穿透路径（保存/新建/删除/改名）拿不到 mtime 时直接作废判定键（"不知道"只能
  表达成"下一篇必须重读"）。

## FTS5

SQLite FTS5（静态编进二进制），中文逐字分词，行表 + external content
（排名之后还能拿回行号），`bm25` 排序。查询串按自然文本处理，搜 `OR` 不报错。

`created` / `updated` 时间挂钩是另一条"元数据保真"线：见用户手册
[[用户手册/设置与同步]]（实现：`mn-core::timestamps` + 写路径盖章）。
